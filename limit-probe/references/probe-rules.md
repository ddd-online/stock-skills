# 盘中涨停探测细则

用途：limit-probe 判定板块强度、候选资格与数据边界时速查。所有阈值是默认经验值，用户明确说明的个人阈值优先；所有数字必须来自真实行情并标注数据日期与运行时间；不构成投资建议。

## 1. 运行时段

| 时段 | 处理 |
|---|---|
| 9:25–9:30 | 不运行本 SKILL，改用 $limit-judge 做集合竞价评估 |
| 9:30–11:30 | 正常盘中口径 |
| 11:30–13:00 | 使用上午收盘快照，标“午间快照” |
| 13:00–14:30 | 正常盘中口径，可新增待涨停候选 |
| 14:30–15:00 | 可继续看已封板与板块强度，不新增待涨停买入候选 |
| 15:00 后 | 改用 $limit-find 做收盘复盘 |

盘中接口的涨停池、板块榜与个股报价都会变化；报告只代表运行时刻，不把当前状态外推为收盘或次日结论。

## 2. 涨停幅度与距涨停

早筛可用代码规则，最终以 fetch_quote 返回的 `limit_up`（涨停价）为准：

| 代码/名称 | 默认涨停幅度 |
|---|---|
| 沪市 60 / 深市 00 主板 | 10% |
| 创业板 300/301、科创板 688/689 | 20% |
| 北交所 4/8/92 | 30% |
| ST / *ST | 5%（默认不交易） |

距涨停幅度 =（涨停价 − 现价）÷ 涨停价 × 100%。现价等于或高于涨停价时按“已涨停/封板”处理，不再算待涨停。

## 3. 板块归属

1. `fetch_limit_up --json` 的 `zt_rows[].industry` 是 4 字截断行业名，只用于第一层速览和找候选板块。
2. 强势板块必须用 `fetch_sector_boards` 的 BK 代码，再跑 `fetch_sector_leaders --board BKxxxx --top 300 --json` 取成分股。
3. 板块涨停/炸板/候选数一律用成分股代码集合与 `zt_rows`、`zb_all_rows`、`dt_rows` 按代码求交；不得用 `industry` 与板块名做模糊匹配来计数。
4. 行业板块与概念板块重叠时保留两行，标注“重叠”；同一只候选只归入强度最高的板块，避免重复。
5. 板块候选上限 6 个：行业板块先对涨停速览≥2 家的板块做板块行预检（G2–G4），预检通过的按涨停家数→当日涨幅→资金取前 3；预检不通过的降为观察，不占下钻名额。不足 3 个再用概念板块涨幅/资金榜前 3 个补足。被挤掉的板块列在报告“未探测板块”里。
6. 行业速览的截断名与行业板块名只可做一次前缀/包含匹配来定位 BK（如「汽车零部」→「汽车零部件」）；定位后的家数与候选一律按成分股代码求交复核，匹配不确定就不纳入。若≥2 家涨停的行业不在四个榜单内，最多用 `--search` 补 2 次；仍找不到就列“未映射板块”。`--search` 会翻完整板块列表，连续多次易触发东财限流，只能作为兜底且要计入调用次数。

## 4. 板块强度

### 4.1 硬门槛

以下五项全部通过才算“有资格评级”：

| 编号 | 门槛 | 数据 |
|---|---|---|
| G0 | 板块成分股≥5 只 | 成分股榜行数；不足 5 只标“样本不足”，不评级 |
| G1 | 板块内当前涨停≥2 家 | 成分股 `limit_up=true` 或与 zt_rows 求交 |
| G2 | 板块当日涨幅>0 且近5日涨幅>0 | 板块行 `change_pct`、`change5_pct` |
| G3 | 上涨家数≥下跌家数 | 板块行 `up_count/down_count`；缺失时用成分股涨跌统计 |
| G4 | 主力净流入≥0 | 板块行 `main_inflow_yi`；缺失标“待核”，最高评“中” |

任一硬门槛不通过：标“弱”；关键字段缺失且无法从成分股补齐：标“待核”，不进入候选。

### 4.2 强度分

通过门槛后每项 1 分：

| 项 | 得分条件 |
|---|---|
| 涨停集中度 | 涨停≥3 家，或涨停家数占全场前 3 |
| 封板质量 | 封板率≥60%；封板率 = 涨停家数 ÷（涨停家数 + 炸板家数），分母为 0 记“-” |
| 高度/先动 | 板块内有≥2 板个股，或最早首封≤10:00 |
| 待涨停宽度 | 板块内满足距涨停≤2%的股票≥1 家 |

评级：

| 分数 | 标签 | 是否进入候选 |
|---|---|---|
| 4 | 强 | 是 |
| 3 | 强（边缘） | 是 |
| 2 | 中 | 否，只列观察 |
| ≤1 | 弱 | 否 |

没有“强/强（边缘）”板块时，报告写“今日盘中无高强度板块”，候选表写“无”，不用中等板块补位。

### 4.3 板块内龙头标签

只作为板块强度证据，不替代 $leader-find：

1. 按首封时间→连板高度→换手与量能→资金→炸板后的回封速度排序。
2. 全为首板：写“无龙头（先动股：名称+首封时间）”。
3. 出现 2–3 板：写“龙头候选（名称+板数）”。
4. 4 板以上，或板块内≥2 只三板及以上：写“龙头（已确认）”。
5. 跟风板（首封晚于板块先动股）、14:00 后首封、连板换手≥25%、板块资金净流出的独涨板：标“伪龙头（类型）”，不作为板块强度加分项。

## 5. 候选矩阵

### 5.1 已涨停（回封型）

必须全部满足：

- 当前在 zt_rows 且封住；只在 zb_all_rows 里的列“回封观察”；
- 1–3 板；4 板及以上只观察；
- 首封≤11:00；14:00 后首封只观察；
- 炸板次数≤1；
- 换手 5%–25%；>25% 剔除，15%–25% 标“换手偏高”；
- 封单不低于同板块涨停股中位数；封单缺失标“待核”；
- fetch_quote 核对不是一字板，且行情日期为今天。

触发：开板回封，封单恢复到板块中位数以上。未回封不买，不在涨停价盲目排队。

### 5.2 待涨停（上板确认型）

必须全部满足：

- 不在 zt_rows，属于强势板块成分股；
- 距涨停≤2%；优先用 fetch_quote 的 `limit_up` 计算；
- 现价≥开盘价，且距当日最高价≤1%；
- 5日涨幅 0–25%；
- 换手 5%–15%；
- 流通市值 50–200亿；
- 主力净流入为正；
- 当前时间不晚于 14:30。

触发：放量上板并封住。未上板不买；上板后封单快速衰减或板块龙头炸板，视为失效。

### 5.3 固定排除与观察标签

| 情况 | 处理 |
|---|---|
| ST / 退市风险 / 权限未开通 | 剔除，不进候选 |
| 4 板及以上 | 只观察·高位 |
| 14:00 后首封 | 只观察·尾盘板 |
| 一字板 | 只观察·买不到 |
| 当前炸板 / 炸板≥2次 | 只观察·回封观察 |
| 换手>25% | 剔除，标“高位高换手” |
| 5日涨幅>25% | 只观察·追高 |
| 板块主力净流出或上涨家数<下跌家数 | 板块降级，候选不入选 |
| 涨停价或行情时间取不到 | 待核，不标“可执行” |

## 6. 数据边界

- 东财涨停池不含 ST 与科创板；板块涨停家数按成分股 `limit_up` 可补到科创板，但封板细节仍可能缺失，报告写“涨停家数为下限/封板细节未获取”。
- `fetch_sector_leaders` 的 F10 备用源名单可能少于行情中心全量；报告必须写数据源与“名单可能不全”，不能用它反推板块总家数。
- `fetch_sector_leaders --top 300` 只覆盖前 300 只成分股；板块超过 300 只时标“覆盖不足”，涨停家数按已覆盖样本计，不外推全板块。
- 板块行与成分股行可能来自不同源；跨源数值不做比例、不混在同一张对比表，必要时标“不可比”。
- 主力净流入、量比、封单等字段缺失时写“未获取/待核”，不填 0；接口返回 0 才写 0。
- 板块封板率的分母用板块内涨停+炸板；若全市场炸板家数>0 但板块炸板明细缺失，封板率标“未获取”，不按 100% 计。
- 板块行的近10日涨幅可能与近5日同值（东财镜像字段问题）；只把近5日作为硬门槛，近10日仅作参考并标注。

## 7. 示例（仅示范算法，不是行情建议）

板块 A：涨停 3 家、炸板 1 家、封板率 75%、当日 +3.2%、5日 +6.1%、上涨 20 家/下跌 8 家、主力净流入 +1.2 亿、最高 2 板、最早首封 09:42、待涨停 1 家。

- 硬门槛：G0–G4 全过。
- 得分：涨停≥3（+1）、封板率≥60%（+1）、有2板（+1）、有待涨停（+1）= 4 分，评“强”。
- 候选：板块内 2 板股若首封 09:42、换手 12%、封单高于中位数、非一字，可列“可执行·已涨停（回封）”；同板块待涨停股若距涨停 1.2%、现价高于开盘、换手 8%，可列“可执行·待涨停（上板确认）”。

报告只写这类可复核数字与触发条件，不写“明天还会涨”。
