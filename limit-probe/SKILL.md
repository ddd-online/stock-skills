# 盘中涨停探测（limit-probe）

盘中只输出**截至运行时刻的快照**，不预测下一根 K 线。要回答的问题只有三个：

1. 现在涨停的股票集中在哪些板块？
2. 这些板块里，哪些板块的强度足以继续看？
3. 强势板块里，哪些已涨停或待涨停的股票满足可跟踪条件，触发与失效条件是什么？

候选只代表“值得盯到触发”，不是无条件买入。资金、仓位与最终下单仍走 $position-management；需要完整买点/止损/基本面时转 $stock-analysis。

## 触发与前置

- 触发：交易日盘中请求“现在哪些板块强”“当前涨停都在哪”“哪些票还能买/待涨停”“盘中涨停探测”。
- 运行窗口：9:30–11:30、13:00–15:00。11:30–13:00 按上午收盘快照运行并标注“午间快照”；9:25–9:30 用 $limit-judge；15:00 后用 $limit-find。没有当日实时数据时不生成盘中报告。
- 依赖：$market-data 的 fetch_limit_up、fetch_sector_boards、fetch_sector_leaders、fetch_quote。只读 ACCOUNT.md「板块权限」，不读 MUST.md、POSITION.md、stocks/；权限缺失时按保守默认（仅主板、ST 不交易）并标注。
- 落盘：report/盘中涨停探测/YYYY-MM-DD.md（同日重跑覆盖更新并注明本次运行时间）。
- 数据时效：fetch_limit_up 的 base_date 与 quote_date 必须都是今天；任一项不是今天，立即停止并说明“接口未提供今日盘中数据”，不得把上一交易日冒充当前涨停。

## 核心口径

| 项目 | 口径 |
|---|---|
| 板块归类 | 先用 zt_rows 的 industry 做速览分组；强势板块必须用 BK 代码取成分股，再与 zt_rows/zb_all_rows/dt_rows **按代码求交**，不按板块名称匹配 |
| 板块强度 | 硬门槛：成分股≥5、涨停≥2、当日与5日涨幅为正、上涨家数≥下跌家数、主力净流入≥0；再按涨停集中度、封板率、龙头高度、待涨停宽度打 0–4 分 |
| 已涨停候选 | 1–3 板、首封≤11:00、炸板≤1次、换手 5%–25%、封单不低于板块涨停股中位数、非一字、当前封住 |
| 待涨停候选 | 距涨停≤2%、现价不低于开盘价且距当日高点≤1%、5日涨幅0–25%、换手5%–15%、流通市值50–200亿、主力净流入为正 |
| 买入含义 | 只给触发条件：已涨停等开板回封，待涨停等放量上板；不触发不买，不预测次日 |

默认阈值均可由用户在请求中覆盖，报告中注明实际采用值。完整判定表、涨停幅度与边界情况见 references/probe-rules.md。

## 流程

### 第一步：校验时间、权限与数据时效

1. 记录运行时间、交易日与当前时段；不在允许窗口时停止，并指向 $limit-judge 或 $limit-find。
2. 从工作区 ACCOUNT.md 读取「板块权限」；缺失或未确认时用默认值，并在报告开头写明来源。
3. 先跑 `python market-data/scripts/fetch_limit_up.py --json`，检查 `data_available`、`base_date`、`quote_date`。日期不是今天、或当日涨停池为空时，写“当前盘中样本未获取/暂无涨停样本”后结束，不拿昨日数据充数。

### 第二步：当前涨停全景与板块速览

从 --json 取：

- `overview`：涨停、跌停、炸板家数与封板率；
- `zt_rows`：全量涨停股（代码、名称、板数、首封/末封、炸板次数、换手、封单、成交额、行业）；
- `zb_all_rows`、`dt_rows`：炸板与跌停；
- `industry_dist`：按行业家数分布。

先按 `industry` 输出「涨停股行业速览」。这个字段是接口给的 4 字截断名，只用于初筛与展示，不能直接当成 BK 板块名。

### 第三步：板块初筛与成分股下钻

1. 跑四次板块榜（每次一个命令，结果去重）：

```
python market-data/scripts/fetch_sector_boards.py --type industry --sort change --top 20 --json
python market-data/scripts/fetch_sector_boards.py --type industry --sort flow --top 20 --json
python market-data/scripts/fetch_sector_boards.py --type concept --sort change --top 20 --json
python market-data/scripts/fetch_sector_boards.py --type concept --sort flow --top 20 --json
```

2. 候选板块最多 6 个：行业板块优先取涨停速览中≥2 家的前 3 个，再用概念板块涨幅/资金榜前 3 个补足。行业速览映射到 BK 只允许用板块名做一次前缀/包含匹配来定位（如「汽车零部」→「汽车零部件」），定位后必须用成分股代码求交复核；匹配不确定的板块不纳入。若≥2 家涨停的行业不在四个榜单内，最多用 `--search` 补 2 次定位；仍找不到就列“未映射板块”。被上限挤掉的板块在报告里列出，不假装已经探测过。
3. 每个候选板块跑一次 `fetch_sector_leaders.py --board BKxxxx --top 300 --json`，取全量成分股。用成分股代码与涨停池/炸板池/跌停池求交，计算板块涨停数、炸板数、封板率、待涨停数、最高板、最早首封与龙头候选。
4. 同一批股票同时属于行业与概念时保留两个板块，但候选只归入强度最高的板块，避免重复计数。成分股来自 F10 备用源、名单可能少于行情中心全量时，报告必须写明数据源与覆盖限制。

### 第四步：板块强度评级

先过硬门槛，再打分；任一硬门槛不过就是“弱”或“待核”，不进入候选。

| 门槛 | 默认要求 |
|---|---|
| G0 样本充足 | 板块成分股≥5；不足 5 只标“样本不足”，不评级 |
| G1 涨停结构 | 板块内当前涨停≥2 家 |
| G2 板块动能 | 板块当日涨幅>0 且近5日涨幅>0 |
| G3 市场宽度 | 上涨家数≥下跌家数 |
| G4 资金 | 主力净流入≥0；未获取时标“待核”，最高只能评“中” |

通过门槛后，每项 1 分：

1. 涨停≥3 家，或涨停家数占全场前 3；
2. 封板率≥60%；
3. 板块内有≥2 板个股，或最早首封≤10:00；
4. 板块内待涨停≥1 家。

评级：4 分“强”，3 分“强（边缘）”，2 分“中”，≤1 分“弱”。候选只从“强”和“强（边缘）”里取；没有强势板块就明确写“今日盘中无高强度板块”，不硬凑。

板块内龙头只做强度证据，不抢 $leader-find 的职责：按首封时间、连板高度、换手与量能、资金、回封速度排序；全为首板时写“无龙头（先动股：名称）”，2–3 板写“龙头候选”，4 板以上或≥2 只三板写“龙头（已确认）”。跟风板、14:00 后首封、连板换手≥25%、板块资金净流出的独涨板，只能标“伪龙头（类型）”。

### 第五步：板块内候选筛选

候选池只来自强势板块，先按板块权限剔除，再分两类：

**已涨停（回封型）**

- 当前在 zt_rows 且封住；在 zb_all_rows 里的只列“回封观察”，不列可买；
- 板数 1–3；≥4 板只观察；
- 首封≤11:00；14:00 后首封只观察；
- 炸板次数≤1；换手 5%–25%，>25% 剔除，15%–25% 标“换手偏高”；
- 封单不低于同板块涨停股中位数；
- 最终用 fetch_quote 核对是否一字、是否仍在涨停价、行情时间是否为今天。

**待涨停（上板确认型）**

- 不在 zt_rows，属于强势板块成分股；
- 用 fetch_quote 的 `limit_up`（涨停价）计算距涨停幅度，≤2%；未取到涨停价时可用代码规则预筛，但不得标“可执行”；
- 现价≥开盘价，且距当日最高价≤1%（回撤不深）；
- 5日涨幅 0–25%，换手 5%–15%，流通市值 50–200亿，主力净流入为正；
- 14:30 后不再新增待涨停买入候选。

最终按“板块强度→类型→封板/涨幅质量”排序，最多 5 只，单板块最多 2 只。每只给：

| 输出项 | 要求 |
|---|---|
| 类型 | 可执行·已涨停（回封）/ 可执行·待涨停（上板确认）/ 只观察 |
| 触发 | 已涨停：开板回封且封单恢复；待涨停：放量上板并封住 |
| 失效 | 跌破当日开盘价、板块龙头炸板、或触发后封单快速衰减 |
| 风险 | 高位、换手偏高、尾盘板、一字买不到、板块资金转弱等固定标签 |

对每只最终候选跑一次 `fetch_quote.py <代码> --days 30 --json`，核对 `quote.datetime`、`quote.limit_up`、开盘/最高/现价与均线；核对失败写“待核”，不写“可执行”。

### 第六步：写报告并回复

1. 读 references/report-template.md，按固定节名与表头填写；所有数字标数据日期与运行时间。
2. 先写 report/盘中涨停探测/YYYY-MM-DD.md，再回复摘要：强势板块 1–3 个、可执行候选 0–5 只、买不到/高位/炸板的观察名单。
3. 没有强势板块、没有候选或数据不完整时，报告保留对应小节并写“无/未获取”，不用其他板块或昨日数据补齐。

## 硬性规则

- **只在盘中用当日数据**：base_date 或 quote_date 不是今天就停止；不得把上一交易日当作“当前涨停”。
- **不编数据**：接口没返回的家数、封板率、涨幅、换手、封单、资金一律写“未获取”，不填 0、不估算；区分“0 家”和“未获取”。
- **板块归属按代码求交**：行业字段只做速览；强势板块的涨停/炸板/候选必须用 BK 成分股代码与涨停池求交，不按名称匹配。
- **只从强势板块选候选**：不做全市场待涨停扫描；没有强势板块就不出候选。
- **权限硬过滤**：ACCOUNT.md 未开通的板块、默认不交易的 ST，即使形态满足也不进候选，并写明剔除只数。
- **不追高、不排队**：4 板以上、14:00 后首封、换手>25%、一字板、当前炸板股只列观察；已涨停候选必须等回封触发，待涨停候选必须等上板确认。
- **不预测、不给仓位**：不写“明天会涨停/会退潮”；候选的仓位、手数与最终下单交 $position-management，完整买卖判断交 $stock-analysis。
- **不维护观察池**：不创建 WATCHLIST.md 等状态文件；候选只写进当日报告，下一次运行重新计算。
- **报告必落盘**：先写 report/盘中涨停探测/YYYY-MM-DD.md 再回复；同日重跑覆盖更新并注明运行时间。
- **输出可视化**：数字进表格；板块强度用固定标记（强/强（边缘）/中/弱/待核/样本不足），候选用固定标签（可执行·已涨停（回封）/可执行·待涨停（上板确认）/只观察）；不写散文式数字段，不用表情符号。
- **免责声明**：报告结尾必须带“不构成投资建议”。
