# 题材生命周期判定细则

用途：limit-lifecycle 判阶段、做主线健康度体检、写报告与生成推荐时的速查。所有阈值均为默认经验值，用户明确说明的个人规则优先；所有数字必须来自 $limit-find 报告或 $market-data 的真实输出并标注数据日期；不构成投资建议。

一句话原则：阶段不是按板块名字分的，是按每天都在变的数字分的；同一条线昨天是扩散、今天可能已经加速末期，所以每个交易日都要重判一次。

## 1. 四阶段判定数字

| 阶段 | 涨停结构 | 龙头状态 | 资金与量能 |
|---|---|---|---|
| 点火 | 涨停 1–3 家，一板占比 ≥2/3（板块内无 2 板以上）；板块当日涨幅多在 -1%~+3% | 刚冒头，还没有连板龙头 | 小幅净流入，量能温和放大 |
| 扩散 | 涨停 ≥5 家，或出现 2–3 板核心票且涨停 ≥3 家；产业链上下游一起动 | 出现 2–3 板核心票 | 主力净流入为正，板块内涨停股换手 5%–15% |
| 加速 | 板块内多股连板，涨停家数占全场比重高（默认 ≥15%） | 龙头 ≥4 板，或板块内 ≥2 只三板及以上 | 主力净流入最大，板块内涨停股平均换手 ≥20%（或板块成交额创近10日新高） |
| 退潮 | 涨停家数快速减少，开始出现跌停 | 龙头断板、炸板（该封没封住）或跌停 | 资金转为净流出，缩量阴跌或放巨量下跌 |

“换手 ≥20%”指**板块内涨停股的平均换手**（用 fetch_limit_up.py --json 的 zt_rows.turnover_pct 取该板块涨停股均值），不是板块指数换手；板块成交额 “阶段新高” 指板块行情榜的成交额高于样本内前几日的最高值。

板块归属只按**代码求交**：涨停池的行业名是接口给的 4 字截断名（「汽车零部」「自动化设」「互联网电」），与板块行情榜的板块名（「汽车零部件」「互联网电商」）不能按名字比对；正确做法是取该板块 BK 代码的成分股代码集合，与 zt_rows / zb_all_rows / dt_rows / yesterday_performance.rows 按代码求交（实测：汽车零部件 BK0481 成分 276 只，今日涨停 8 家、昨日涨停 3 家、平均换手 8.2%、炸板 2 家）。

## 2. 判定顺序（固定，不可跳步）

1. **退潮**：龙头断板/炸板/跌停（昨日最高板个股今日不在涨停池），或板块出现跌停且涨停家数较昨日减少，或主力净流入转负且涨停家数减少。
2. **加速**：高度条件（龙头 ≥4 板、板块内 ≥2 只三板及以上、或板块涨停家数占全场比重 ≥15%）**且**量能条件（板块内涨停股平均换手 ≥20%）。默认口径明确不含“成交额创阶段新高”：fetch_sector_boards 只给当日快照，没有历史成交额来源；成交额每天记进「阶段演变时间线」，样本 ≥3 份后作交叉印证写进理由，不足时写“成交额样本不足”。
3. **扩散**：涨停 ≥5 家或（2–3 板核心票且涨停 ≥3 家），且主力净流入为正；5日与10日至少一个为正 → 扩散；两个都为负 → 「扩散（首日，持续性待确认）」并写出两个负值。
4. **点火**：涨停 1–3 家、一板占比 ≥2/3 且板块内无 2 板以上。
5. **降级/收缩**：不满足第 2–4 条但有「≥1 只 2 板及以上」或「涨停 ≥2 家」→ 取样本内最近一次阶段加「（收缩）」；样本不足时按数字直判（有 2 板及以上 → 扩散（收缩）；只有 1 家首板 → 点火（收缩））。
6. **无涨停 / 阶段待确认**：今日与昨日涨停均 0 家 → 「无涨停（未启动/已退潮）」；其余不满足前五条 → 「阶段待确认（数据不足）」并写出缺哪几个数字（如“板块 5 日涨幅未获取”），不硬判。

冲突与覆盖规则：

| 情形 | 处理 |
|---|---|
| 主线健康度三检查点两格为负 | 阶段直接落「退潮」，理由写“三检查点两格负（哪两格）” |
| 三检查点一格为负、数字仍指向扩散/加速 | 阶段写「扩散（收缩）」或「加速（收缩）」，两套数字都写出来 |
| 三检查点出现「弱」格（资金缩量、宽度收缩但未转负） | 阶段同样加「（收缩）」；结论写「继续跟踪但不作为主线」，不进推荐 |
| 三检查点出现「未知」格 | 阶段照数字写，但结论必须写明未知格数与缺什么、不下“还活着”，也不进推荐 |
| 高度/资金仍在但涨停家数收缩、也够不上点火 | 走第 5 条降级：取样本内最近阶段加「（收缩）」，不要写成「阶段待确认（数据不足）」——有数字就不是数据不足 |
| $limit-find 的板块活跃度标“转弱”而阶段数字仍指向扩散/加速 | 同上，阶段加「（收缩）」，并注明与活跃度口径的差异 |
| 板块昨日无涨停数据（分母缺失） | 家数变化写“未获取”，该格不计正负，不用 0 代替 |
| 报告里的板块只有名字、没有 BK 代码，或名称与板块行对不上 | 用 fetch_sector_boards.py --search <板块名> 定位 BK 代码，并在报告里注明“BK 代码为本次检索得到” |

本轮第 N 天：以 ≤5 份样本（当日 + 之前四份 limit-find 报告）内该板块**首次出现涨停（≥1 家）**那天为第 1 天连续计数；中途出现 0 家涨停视为本轮结束，之后再出现写「第 1 天（重启）」；样本不足五份时写实际份数。

## 3. 主线健康度三检查点

每个板块三格，每格四种状态：**正 / 弱 / 负 / 未知**。铁律：**每一个「正」「弱」「负」都要指向一个可比数字（两个时点 + 数值）；指不出来就写「未知」，未知既不算正也不算负**。用未知撑出「三格全正」，等于用结论补证据。

| # | 检查点 | 正（跟数字） | 弱（跟数字） | 负（跟数字） | 未知 | 数据来源 |
|---|---|---|---|---|---|---|
| 1 | 龙头还在不在 | 昨日最高板个股今日仍在涨停池（写今日板数与首封时间；今日最高板 ≥ 昨日注明“高度在抬”） | 不设 | 昨日最高板个股今日炸板、跌停或断板 | 昨日无涨停股（没有可比龙头），或当日数据未获取 | 「连板高度与最高板」高标梯队表 + --json 的 zb_all_rows / dt_rows |
| 2 | 涨停家数是增是减 | 今日家数 ≥ 昨日 | 今日少于昨日，但减少幅度 <1/3 且无跌停 | 今日较昨日减少 ≥1/3，或板块出现跌停 | 昨日家数未获取 | 板块成分股代码集合 ∩ zt_rows / yesterday_performance.rows |
| 3 | 资金是进还是退 | 今日主力净流入 >0 且 ≥ 基准日 ×70%（放大或基本持平；基准日为负而今日为正＝转向流入） | 今日 >0 但 < 基准日 ×70%（流入但明显缩量） | 今日 ≤0（含由净流入转净流出） | 时间线里找不到任何更早的可比数值 | 板块行主力净流入（今日）+ 时间线里该板块最近一份有数值的报告（基准日） |

**第三格必须两个时点**：单日数值只能说明“今天是流入还是流出”（状态），不能说明“方向”。基准日 = 时间线里该板块最近一份有主力净流入数值的报告日期，优先前一交易日；前一交易日缺失时取更早的最近一天，并写「X 日数值缺失，属两日对比」。默认阈值 70%（缩量三成以上算「弱」），用户可覆盖。

正例（把未知写成正的反面教材 → 正确写法）：风电设备今日主力 +2.61 亿、基准日 9/15 为 +11.57 亿（9/16 缺失）→ 2.61/11.57 = 23% < 70% → 记「**弱**：主力 +2.61 亿为正，但与 9/15 的 +11.57 亿相比明显缩量（9/16 数值缺失，属两日对比）」。不能写成「正：主力 +2.61 亿（昨日值未获取）」，也不能因为昨日值缺失就整格跳过。

综合结论（优先级：负 → 弱 → 未知 → 全正）：

| 三格结果 | 结论 | 报告里怎么写 |
|---|---|---|
| 负 ≥2 | 已进入退潮 | 移出跟踪名单，不推荐；写明哪两格为负 |
| 负 =1 | 已进入收缩 | 继续跟踪并标注收缩点（哪一格、数字） |
| 负 =0 且 弱 ≥1 | 继续跟踪但不作为主线 | 按弱在哪格给一句（资金在退 / 宽度在缩），不推荐 |
| 负 =0、弱 =0 且 未知 ≥1 | 证据不足 | 写明哪几格未知、缺什么，不能判为“还活着”，也不能进推荐 |
| 三格全正 | 还活着 | 继续跟踪，可进推荐（还需阶段为点火/扩散 或 扩散（首日，持续性待确认）） |

示例（2026-09-14 元件簇，数字取自当日报告）：龙头超声电子 6 天 4 板封住（正）、涨停家数 9→6 家减少（负）、PCB 概念主力 +43.85 亿（正）→ 一负：已进入收缩；次日超声电子盘中涨停后炸板、换手 40.42%，收缩信号应验。

示例（风电设备，两正一弱）：龙头锡华科技 2 板 → 3 板（正）、涨停 1 → 2 家（正）、主力 +2.61 亿 vs 9/15 +11.57 亿（弱）→ 结论「宽度和高度在走、资金在退，继续跟踪但不作为主线」。

## 4. 阶段对应动作（报告里怎么写）

| 阶段 | 市场含义 | 本 SKILL 的输出 |
|---|---|---|
| 点火 | 谁都没看见的时候，钱最好赚也最容易假 | 可进推荐（需三格全正：无负、无弱、无未知）：列观察候选、等回踩确认，不在第一天追 |
| 扩散 | 产业链上下游一起动，资金有持续性 | 可进推荐（相对安全的介入窗口，仍要过 $stock-analysis 的体检与买点）；带「（首日，持续性待确认）」后缀时同样可推荐（仍要三格全正），但理由里要写明 5日/10日仍为负 |
| 加速 | 最热的时候也是离场窗口 | 不推荐：写「空仓不追；持有者按既有规则减仓」 |
| 退潮 | 龙头断板的第一天就是信号，反抽多为反抽 | 不推荐：写「移出跟踪，等下一轮点火」 |
| 「（收缩）」变体（扩散（收缩）/点火（收缩）/加速（收缩）） | 还有数字但已在收缩，次日容易应验 | 不推荐：写「只跟踪不新增，等三格回到全正或龙头创新高」 |
| 有「弱」格（如资金缩量）/ 有「未知」格 | 宽度和高度可能在走，但有一项在退或证据不足 | 不推荐：写「继续跟踪但不作为主线」或「证据不足：N 格未知」，不进候选 |

本 SKILL 不写“模拟盘/实盘动作”当作指令，只把阶段对应的纪律提示写进报告；具体买卖由 $stock-analysis → $position-management 决定。

## 5. 三个最常见的错误（写完报告自检一遍）

1. **把当天涨幅榜第一当买入信号**：板块涨幅、资金、涨停家数三项都第一，往往已是加速末期，不是起点。
2. **把退潮中的反抽当新一轮启动**：涨停家数回升、封板率修复看着像回暖，区别只在龙头是不是创新高；老题材反抽不成立。
3. **用“它还在涨”给自己壮胆**：盘中摸涨停不等于封住；换手是不会说谎的指标（板块内涨停股平均换手 ≥20% 属高位区，接近 40% 属派发嫌疑）。
4. **把「未获取」当正数**：一格没有可比数字就是「未知」，既不算正也不算负；单日的主力净流入只能说明状态，方向必须两个时点（今日 vs 基准日）。用未知撑出「三格全正」，等于用结论补证据。

## 6. 数字从哪来（字段对照）

| 判定需要 | 来源 |
|---|---|
| 板块涨停家数（今/昨） | 板块成分股代码集合（fetch_sector_leaders --board BKxxxx）∩ zt_rows（今日）/ yesterday_performance.rows（昨日）；limit-find 报告「分板块晋级与炸板统计」按 4 字截断行业名给的是参考口径，两者不一致时以代码求交为准 |
| 板数结构、最高板、晋级率、炸板率 | 代码求交结果（板数、最高板）+ 「连板高度与最高板」高标梯队表（一字、首封时间）+「分板块晋级与炸板统计」（晋级率/炸板率参考） |
| 龙头今日状态（封住/炸板/跌停） | 代码求交（涨停池/炸板池/跌停池）+「连板高度与最高板」+「昨日涨停今日表现」 |
| 主力净流入（今日） | 报告「当日主线板块（板块行合并表）」 |
| 主力净流入（基准日，第三格对比用） | 阶段演变时间线：该板块在更早 limit-find 报告「当日主线板块」行里的数值，优先前一交易日；缺失时取更早的最近一天并注明“X 日缺失，属两日对比”；都没有则第三格记「未知」 |
| 板块当日/5日/10日涨幅、换手%、成交额 | 报告板块行 + fetch_sector_boards.py |
| 板块内个股换手、封板资金、首封时间 | fetch_limit_up.py --json 的 zt_rows（按代码与板块成分股求交） |
| 个股主力净流入 | fetch_sector_leaders 的 main_inflow_wan；涨停股封板后常返回 0 或很小，属正常，此时用封板资金与成交额作量能证据并注明 |
| 个股角色 | 连板核心 = 板块最高板且 ≥2 板；首板 = 1 板；跟随 = 板块涨幅居前未涨停；板块内全是首板时，按「首封时间最早 → 成交额最大」挑一只写“龙头候选”并注明依据 |
| 板块内分化（高开/低开、尾盘分布） | 报告「昨日涨停股今日开盘与尾盘分类」（按行业）；需要按板块重算时用 yesterday_performance.rows 的 open_class / close_state 与板块成分股代码求交 |
| 板块成分股与候选个股 | fetch_sector_leaders.py --board BKxxxx --top 300（必须取全量：脚本 100 只一页分页拉齐，默认 30 只会漏计板块内涨停家数） |
| 板块权限（能不能买） | ACCOUNT.md「板块权限」（唯一读取的工作区文件） |

## 7. 免责

以上为经验性判定框架，无官方背书；与用户明确说明的个人规则冲突时以用户规则为准。所有分析不构成投资建议，股市有风险，投资需谨慎。
