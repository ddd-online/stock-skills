# 题材生命周期（limit-lifecycle）

「今天的钱在哪」$limit-find 每天已经答了；本 SKILL 回答另一个问题：**这条线现在在第几天**。同一批热门股，处在点火/扩散期与处在加速末期，结局可以差几十个百分点。生命周期不是按板块名字分的，是按每天都在变的数字分的，所以每个交易日都要重新判一次。

本 SKILL 做三件事：给今日主线板块（以及仍在跟踪的历史主线）标注【阶段】与数字依据；用主线健康度三检查点给每条线做体检；最后给出推荐的题材板块与板块内候选股票（只到候选与观察条件，买卖判断走 $stock-analysis → $position-management）。判定口径见 references/limit-lifecycle-cheatsheet.md，报告骨架见 references/report-template.md。

## 触发与前置

- 触发：用户请求判断主线板块的阶段（点火/扩散/加速/退潮）、这条线第几天、是不是要退潮了、板块还活着吗、主线健康度体检、题材轮动到哪一步、推荐哪个题材与板块内哪些股票。
- 前置（按顺序）：
  1. **$limit-find 的当日报告** `report/涨停板复盘/YYYY-MM-DD.md`（文件日期即数据日期，取最近交易日）。报告不存在或日期早于最近交易日时，**先执行 $limit-find** 生成后再继续；执行失败则说明原因结束，不用接口数据临时拼凑主线板块。
  2. $market-data 可用（fetch_sector_boards 板块行情榜、fetch_limit_up --json 涨停池明细、fetch_sector_leaders 板块成分股榜）。
  3. 只读 ACCOUNT.md「板块权限」（主板 60/00、创业板 300/301、科创板 688/689、北交所 4/8/92、ST 是否允许交易）；未提供或未确认时用保守默认（仅主板可交易、ST 不交易）并标注“权限未提供，按默认处理”。不读取 MUST.md / NOTES.md / POSITION.md / stocks/。
- 样本：以当日报告为第一份，加 `report/涨停板复盘/` 下日期早于数据日期的最近四份，共 ≤5 份；不足时按实际份数写“样本 N 份，不足五次”。
- 落盘：报告写入 report/题材生命周期/YYYY-MM-DD.md（YYYY-MM-DD 为数据日期；report/ 与 report/题材生命周期/ 不存在则创建；同日再次运行覆盖更新并注明运行时间），格式照 references/report-template.md 的固定骨架。
- 交接：本 SKILL 只做阶段判定、体检与候选筛选，**不给买点/止损/仓位、不预测次日**；要买什么、在哪买转 $stock-analysis，仓位走 $position-management。

## 流程

### 第一步：定位并读取 limit-find 报告

1. 取 `report/涨停板复盘/` 下最近一份 `YYYY-MM-DD.md`：其文件日期就是本次数据日期。目录不存在或最新报告日期早于最近交易日 → 先执行 $limit-find（它自动解析最近有数据的交易日），拿到它的落盘报告再继续；两次都拿不到报告则说明原因结束，不猜数据。
2. 从当日报告取六节数字：「当日主线板块（板块行合并表）」（板块名与 BK 代码、类型、今日/5日/10日涨幅、领涨股、主力净流入、涨停家数、判定）、「连板高度与最高板」（最高板数、名单、一字、高标梯队表）、「昨日涨停今日表现」、「昨日涨停股今日开盘与尾盘分类」（分行业的开盘与尾盘分布、板块强弱、内部分化）、「分板块晋级与炸板统计」（各行业昨日/今日涨停家数、板数结构、晋级率、炸板率、最高板）、「阵型判定」。
3. 读本目录 `report/题材生命周期/` 下日期早于本次数据日期的最近一份报告，取它的「推荐题材板块」与「主线健康度三检查表」→ 得到**上一日在跟踪的板块**（≤5 个），用于判定延续/转弱/移出跟踪。
4. 读 `report/涨停板复盘/` 下日期早于数据日期的最近四份报告，取各日的「当日主线板块」与「分板块晋级与炸板统计」→ 补充阶段演变时间线所需的逐日数字（涨停家数、最高板、主力净流入）。

### 第二步：经 $market-data 补取判定所需列

报告里缺的列按需补取，不重复取已有数字；拉取失败明确报错或标“未获取”，不脑补，所有数字标数据日期：

- 板块行情榜：fetch_sector_boards.py --type industry --sort change、--type concept --sort change、--type concept --sort flow、--type industry --sort gain5（按需）→ 板块今日/5日/10日涨幅、换手%、成交额、主力净流入、领涨股、涨跌家数；用报告「板块（代码）」的 BK 代码对齐同一板块。
- 涨停池明细：fetch_limit_up.py --json → `zt_rows`（每只涨停股的板数、行业、换手 turnover_pct、成交额、封板资金、首封/末封时间）、`zb_all_rows`（炸板池）、`dt_rows`（跌停池），用于龙头状态、换手与量能口径的证据。
- 板块成分股榜：fetch_sector_leaders.py --board BKxxxx --top 300 → 每个候选板块一次，取全量成分股（脚本按 100 只一页分页拉齐，默认 30 只不够用，会漏计板块内涨停家数与候选个股），字段含现价、今日/5日/10日涨幅、换手、量比、成交额、主力净流入、行业、备注，用于板块归属求交、板块内候选股票与内部分化证据。
- 只向 $market-data 说明需要的数据列，具体参数由 $market-data 按其 SKILL 执行。

**板块归属只按代码求交，不按名称匹配**：涨停池的行业名是接口给的 4 字截断名（如「汽车零部」「自动化设」「互联网电」），与板块行情榜的板块名（如「汽车零部件」「互联网电商」）不能直接比对，靠名称匹配会把「汽车零部」错配到「汽车」。做法是：以 limit-find 报告「当日主线板块」里的 BK 代码（缺代码时用 fetch_sector_boards.py --search <板块名> 定位并注明来源）取成分股代码集合，再与涨停池/炸板池/跌停池/昨日涨停股按**代码**求交，得到该板块的涨停家数、最高板、平均换手、炸板与跌停家数。

### 第三步：给每个板块标阶段与判断理由

判定顺序**固定**（默认口径照 references/limit-lifecycle-cheatsheet.md，用户请求中说明的个人阈值优先并在报告中注明）：

1. **退潮**：龙头断板/炸板/跌停（昨日最高板个股今日不在涨停池），或板块出现跌停且涨停家数较昨日减少，或板块主力净流入转负且涨停家数减少。
2. **加速**：高度条件（龙头 ≥4 板，或板块内 ≥2 只三板及以上，或板块涨停家数占全场比重 ≥15%）**且**量能条件（板块内涨停股平均换手 ≥20%）。默认口径明确不含“成交额创阶段新高”：fetch_sector_boards 只给当日快照，没有历史成交额来源；本 SKILL 把每日成交额记进「阶段演变时间线」，样本 ≥3 份后可作交叉印证写进理由，样本不足时写“成交额样本不足”。
3. **扩散**：涨停 ≥5 家，或（出现 2–3 板核心票且涨停 ≥3 家）；且板块主力净流入为正；且 5日与10日涨幅**至少一个为正** → 扩散；若 5日与10日都为负 → 写「扩散（首日，持续性待确认）」并把两个负值写进理由。
4. **点火**：涨停 1–3 家、一板占比 ≥2/3 且板块内无 2 板以上个股（当日涨幅 ≥+3% 时在理由里注明“涨幅偏大，点火待确认”）。
5. **降级/收缩**：不满足第 2–4 条，但板块内仍有 ≥1 只 2 板及以上，或涨停 ≥2 家 → 取该板块样本内最近一次的阶段并加「（收缩）」，如「扩散（收缩）」「加速（收缩）」；样本不足时按数字直判：有 2 板及以上 → 「扩散（收缩）」，只有 1 家首板 → 「点火（收缩）」。
6. **无涨停 / 阶段待确认**：今日与昨日涨停均 0 家 → 写「无涨停（未启动/已退潮）」；其余不满足上面五条 → 写「阶段待确认（数据不足）」并列出缺哪几个数字，不硬判。

每个板块同时给出：

- **本轮第 N 天**：以样本内该板块**首次出现涨停（≥1 家）**那天为第 1 天连续计数；中途出现 0 家涨停的日子视为本轮结束，之后再出现写「第 1 天（重启）」；样本不足时按实际份数写。
- **判断理由**：一条一行，每条跟一个数字（涨停家数今/昨、最高板今/昨与龙头今日状态、主力净流入今/昨、平均换手或成交额、板块涨幅）。
- **冲突处理**：健康度两格为负 → 阶段直接落「退潮」（在理由里写明“三检查点两格负”）；**一格为负或存在「弱」格**（资金缩量、宽度收缩）→ 阶段加「（收缩）」；$limit-find 的板块活跃度标“转弱”而本 SKILL 数字仍指向扩散/加速 → 阶段写「扩散（收缩）」或「加速（收缩）」，两套数字都写出来。

### 第四步：主线健康度三检查点

每个板块三格，每格四种状态：**正 / 弱 / 负 / 未知**；每个「正」「弱」「负」都要指向一个可比数字（两个时点 + 数值），指不出来就写「未知」，**未知既不算正也不算负**。三格的状态定义表、风电设备示例与综合结论优先级表见 references/limit-lifecycle-cheatsheet.md（填表前读）。必须记住三条：

- **第三格是资金方向，必须两个时点**：今日主力净流入 vs 基准日（时间线里该板块最近一份有数值的报告日期，优先前一交易日；缺失时取更早的最近一天并注明“X 日缺失，属两日对比”）。默认阈值 70%，低于即记「弱」；单日数值只能说明状态，不能说明方向。
- **综合结论按优先级**：负 ≥2 → 已进入退潮、移出跟踪；负 =1 → 已进入收缩；无负但有弱 → 继续跟踪但不作为主线；无负无弱但有未知 → 证据不足、不能判“还活着”；只有三格全正才写「还活着」。
- **不许用结论补证据**：缺数字不用 0 或“未获取”补位，也不用括号放宽规则；未知格不能支撑推荐。

### 第五步：生成推荐（题材板块 + 板块内股票）

1. **推荐板块**：只推荐阶段为「扩散」或「扩散（首日，持续性待确认）」、且**三格全正（无负、无弱、无未知）**的板块，按「涨停家数 + 主力净流入」排序取 ≤3 个。**点火不进推荐**（点火的样本是 1–3 家首板，还没出现连板核心，属观察期）；两正一弱（如资金缩量）不算还活着、也不进推荐——写「继续跟踪但不作为主线」。
2. **不推荐但要写明的板块**：点火 → 写「列观察，连续跟踪 3 天，等确认（出现连板核心或家数上到 5 家以上）后再评估；不进推荐」；「扩散（收缩）」「点火（收缩）」→ 写「只跟踪不新增，等三格回到全正或龙头创新高」；加速 → 写「空仓不追，持有者按既有规则减仓」；退潮 → 写「移出跟踪，等下一轮点火」；阶段待确认或无涨停 → 写缺哪几个数字或未启动；这些都只进「排除与不推荐清单」，不做候选。
3. **板块内候选股票**：对每个推荐板块，先列出该板块今日涨停股（板块成分股代码集合 ∩ 涨停池，名称与板数取自 $limit-find「涨停全名单」），再从成分股榜里补 ≤3 只未涨停的「跟随」候选（今日涨幅与 5日涨幅居前、主力净流入为正），逐只给出：
   - 角色：连板核心（该板块最高板且 ≥2 板）/ 首板（1 板）/ 跟随（板块内涨幅居前但未涨停）；板块内最高板为 1 板时（没有连板），从首板里挑一只作为「龙头候选」，判定依据按「首封时间最早 → 成交额最大」依次取第一个，并在报告里写明用的是哪条依据，其余仍写「首板」；
   - 数字理由：板数与涨停统计、换手%、封板资金、5日与10日涨幅（与板块对比）、首封时间（个股主力净流入以接口返回为准：涨停股封板后常返回 0 或很小，属正常，此时用封板资金与成交额作量能证据并注明）；
   - 观察条件：可检查的启动与失效条件（如“放量突破平台 {{价位}}”“跌破 MA10 {{价位}} 未收回”“次日竞价低开破 {{价位}} 视为走坏”），写在报告里、不落盘；
   - 权限：按 ACCOUNT.md 板块权限标注（已开通/未开通并剔除），报告注明权限来源与因权限剔除的只数。
4. **边界**：不给买点、止损、止盈、仓位与手数，不写“明天会涨”；每只候选注明“是否值得买由 $stock-analysis 判断”。推荐板块为空时明确写「今日无推荐板块」并给出原因（全线加速/退潮、样本不足等），不硬凑。

### 第六步：生成报告并落盘

1. 读 references/report-template.md，按骨架逐节填充：节名、表头、列顺序照抄，`{{...}}` 全部替换为真实数字或“未获取”；当天没有内容的小节保留标题并写“无”或“不适用”；模板自带的使用说明与填充示例不写进报告。
2. 正文先写入 report/题材生命周期/YYYY-MM-DD.md（目录不存在则创建；同日再次运行覆盖更新并注明运行时间），再在回复中给阶段结论、三格体检结果、推荐板块与个股摘要及文件位置。

## 报告格式（固定）

以 references/report-template.md 为骨架，节名、表头、列顺序照抄，不新增或调序；模板里的使用说明与填充示例不写进报告。不可省略的要求：

- 落盘 report/题材生命周期/YYYY-MM-DD.md（文件名日期＝数据日期；同日重跑覆盖更新并注明运行时间），结尾必须带“不构成投资建议”。
- 阶段列写全后缀（「扩散（收缩）」「扩散（首日，持续性待确认）」等）并给出本轮第 N 天；阶段判断理由每条跟一个数字。
- 三检查表每格写「状态 + 两个时点的数字」，三格合计写明几正几弱几负几未知；第三格必须写出今日值、基准日值与比例。
- 推荐只列「扩散」或「扩散（首日，持续性待确认）」且三格全正的板块；点火、有弱格或未知格的板块只进「排除与不推荐清单」。

各节的内容规格、表头与填写示例见 references/report-template.md（第六步落盘前读）。

## 硬性规则

- 依赖明确：必须有 $limit-find 的当日报告；没有就先执行 $limit-find，执行不成功就说明原因结束，不用接口数据临时拼凑主线板块；报告中注明所读报告的日期与份数。
- 阶段每天重判：阶段只能由当日与样本内的真实数字推出，昨天判过不代表今天有效；只判当前位置，不推演次日阶段。
- 数据必须真实：$market-data 拉不到就明确报错或标“未获取”，不编造涨停家数、板数、换手、成交额、主力净流入或板块数据；所有数字标数据日期。
- 口径透明：阶段、三检查点、推荐排序都用默认口径或用户说明的口径，报告里注明用的是哪一档；跨报告取历史数字时写清取自哪份报告。
- 正负必须可核对：三检查表里每一个「正」「弱」「负」都要指向一个可比数字（两个时点 + 数值，资金格还要写比例）；指不出可比数字就写「未知」，**未知既不算正也不算负**——不得用「未获取」凑出「三格全正」，也不得把单日状态当作方向。
- 只给筛选不给动作：推荐只到「板块 + 候选个股 + 数字理由 + 观察条件」，**不给买点、止损、止盈、仓位与手数**，不预测次日；买卖判断转 $stock-analysis → $position-management。
- 板块权限硬过滤：只推荐 ACCOUNT.md「板块权限」已开通的板块内股票；未开通板块即使形态满分也不进入推荐，报告注明权限来源与剔除只数。
- 不硬凑：推荐板块或候选个股为空时写明原因（全线加速/退潮、样本不足、权限剔除），不为了凑数把加速或退潮的板块写成推荐。
- 报告必落盘：先写 report/题材生命周期/YYYY-MM-DD.md，再回复摘要；回复不替代落盘。
- 格式统一：报告按 references/report-template.md 的固定骨架输出，节名与表头不改写、不调序、不新增小节；模板里的使用说明与填充示例不写进报告。
- 输出可视化：数字一律进表格；趋势与路径用箭头（如「本轮第 3 天：点火 → 扩散」「最高板 2→3」），状态用固定标记（正/弱/负/未知、还活着/收缩/移出跟踪）；分布类可加等宽条（如 ▉▉▉ 3 家）；不写散文式数字段，不用表情符号。
- 免责声明：报告结尾必须带“不构成投资建议”。
