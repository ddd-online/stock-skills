# 持仓生命周期管理（建仓 → 加仓 → 清仓 → 总结）

## 触发与前置条件

- 触发：用户直接请求建仓/加仓/减仓/空仓/清仓/平仓总结，或 stock-analysis 输出建仓/加仓/减仓/空仓信号（建仓/加仓信号带六格清单分析交接）后自动调用。
- 前置：工作区已初始化（ACCOUNT.md / POSITION.md / stocks/）；建仓前必须有 stock-analysis 的分析结果（支撑区买点、压力区止盈、止损、时间止损、买入理由）——用户直接触发建仓而本 SKILL 未收到该分析时，先调用 $stock-analysis 获取，未获得分析结果不建仓；加仓前该股必须在 POSITION.md 持仓中；清仓前该股必须在 POSITION.md 持仓中。
- 依赖文件：ACCOUNT.md（本金/现金/总盈亏/累计支取/实际可用资产/资金规则）、POSITION.md（总览表 + 该股持仓明细小节）、MUST.md（个人交易风格与必守规则）、TRADE-STATS.md（累计交易记录与连亏计数）；每次建仓/加仓/减仓/清仓后更新 POSITION.md 并在 TRADE-SUMMARY.md 追加交易记录，资金变动更新 ACCOUNT.md，清仓后补写 TRADE-SUMMARY.md 盈亏与总结并更新 TRADE-STATS.md。
- 动作前确认：每个动作前调用 $market-data 拉取当前价格，确认建仓/加仓/减仓/清仓条件仍成立。
- 禁止：无计划建仓（缺买点/止损/止盈）、对非持仓股加仓或清仓。

## 资金调度（每个动作前必做）

四个动作（建仓/加仓/减仓/空仓）都有触发条件与金额上限；金额按 ACCOUNT.md「资金规则」计算，不写死。

- 读取：ACCOUNT.md（本金、现金、总盈亏、累计支取、实际可用资产、资金变化记录、资金规则）。
- 账户口径：实际可用资产 = 本金 + 总盈亏 − 累计支取（以 ACCOUNT.md「账户总览」为准，缺失按本金计算并标注）；现金红线与单笔预算均以实际可用资产为基数；本金只可追加，支取只减现金并计入累计支取（不减本金与盈亏），总盈亏只由已实现交易产生（浮盈不计入）；每次资金变动（买卖/追加/支取/盈亏结算）后按此口径重算账户总览与资金规则，并在「资金变化记录」追加一行
- 现金储备：按 ACCOUNT.md「资金规则」执行；低于红线时禁止建仓/加仓，只允许减仓/空仓。
- 单笔预算：按 ACCOUNT.md「资金规则」执行（含连亏降档后的档位）。
- 账户回撤：按 ACCOUNT.md「资金规则」判断是否金额减半；回撤幅度从 ACCOUNT.md 资金变化记录计算。
- 输出资金调度卡（模板见 references/fund-allocation-card.md）：动作 / 触发条件 / 金额上限 / 记录位置；档位（正常/降档/金额减半）写回 ACCOUNT.md 资金规则。
- 禁止：亏损摊平、满仓单吊、情绪票加仓、回本前破例放大仓位。

## 建仓

- 资金约束：建仓金额受资金调度卡约束——现金储备与单笔预算按 ACCOUNT.md「资金规则」执行；第一批小仓试错（1手起）。
- 分批建仓（默认三批封顶，避免手续费侵蚀）：
  - 第一批：回踩支撑企稳（缩量止跌+阳线），小仓试错
  - 第二批：确认——放量突破第一压力/均线
  - 第三批：突破后回踩不破（站稳确认），剩余额度内
- 计算：
  - 一手金额 = 价格 × 100；按100股整数倍申报
  - 验证：最大亏损 =（买入价 − 止损价）× 股数 + 费用 ≤ 单笔亏损预算
  - 费用按 ACCOUNT.md 交易费用设置计算（佣金费率与最低佣金；印花税卖出 0.05%、过户费 0.01‰）
- 下单前检查（缺一条不做）：买点条件成立？止损/止盈/时间止损已写？亏损在预算内？T+1 已考虑？费用已计入？
- 禁止：条件不满足就下单、全仓、无止损下单。
- 建仓执行后：创建 stocks/<股票名称-股票代码>/STOCK-REVIEW.md（不存在时按本 SKILL 的 assets/STOCK-REVIEW.md 模板）并写入「交易计划」节（规则见下方「STOCK-REVIEW.md 文件维护」）；更新 POSITION.md——总览表新增该股一行，并按 POSITION.md 的结构约定（setup-stock-workspace assets/POSITION.md）创建 `### <股票名> <代码>` 持仓明细小节（买入日期/买入成本/现价浮动盈亏/止损/止盈/时间止损/买入理由/备注）；同时更新 ACCOUNT.md（资金变化记录追加一行 + 按「账户口径」重算总盈亏/实际可用资产/红线/预算）；TRADE-SUMMARY.md 不存在时按本 SKILL 的 assets/TRADE-SUMMARY.md 模板创建，并在交易记录表追加一行（方向=买入）；若该股仍在 WATCHLIST.md 观察池中，同步移出——删除观察池清单中该股行与其条件单参数，并在“移除记录”注明“已建仓”，持仓期间不再为该股挂观察池条件单（日常检查走 stock-review）。
- 模板见 references/entry-checklist.md 与 references/batch-position-card.md。

## STOCK-REVIEW.md 文件维护

- 归属：STOCK-REVIEW.md = 交易计划 + 持仓期间每日检查记录，是该股唯一落盘的交易计划文件（工作区不再有 TRADE-RULES.md；平仓复盘不写本文件，只写 TRADE-SUMMARY.md）。交易计划含资金调度结果（买入价×手数、总成本含佣金、最大亏损金额与本金%、盈亏比），只能由本 SKILL 在建仓执行时创建并写入；stock-review 只在该文件「每日检查」表追加行，不创建文件、不改写交易计划。
- 填写：按建仓资金调度与费用计算结果填模板「交易计划」节（股票/代码、买入日期、买入价×手数、总成本含佣金、买入理由、止损、止盈、时间止损、最大亏损、盈亏比）；stock-analysis 的六格清单分析（选什么/何时买/买多少/错了怎么办/对了怎么办/交易后）在建仓前完成并交接给本 SKILL 汇总，不单独落盘。盈亏比 = (止盈价 − 买入价) ÷ (买入价 − 止损价)；最大亏损 = (买入价 − 止损价) × 股数 + 费用，占本金% 以 ACCOUNT.md 实际可用资产（缺失时按本金并标注）为基数。
- 加仓/减仓后：最新成本与止损止盈只更新 POSITION.md 持仓明细，并在 TRADE-SUMMARY.md 追加交易记录，不回写初始交易计划；持仓检查以 POSITION.md 为准。
- 归档：清仓后与 TRADE-SUMMARY.md 一起移入 history/YYYY-MM-DD/（见「平仓复盘与总结」第 7 步）；下次建仓该股时重新创建。

## 加仓决策

输入：stock-analysis 的加仓建议（能否加、参考加仓价/止损止盈/批次）；本 SKILL 负责计算并确认「加多少」。

两个条件全部满足才考虑加仓：
1. 现有持仓是盈利的（禁止亏损摊平）
2. 趋势延续：价格仍在支撑上方、未破位

加仓条件=判断被确认：第一批买入后上涨且趋势确认才加；第一批后下跌再买=亏损摊平，禁止。
反例：持仓亏损时加仓摊低成本→违反条件 1，禁止；正确做法是按计划止损，等新买点重新建仓。

额度计算：
- 可买股数 ≈ 单笔最大亏损 ÷（加仓价 − 止损价）
- 上限：不超过可用现金（ACCOUNT.md 当前现金）；按一手金额（价格×100）取整
- 资金约束：加仓后整个仓位的单笔亏损预算仍须符合 ACCOUNT.md「资金规则」；现金储备低于红线不加仓

加仓部分独立计划：按建仓标准重写一份（买入价、止损、止盈、时间止损、最大亏损、盈亏比），全部独立计算。

加仓后的整体规则：
- 重新确认整仓止损止盈：止损只可上移（保护利润），不可下移（扩大风险）
- 盈亏平衡成本要重算，但决策依据是「条件是否成立」，不是「摊低成本」
- 加仓后触发止损，按整仓规则执行，不区别对待

加仓执行后：更新 POSITION.md 总览表与该股持仓明细小节（手数/成本/止损止盈/浮动盈亏；备注按“{{日期}} 备注：加仓 …”追加），并更新 ACCOUNT.md 资金变化记录，在 TRADE-SUMMARY.md 交易记录表追加一行（方向=加仓）。

模板见 references/batch-position-card.md。

## 减仓与分批止盈（≥2手）

- 触发：stock-analysis 减仓信号（到第一压力位 / 跌破移动止损），或既定的分批止盈计划。
- 第一批：到达第一压力位，卖一半（≥1手）落袋。
- 第二批：放量站稳后看第二目标；若跌破第一压力/破位则全部卖出，不犹豫。
- 简化版：没时间跟踪就一次全卖（仍然正确）。
- 前提：至少2手才能分批（A股卖出按100股）；不足2手（仅1手）时，到压力位或破位直接清仓处理。
- 执行后：更新 POSITION.md 总览表与该股持仓明细小节（手数/成本/止损止盈；备注按“{{日期}} 备注：减仓 …”追加），并更新 ACCOUNT.md 资金变化记录，在 TRADE-SUMMARY.md 交易记录表追加一行（方向=减仓，记录该笔盈亏）。

## 清仓执行

- 触发情形：止损触发（收盘跌破/跳空破位）、止盈到位、时间止损到期、买入理由破坏（stock-analysis 空仓信号）。
- 结论来源：触发结论由 stock-review 每日检查或 stock-analysis 空仓信号给出，或用户自行决定；本 SKILL 不代替用户下单，可能不在交易时段。
- 执行：用户在可交易时间自行卖出（触发即走；跳空破位/暴跌日不等收盘；接受滑点；T+1 当天买入不能卖），卖出后把卖出价、手数、卖出日期告知本 SKILL。
- 结算：以用户提供的实际成交价为准，费用按 ACCOUNT.md 交易费用设置计算（缺失用默认并标注）；记录实际盈亏与滑点，计算公式见下方平仓复盘事实层。
- 清仓后：从 POSITION.md 移除该股的总览表行与持仓明细小节（完整记录已在 stocks/<股票名称-股票代码>/history/ 归档），更新 ACCOUNT.md（资金变化记录追加一行 + 总盈亏与按「账户口径」重算实际可用资产/红线/预算），并在 TRADE-SUMMARY.md 交易记录表追加一行（方向=卖出/清仓）。

## 平仓复盘与总结（卖出后必做）

输入：用户提供的实际卖出价、手数、卖出日期；本 SKILL 不代替用户下单。

按「事实 → 执行 → 判断 → 改进」四层复盘，顺序不能乱：先算账，再查纪律，然后判断对错，最后才谈改进。原则：结果由市场决定，过程由自己决定——复盘只审判过程，不审判结果。

1. 事实层（先算账）：计算实际盈亏——买入成本 = 买入价×股数 + 买入佣金；卖出净额 = 卖出价×股数 − 佣金 − 印花税0.05% − 过户费0.01‰；盈亏 = 卖出净额 − 买入成本（费率以 ACCOUNT.md 交易费用设置为准，缺失用默认万2.5/最低5元并标注）。滑点 = 实际成交价 − 预设止损/止盈价，差额单列。
2. 执行层（查纪律）：逐条对照该股 STOCK-REVIEW.md「交易计划」（买点条件/止损/止盈/时间止损/盈亏比）与 TRADE-SUMMARY.md 逐笔记录，结合下单前六问，标注每条执行了没有，给出纪律得分。执行与判断分开记：止损做对了就是做对了，不因结果亏钱而否定。
3. 判断层（判对错）：当初的买入理由后来成立了吗？判断对错，不和运气混在一起。
4. 改进层（出规则）：流程哪里改？提炼至少一条可落地规则，随第 5 步写入 TRADE-SUMMARY.md「总结」，关键教训沉淀到 NOTES.md。
5. 补写 TRADE-SUMMARY.md：文件已在建仓时按本 SKILL 的 assets/TRADE-SUMMARY.md 模板创建，并随建仓/加仓/减仓/清仓逐笔追加交易记录；此处补写「本次盈亏」与「总结」（写入 stocks/<股票名称-股票代码>/），总结内容参考 references/exit-summary-template.md 的四层复盘（事实→执行→判断→改进），不写账户级累计指标。
6. 更新四指标统计：把该笔（日期/股票/方向/价格/盈亏/是否符合系统/违规说明）写入工作区 TRADE-STATS.md；攒够 5-10 笔后按 TRADE-STATS.md「公式速查」结算四指标（胜率/平均盈亏/期望值/最大回撤），判断系统是否有效、亏损在入场端还是出场端；一次只改一条规则。触发 ACCOUNT.md「资金规则」的降档条件（连亏/回撤等）时按规则降档（仓位减半/金额减半），档位写回 ACCOUNT.md 资金规则。
7. 归档：把 STOCK-REVIEW.md 与 TRADE-SUMMARY.md（含平仓复盘总结）**移动**到 history/YYYY-MM-DD/（归档=移动，工作区不留副本；下次建仓该股时由本 SKILL 重新创建这两个文件）。

每笔平仓都问一句：「这笔交易能长出什么规则？」有答案，这笔就没白做。

输出格式见 references/exit-summary-template.md。

## 硬性规则

- 加仓≠摊平：亏损时不加仓；第一批后下跌再买=摊平，禁止。
- 任何一笔加仓都要独立完成一次“计划→执行→记录”。
- 资金调度先行：任何建仓/加仓前必须先输出资金调度卡；违反 ACCOUNT.md「资金规则」（现金储备红线、预算超限）时禁止执行。
- 建仓即出池：买入成功后，若该股在观察池中，必须同步移出观察池（含条件单参数），避免持仓标的与观察池重复挂单。
- 降档执行：触发 ACCOUNT.md「资金规则」的降档条件时立即降档，不因“想回本”破例放大仓位。
- 减仓/空仓不犹豫：破位减仓、止损离场不商量。
- 仓位处理集中：所有资金调度与仓位计算（现金储备、单笔预算、批次、手数、费用）由本 SKILL 负责；stock-analysis 只提供信号、锚点与建议。
- 交易计划归属：STOCK-REVIEW.md 与其「交易计划」节由本 SKILL 建仓时创建/写入（涉及资金调度；工作区不再有 TRADE-RULES.md），stock-review 只追加每日检查行；四层复盘内容只写 TRADE-SUMMARY.md，不写 STOCK-REVIEW.md。
- 不替用户做决定：输出客观条件和计算，是否执行由用户决定。
