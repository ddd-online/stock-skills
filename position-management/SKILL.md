# 持仓生命周期管理（建仓 → 加仓 → 清仓 → 总结）

## 流程总览

1. 收集输入：股票代码、本金、最大亏损预算（默认本金2%）、买点/止损/止盈/支撑压力（可来自 stock-analysis 或 stock-support-resistance-analysis 的输出）。
2. 拉取当前价格确认买点条件仍成立：

   ```bash
   python scripts/fetch_quote.py <代码> --days 30
   ```

3. 建仓：计算股数与亏损 → 下单前检查 → 输出建仓计划卡。
4. 持仓期间：每日收盘5分钟检查（详细流程用 stock-review）。
5. 加仓决策：三条件全过才考虑 → 计算额度 → 输出加仓计划。
6. 清仓执行：触发即走、接受滑点、T+1 → 记录实际盈亏。
7. 平仓总结：复盘三问 + 滑点记录 + 一条改进项。

## 建仓

- 计算：
  - 一手金额 = 价格 × 100；按100股整数倍申报
  - 最大可买手数受“单只≤40%仓位”限制
  - 验证：最大亏损 =（买入价 − 止损价）× 股数 + 费用 ≤ 单笔亏损预算
- 下单前检查（缺一条不做）：买点条件成立？止损/止盈/时间止损已写？亏损在预算内？总仓位≤70%？T+1 已考虑？费用已计入？
- 禁止：条件不满足就下单、全仓、无止损下单。
- 模板见 references/entry-checklist.md。

## 加仓决策

三个条件全部满足才考虑加仓：
1. 现有持仓是盈利的（禁止亏损摊平）
2. 趋势延续：价格仍在支撑上方、未破位
3. 加仓后总仓位≤70%、单只≤40%

加仓部分单独计算：买入价、止损、止盈、亏损预算都要重新写，且加仓后重新确认整个仓位的止损止盈（可上移止损，不可下移）。

规则与额度计算见 references/add-position-rules.md。

## 清仓执行

- 触发情形：止损触发（收盘跌破/跳空破位）、止盈到位、时间止损到期、买入理由破坏。
- 执行规则：触发即走；跳空破位/暴跌日不等收盘；接受滑点，尽快成交；T+1 当天买入不能卖。
- 卖出后立即记录：卖出价、实际盈亏（佣金万2.5最低5元、印花税0.05%、过户费0.01‰）、滑点。

## 平仓总结

复盘三问：①计划执行了吗 ②买入理由成立了吗 ③流程哪里改进。
输出格式见 references/exit-summary-template.md。

## 硬性规则

- 加仓不等于摊平：亏损时不加仓。
- 任何一笔加仓都要独立完成一次“计划→执行→记录”。
- 不替用户做决定：输出客观条件和计算，是否执行由用户决定。
