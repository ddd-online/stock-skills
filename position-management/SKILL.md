# 持仓生命周期管理（建仓 → 加仓 → 清仓 → 总结）

## 触发与前置条件

- 触发：用户直接请求建仓/加仓/减仓/空仓/清仓/平仓总结，或 stock-analysis 输出建仓/加仓/减仓/空仓信号后自动调用（建仓/加仓信号还需 trade-rules-generate 已生成/追加规则）。
- 前置：工作区已初始化（ACCOUNT.md / POSITION.md / stocks/）；建仓前必须有明确买点/止损/止盈（来自 stock-analysis 输出或用户输入）；加仓前该股必须在 POSITION.md 持仓中；清仓前该股必须在 POSITION.md 持仓中。
- 依赖文件：ACCOUNT.md（本金/现金/总盈亏/资金规则）、POSITION.md（该股持仓与总仓位）、MUST.md（个人交易风格与必守规则）、TRADE-STATS.md（累计交易记录与连亏计数）；每次建仓/加仓/减仓/清仓后更新 POSITION.md，资金变动更新 ACCOUNT.md，每笔清仓后更新 TRADE-STATS.md。
- 禁止：无计划建仓（缺买点/止损/止盈）、对非持仓股加仓或清仓。

## 流程总览

触发方式：用户直接请求，或 stock-analysis 输出建仓/加仓/减仓/空仓信号后自动调用（建仓/加仓信号还需 trade-rules-generate 已生成/追加规则）。

0. 资金调度（每个动作前必做）：读 ACCOUNT.md（本金/现金/总盈亏/资金规则）与 TRADE-STATS.md（连亏计数）→ 计算现金储备（≥本金30%）与单笔预算（≤本金2%，连亏降档1%）→ 输出资金调度卡。
1. 读取工作区上下文并收集输入：ACCOUNT.md、POSITION.md（该股持仓与总仓位）、MUST.md、股票代码、买点/止损/止盈/支撑压力与信号建议（来自 stock-analysis 的输出）。
2. 拉取当前价格确认条件仍成立：调用 $market-data 获取该股行情。

3. 建仓：确认批次结构 → 计算股数与亏损（受资金调度卡约束）→ 下单前检查 → 输出建仓计划卡。
4. 持仓期间：每日收盘检查（详细流程用 stock-review）。
5. 加仓决策：两条件全过 → 计算并确认加仓数量（stock-analysis 只提供建议，受资金调度卡约束）→ 输出加仓计划。
6. 减仓与分批止盈（≥2手）：到第一压力卖一半；站稳看第二目标；跌破第一压力/破位全卖。
7. 空仓与清仓执行：无信号现金全留；触发即走、接受滑点、T+1 → 记录实际盈亏。
8. 平仓复盘与总结：四层复盘（事实→执行→判断→改进）+ 滑点记录 → 规则修订写回 TRADE-RULES.md → 生成 TRADE-SUMMARY.md → 更新 TRADE-STATS.md（每 5-10 笔结算四指标，连亏2笔触发降档）→ 归档 history/YYYY-MM-DD/ → 教训沉淀到 NOTES.md。

## 资金调度（每个动作前必做）

参考第18课：四个动作（建仓/加仓/减仓/空仓）都有触发条件与金额上限；金额按实际账户计算，不写死（课程里的 5000 元只是示例）。

- 读取：ACCOUNT.md（本金、现金、总盈亏、资金变化记录、资金规则）与 TRADE-STATS.md（最近交易记录，用于连亏计数）。
- 现金储备：现金 ≥ 本金 × 30%；低于红线时禁止建仓/加仓，只允许减仓/空仓。
- 单笔预算：单笔最大亏损 ≤ 本金 × 2%；连续 2 笔亏损后降档为 1%（仓位减半、停手 1 周）。
- 账户回撤 10%（从 ACCOUNT.md 资金变化记录计算）：新建仓/加仓金额减半，直到统计确认系统有效。
- 输出资金调度卡（模板见 references/fund-allocation-card.md）：动作 / 触发条件 / 金额上限 / 记录位置；档位（正常/降档/停手中）写回 ACCOUNT.md 资金规则。
- 禁止：亏损摊平、满仓单吊、情绪票加仓、回本前破例放大仓位。

## 建仓

- 资金约束：建仓金额受资金调度卡约束——现金储备≥30%红线、单笔亏损预算（≤本金2%，降档1%）内；第一批小仓试错（1手起）。
- 分批建仓（默认三批封顶，避免手续费侵蚀）：
  - 第一批：回踩支撑企稳（缩量止跌+阳线），小仓试错
  - 第二批：确认——放量突破第一压力/均线
  - 第三批：突破后回踩不破（站稳确认），剩余额度内
- 计算：
  - 一手金额 = 价格 × 100；按100股整数倍申报
  - 验证：最大亏损 =（买入价 − 止损价）× 股数 + 费用 ≤ 单笔亏损预算
  - 费用按 ACCOUNT.md 交易费用设置计算（佣金费率与最低佣金；印花税卖出 0.05%、过户费 0.01‰）
- 下单前检查（缺一条不做）：买点条件成立？止损/止盈/时间止损已写？亏损在预算内？T+1 已考虑？费用已计入？
- 禁止：条件不满足就下单、全仓、无止损下单。
- 建仓执行后：更新 POSITION.md（新增该股持仓行）与 ACCOUNT.md 资金变化记录；若该股仍在 WATCHLIST.md 观察池中，同步移出——删除观察池清单中该股行与其条件单参数，并在“移除记录”注明“已建仓”，持仓期间不再为该股挂观察池条件单（日常检查走 stock-review）。
- 模板见 references/entry-checklist.md 与 references/batch-position-card.md。

## 加仓决策

输入：stock-analysis 的加仓建议（能否加、参考加仓价/止损止盈/批次）；本 SKILL 负责计算并确认「加多少」。

两个条件全部满足才考虑加仓：
1. 现有持仓是盈利的（禁止亏损摊平）
2. 趋势延续：价格仍在支撑上方、未破位

加仓条件=判断被确认：第一批买入后上涨且趋势确认才加；第一批后下跌再买=亏损摊平，禁止。

额度确认：
- 按单笔最大亏损预算倒推：可买股数 ≈ 最大亏损 ÷（加仓价 − 止损价）
- 上限：不超过可用现金（ACCOUNT.md 当前现金）；按一手金额（价格×100）取整
- 资金约束：加仓后整个仓位的单笔亏损预算仍 ≤ 本金2%（降档1%）；现金储备低于30%红线不加仓；止损只上移。

加仓部分单独计算：买入价、止损、止盈、亏损预算都要重新写，且加仓后重新确认整个仓位的止损止盈（可上移止损，不可下移）。

加仓执行后：更新 POSITION.md（手数/成本/止损止盈/浮动盈亏）与 ACCOUNT.md 资金变化记录。

规则与额度计算见 references/add-position-rules.md 与 references/batch-position-card.md。

## 减仓与分批止盈（≥2手）

- 触发：stock-analysis 减仓信号（到第一压力位 / 跌破移动止损），或既定的分批止盈计划。
- 第一批：到达第一压力位，卖一半（≥1手）落袋。
- 第二批：放量站稳后看第二目标；若跌破第一压力/破位则全部卖出，不犹豫。
- 简化版：没时间跟踪就一次全卖（仍然正确）。
- 前提：至少2手才能分批（A股卖出按100股）；不足2手（仅1手）时，到压力位或破位直接清仓处理。
- 执行后：更新 POSITION.md（手数/成本/止损止盈）与 ACCOUNT.md 资金变化记录。

## 清仓执行

- 触发情形：止损触发（收盘跌破/跳空破位）、止盈到位、时间止损到期、买入理由破坏（stock-analysis 空仓信号）。
- 结论来源：触发结论由 stock-review 每日检查或 stock-analysis 空仓信号给出，或用户自行决定；本 SKILL 不代替用户下单，可能不在交易时段。
- 执行：用户在可交易时间自行卖出（触发即走；跳空破位/暴跌日不等收盘；接受滑点；T+1 当天买入不能卖），卖出后把卖出价、手数、卖出日期告知本 SKILL。
- 结算：以用户提供的实际成交价为准，按 ACCOUNT.md 交易费用设置计算佣金（费率与最低佣金，缺失用默认万2.5/最低5元并标注），印花税 0.05%、过户费 0.01‰ 固定；记录实际盈亏与滑点（实际成交价 − 预设止损/止盈价）。
- 清仓后：从 POSITION.md 移除该股，更新 ACCOUNT.md 资金变化记录与总盈亏。

## 平仓复盘与总结（卖出后必做）

输入：用户提供的实际卖出价、手数、卖出日期；本 SKILL 不代替用户下单。

按「事实 → 执行 → 判断 → 改进」四层复盘，顺序不能乱：先算账，再查纪律，然后判断对错，最后才谈改进。原则：结果由市场决定，过程由自己决定——复盘只审判过程，不审判结果。

1. 事实层（先算账）：计算实际盈亏——买入成本 = 买入价×股数 + 买入佣金；卖出净额 = 卖出价×股数 − 佣金 − 印花税0.05% − 过户费0.01‰；盈亏 = 卖出净额 − 买入成本（费率以 ACCOUNT.md 交易费用设置为准，缺失用默认万2.5/最低5元并标注）。滑点 = 实际成交价 − 预设止损/止盈价，差额单列。
2. 执行层（查纪律）：逐条对照该股 TRADE-RULES.md 的规则与下单前六问，标注每条执行了没有，给出纪律得分。执行与判断分开记：止损做对了就是做对了，不因结果亏钱而否定。
3. 判断层（判对错）：当初的买入理由后来成立了吗？判断对错，不和运气混在一起。
4. 改进层（出规则）：流程哪里改？提炼至少一条可落地规则，写回该股 TRADE-RULES.md（规则修订，历史保留），关键教训沉淀到 NOTES.md。
5. 生成 TRADE-SUMMARY.md：累计交易记录 + 累计盈亏 + 胜率 + 总结（写入 stocks/<纯数字代码>/，已存在则更新）。
6. 更新四指标统计：把该笔（日期/股票/方向/价格/盈亏/是否符合系统/违规说明）写入工作区 TRADE-STATS.md；攒够 5-10 笔后按第16课公式结算胜率、平均盈亏、期望值、最大回撤（最大回撤从 ACCOUNT.md 资金变化记录计算），判断系统是否有效、亏损在入场端还是出场端；一次只改一条规则（见 references/trade-stats.md）。连续 2 笔亏损时按第18课降档：单笔预算 2%→1%、仓位减半、停手 1 周，档位写回 ACCOUNT.md 资金规则；账户回撤 10% 时新建仓/加仓金额减半。
7. 归档：把 TRADE-RULES.md / STOCK-REVIEW.md / TRADE-SUMMARY.md **移动**到 history/YYYY-MM-DD/（归档=移动，工作区不留副本；下次交易该股重新生成）。

每笔平仓都问一句：「这笔交易能长出什么规则？」有答案，这笔就没白做。

输出格式见 references/exit-summary-template.md 与 references/close-review-four-layers.md。

## 硬性规则

- 加仓不等于摊平：亏损时不加仓。
- 分批≠摊平：第一批后下跌再买是摊平，禁止；加仓条件=判断被确认。
- 任何一笔加仓都要独立完成一次“计划→执行→记录”。
- 资金调度先行：任何建仓/加仓前必须先输出资金调度卡；现金低于30%红线、预算超限时禁止执行。
- 建仓即出池：买入成功后，若该股在观察池中，必须同步移出观察池（含条件单参数），避免持仓标的与观察池重复挂单。
- 降档执行：连续2笔亏损或回撤10%后按规则降档，不因“想回本”破例放大仓位。
- 减仓/空仓不犹豫：破位减仓、止损离场不商量。
- 仓位处理集中：所有资金调度与仓位计算（现金储备、单笔预算、批次、手数、费用）由本 SKILL 负责；stock-analysis 只提供信号、锚点与建议。
- 不替用户做决定：输出客观条件和计算，是否执行由用户决定。
