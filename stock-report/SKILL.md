# 股票每日复盘（stock-report）

## 触发与前置

- 触发：A股交易日 11:45（午间复盘）与 15:15（收盘复盘）定时触发，或用户直接请求。
- 前置：当日为 A 股交易日（非周末、非法定节假日）且当前时间 ≥ 触发时间；非交易日直接结束——不读写文件、不调用行情与邮件接口。
- 依赖：ACCOUNT.md、POSITION.md、WATCHLIST.md、stocks/<代码>/、AGENTS.md（邮件章节取收件人）；协作 skill：$stock-review（持仓检查）、$watchlist-review / $stock-analysis（观察池）、$agently-mail（发邮件）；行情用各 skill 的 scripts/fetch_quote.py。

## 两种模式

| 步骤 | 午间复盘（11:45） | 收盘复盘（15:15） |
|---|---|---|
| 1. 持仓检查 | $stock-review 精简输出；不写 STOCK-REVIEW.md | $stock-review 完整输出；写入 stocks/<代码>/STOCK-REVIEW.md，回写 POSITION.md 现价与浮动盈亏 |
| 2. 观察池 | 仅更新 WATCHLIST.md 状态（等待/信号触发/移除），不跑完整分析 | 对池内每只标的执行 $stock-analysis 完整分析后更新 WATCHLIST.md |
| 3. 邮件正文 | 按 references/email-template.md「午间版」 | 按 references/email-template.md「收盘版」 |
| 4. 发送 / 生成报告 | 收件人从 AGENTS.md 读取；有邮箱则 $agently-mail 发送，无邮箱则生成 report/ 报告文件 | 同左 |
| 5. 清理 | 不清理 | 发送成功后删除本次临时文件、缓存与草稿 |

## 流程

1. 持仓检查：读 POSITION.md 全部持仓，逐只执行 $stock-review——价格位置（盘中/收盘）、量能（半日/全日）、止损/止盈/时间止损是否触发；触发平仓规则的持仓在报告中明确标注「建议平仓」（仅提示，不下单）。
2. 观察池更新：按上述模式跑 $watchlist-review / $stock-analysis，将每只标的归为「等待 / 信号触发 / 移除」并回写 WATCHLIST.md。
3. 生成邮件：读取 references/email-template.md 对应版本，填充 {{...}} 字段；当天没有的内容删行；数字标注数据时间；证据先行，拿不到数据明确标注、不编造。
4. 发送或生成报告：从 AGENTS.md「邮件」章节解析「复盘/通知邮件收件人：<邮箱>」；解析到邮箱 → 调用 $agently-mail 发送（主题：午间「股票午间复盘 YYYY-MM-DD」；收盘「股票每日复盘（YYYY-MM-DD 收盘）」），成功记录日志（区分午间/收盘）；解析不到邮箱 → 不调用邮件接口，将正文写入 report/（午间：report/股票午间复盘-YYYY-MM-DD.md；收盘：report/股票每日复盘-YYYY-MM-DD-收盘.md），并在回复中告知用户文件位置。
5. 清理（仅收盘）：邮件发送成功后删除本次任务产生的临时文件、缓存数据、未合并草稿；report/ 下的交付文件不清理。

## 异常处理

- 非交易日：直接结束，不生成任何文件、不调用邮件接口。
- 午间邮件发送失败：保留午间报告文件并记录错误日志；不影响收盘复盘。
- 收盘邮件发送失败：保留本次全部报告文件（含午间残留）并记录错误日志；待发送成功后再清理。
- 收件人缺失：不发送邮件，按流程生成 report/ 报告文件；视为正常交付，不记失败。
- 任一环节分析异常：记录错误日志；午间异常不阻塞收盘复盘。

## 硬性规则

- 不替用户下单：「建议平仓」只提示，实际卖出由用户在可交易时间执行。
- 数据必须真实：行情/新闻/资金用脚本拉取，失败则标注，不编造现价。
- 持仓期间不调整既定止损/止盈；触发规则按 POSITION.md 记录执行。
- 收件人不写死：一律从 AGENTS.md 读取；AGENTS.md 无邮箱时不调用邮件接口，改为生成 report/ 报告文件。
