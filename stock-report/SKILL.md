# 股票每日复盘（stock-report）

盘中、盘外只改变**数据口径与预案指向**，不改变报告结构。每次都输出同一套五步复盘：

1. 大盘：现在能不能打；
2. 板块：钱在哪个方向；
3. 个股：持仓触发规则了吗；
4. 量价：涨跌是真是假；
5. 预案：下一步什么条件做什么。

盘中报告是截至运行时刻的快照，不是收盘结论；盘外报告使用最近可用的收盘数据。所有报告都不预测涨跌。

## 触发与前置

- 触发：用户任意时间请求每日复盘、盘中复盘、收盘复盘，或定时任务触发。不再要求固定 11:45 / 15:15。
- 前置：工作区已初始化（ACCOUNT.md / POSITION.md / stocks/）；$market-data 可用；协作 skill 为 $stock-analysis 持仓检查模式与 $agently-mail。
- 数据基准：先取 `sh510300`（沪深300ETF）与 `sh000001`（上证指数）的 `quote.datetime`，用行情日期与当前时间自动判断口径；不能只按钟表时间判断，避免节假日/停牌数据被误当成盘中。两者日期不一致时取较新的有效日期，并在报告标出滞后项。
- 非交易日不再直接结束：使用最近交易日收盘数据生成盘外报告；指数行情完全取不到时仍生成账户/持仓报告，市场、板块、个股数据明确标“未获取”。
- 报告路径：`report/股票每日复盘/YYYY-MM-DD.md`，文件名日期为**运行日期**（Asia/Shanghai）；同一天重跑覆盖更新，报告内记录本次运行时间与数据时间。这样盘前使用上一交易日数据时不会覆盖上一交易日的收盘报告。

## 时段自动判定

先以当前时间（Asia/Shanghai）和 `quote.datetime` 的日期判断，不靠猜：

| 大类 | 子类型 | 判定条件 | 数据口径 | 是否落盘检查记录 |
|---|---|---|---|---|
| 盘中 | 连续竞价 | 9:30–11:30 或 13:00–15:00，且行情日期=今天 | 当前快照，成交量未走完 | 否 |
| 盘外 | 午间休市 | 11:30–13:00，且行情日期=今天 | 上午收盘快照 | 否 |
| 盘外 | 盘前 | 9:30 前，且行情日期<今天 | 上一交易日收盘 | 否 |
| 盘外 | 盘后 | 15:00 后，且行情日期=今天 | 当日收盘 | 是，仅交易日 |
| 盘外 | 非交易日/数据未更新 | 周末、节假日，或其他行情日期<今天且不属于盘前 | 最近交易日收盘 | 否 |
| 盘外 | 数据时间异常 | `quote.datetime` 晚于当前运行时间，或明显滞后于当前时段 | 标“数据时间异常/未获取”，不判断盘中 | 否 |

- 当前时间落在 9:30–15:00，但行情日期不是今天：按“盘外·数据未更新”处理，标“未获取实时盘中数据”，不得写成盘中快照。
- 工作日 9:30 前且行情日期<今天，按“盘前”处理；无法确认是否节假日时标“盘前/可能非交易日”，使用最近收盘。
- 15:00 后若 `quote.datetime` 的时钟仍早于 15:00，标“收盘数据可能未更新”，不得把 14:xx 数据当当日收盘。
- `quote.datetime` 的时钟晚于当前运行时间：标“数据时间异常”，不得用未来数据生成盘中结论。
- 报告第一行必须写明：大类（盘中/盘外）、子类型、运行时间、数据时间、数据日期。
- 盘中的触发判断只作临时状态；收盘确认型规则标“待收盘确认”，跳空破位/暴跌型规则按既定计划即时执行。盘外才给最终“触发/未触发”。

## 流程

### 第一步：确认时段与数据

1. 记录运行时间。
2. 跑 `fetch_quote.py sh510300 --days 60 --json` 与 `fetch_quote.py sh000001 --days 60 --json`，取 `quote.datetime`、最新价/收盘价、MA5/10/20。
3. 按上表判定盘中/盘外与子类型；同时检查 `quote.datetime` 是否晚于当前运行时间或明显滞后。时间异常时标“数据时间异常/未获取”，不生成盘中结论。行情日期、时间缺失时同样标“未获取”，禁止把上一交易日数据写成今日盘中。
4. 读取 ACCOUNT.md、POSITION.md、stocks/<股票名称-股票代码>/ 与 AGENTS.md「邮件」章节。

### 第二步：账户与持仓

- 账户总览按 ACCOUNT.md 输出本金、现金、总盈亏、累计支取、实际可用资产、今日资金变动。
- 当前持仓按 POSITION.md 输出手数、成本、现价/最新价、止损、触发规则、止盈、时间止损、浮动盈亏。
- 盘中用当前快照价；午间用上午数据；盘前/非交易日用最近收盘；盘后用当日收盘。数字必须标数据时间。

### 第三步：按统一五步生成复盘

第 1–2 步由本 SKILL 完成：

1. **大盘**：用 510300/上证指数最新价或收盘价、MA5/10/20、MA20 方向与高低点判档位（正常/防守/观望）。盘中只写“当前档位快照”；盘外写截至数据时间的档位（盘后=当日收盘，午间=上午收盘，盘前/非交易日=最近收盘）。
2. **板块**：经 $market-data 取强势股榜/板块榜，归纳强势方向前 3、弱势方向前 3，并对照持仓题材写启动/加速/退潮；盘中标注“截至 HH:MM”，盘外标数据时间（盘后=收盘，午间=上午收盘，盘前/非交易日=最近收盘）。数据缺失写“未获取”，不编榜单或阶段。

第 3–5 步逐只调用 $stock-analysis 持仓检查模式，按统一三段输出：

- 个股：开/高/低/最新价或收盘价、均线位置、距止损/止盈/时间止损、触发判断、买入理由与新信息；
- 量价：成交量/换手与放量缩量四句；盘中必须标“累计量能未走完”；
- 预案：下一观察点、可检查触发条件、动作、不许做什么。

空仓时第 3–5 步写“空仓，无个股检查”，仍保留大盘与板块。某只持仓数据失败时标注失败原因，继续处理其余持仓。

### 第四步：写报告并发送

1. 读取 references/report-template.md，按统一骨架填写；节名、表头、列顺序照抄。
2. 先写 `report/股票每日复盘/YYYY-MM-DD.md`（运行日期），再回复摘要与文件位置。
3. 从 AGENTS.md「邮件」章节读取「复盘/通知邮件收件人」：有邮箱 → 调用 $agently-mail 发送本次报告，主题为「股票每日复盘（YYYY-MM-DD HH:MM · 盘中/盘外）」；无邮箱 → 不调用邮件接口，报告文件即正常交付。

## 落盘边界

- 盘中、午间、盘前、非交易日：只写复盘报告；不写 STOCK-REVIEW.md，不回写 POSITION.md，不追加每日检查行。
- 盘后且行情日期=今天：写复盘报告；由 $stock-analysis 持仓检查模式写入 STOCK-REVIEW.md 当日检查行并回写 POSITION.md 现价/浮动盈亏。
- 同日盘后重跑：STOCK-REVIEW.md 已有当日检查行时更新该行，不重复追加；POSITION.md 只保留最新收盘价与浮动盈亏。
- 任何模式都不改交易计划、不移动止损/止盈、不代替用户下单。

## 异常处理

- 指数行情缺失：报告继续生成，市场档位、板块与个股相关字段标“未获取”，不编造。
- 非交易日无最近收盘数据：仍生成账户/持仓报告并标“行情未获取”，不调用邮件以外的外部写入。
- 单只持仓检查失败：记录原因，继续其余持仓，不阻塞报告。
- 报告或邮件发送失败：保留已生成的报告；邮件失败记录错误，不删除报告。
- 收件人缺失：只落盘，不调用邮件接口，视为正常交付。

## 硬性规则

- **统一内容**：盘中/盘外都按 大盘→板块→个股→量价→预案 五步输出；不再提供“午间精简版”，不删减五步结构。
- **自动判定**：按当前时间 + `quote.datetime` 判断，不能把 11:45/15:15 当成唯一运行条件；非交易日使用最近收盘，不直接结束。
- **口径不混用**：盘中数字标“截至 HH:MM”；盘外标数据时间与数据日期（盘后=当日收盘，午间=上午收盘，盘前/非交易日=最近收盘）；盘中不得把当前累计成交量当全天量，不得把当前价称收盘价。
- **时间不倒流**：`quote.datetime` 晚于当前运行时间时，标“数据时间异常”，不得使用未来数据推断当前盘中状态。
- **触发分口径**：盘中触发只作临时状态，收盘确认型规则待收盘确认；跳空破位/暴跌型按既定计划即时执行；盘外才给最终触发结论。
- **落盘边界**：只有盘后交易日写 STOCK-REVIEW.md 与 POSITION.md；其余模式只写报告，避免盘中重复追加每日检查。
- **数据真实**：行情、资金、新闻用 $market-data；取不到标“未获取”，不编现价、涨跌幅、板块榜或阶段。
- **分工不越界**：大盘/板块由本 SKILL 分析；个股/量价/预案采用 $stock-analysis 输出；建议平仓只提示，不下单。
- **报告必落盘**：`report/股票每日复盘/YYYY-MM-DD.md`（运行日期），同日重跑覆盖并记录运行时间；结尾必须带“不构成投资建议”。
- **输出可视化**：数字进表格或短标记行；状态用固定标记（盘中快照/午间快照/盘前/盘后/非交易日、正常/防守/观望、触发/未触发/待收盘确认）；不写散文式数字段，不用表情符号。
- **邮件不写死**：收件人只从 AGENTS.md 读取；无邮箱不调用接口。
