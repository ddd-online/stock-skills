# 持仓检查（每日 5 分钟）

## 触发与前置条件

- 触发：用户请求检查某只持仓。
- 前置：该股必须在 POSITION.md 持仓中；不在持仓时不执行每日检查，提示改用 $stock-analysis 分析。
- 依赖文件：POSITION.md（持仓字段）、MUST.md（个人交易风格与必守规则）、stocks/<代码>/STOCK-REVIEW.md（买入理由与历史检查记录）。
- 交接：检查后回写 POSITION.md 的现价与浮动盈亏；触发止损/止盈/时间止损时只给出平仓结论，实际卖出由用户在可交易时间执行；用户卖出后调用 $position-management 告知卖出价，由它完成平仓复盘与总结。

## 流程

1. 读取工作区上下文：先从工作区 POSITION.md 获取该股持仓（代码、买入价/成本、手数、止损、触发规则、止盈、时间止损），从 MUST.md 读取个人交易风格与必守规则（检查与结论必须遵守）；买入理由可从 stocks/<代码>/STOCK-REVIEW.md 取。POSITION.md 缺失或未填写时，向用户询问或明确标注“未提供”。
2. 拉取真实数据：

   ```bash
   python scripts/fetch_quote.py <代码> --days 30
   ```

3. 输出“持仓检查报告”：
   - 数据表：现价、今日高/低、距止损/止盈（金额与%）、成交量、换手、MA5/10/20
   - 五条检查：①价格位置 ②量能 ③新信息（查不到标“未核实”）④买入理由是否成立 ⑤心态
   - 客观判断：是否触发规则（如“收盘价14.61 > 止损14.58 → 未触发，按计划持有”）
   - 禁止：建议挪止损、改止盈、加仓摊平
   - 把本次检查结果写入 stocks/<代码>/STOCK-REVIEW.md（不存在则按种子模板创建）
   - 回写 POSITION.md：更新该股现价与浮动盈亏
   - 若触发（收盘跌破止损/跳空破位/止盈/时间止损）：结论为“建议平仓”，写明触发条件与建议动作；不代替用户下单（可能不在交易时段）。用户卖出后调用 $position-management 告知卖出价完成平仓总结；未触发则按计划持有
4. 结尾：“基于截至<日期>的真实数据，不构成投资建议，最终决定由用户作出。”

## 硬性规则

- 客观判断触发与否：只说“触发/未触发”，不预测涨跌。
- 持仓信息以 POSITION.md 为准：先读工作区 POSITION.md，缺失字段再向用户询问或标注“未提供”。
- 真实数据：脚本拉不到就报错，不编造现价。
- 不改规则：持仓期间不调整用户既定止损/止盈。
- 只给平仓结论不下单：触发平仓条件时只输出“建议平仓”，实际卖出由用户在可交易时间执行。
- 只做每日检查：平仓复盘、盈亏计算与 TRADE-SUMMARY.md 由 $position-management 负责，本 SKILL 不越权。
