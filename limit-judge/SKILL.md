# 打板竞价评估（limit-judge）

打板的胜负发生在第二天开盘。本 SKILL 用每天 9:25 之后的几分钟，把昨天涨停的那批股票今天的竞价读成数字：

1. **高开幅度** =（今开 − 昨收）÷ 昨收 —— 昨天买入的人今天拿到多少溢价；
2. **竞价成交额 ÷ 昨日全天成交额** —— 抢筹强度，衡量今天的真实意愿；
3. **集体分布** —— 不是单只票，而是昨天涨停那一整批里有多少高开、多少低开、平均高开多少。

单只股票的竞价是噪音，一批昨日涨停股的竞价分布才是信号。本 SKILL 只做观察与判定，不打板、不给买卖动作。

## 触发与前置

- 触发：用户请求看今天竞价、做竞价评估、复盘昨天涨停股今天的开盘、填竞价表、判断今天能不能打板；交易日 9:25–9:30 为最佳运行窗口，盘中/收盘后运行按"复盘口径"处理并在报告中注明。
- 前置：最近一份 $limit-find 落盘报告 `report/涨停板复盘/YYYY-MM-DD.md`（日期早于今天，取最近一份）；$market-data 可用（竞价数据报告脚本 fetch_auction.py 提供高开幅度、竞价量占比与集体分布）。本 SKILL **不依赖工作区文件**——不读取 MUST.md / NOTES.md / ACCOUNT.md / POSITION.md，可在任意目录直接运行。
- 报告输出：`report/涨停板评估/YYYY-MM-DD.md`（YYYY-MM-DD 为本次竞价的数据日期；目录不存在则创建；同日再次运行覆盖更新并注明运行时间）；竞价清单是本次运行的临时输入，写在 `report/涨停板评估/YYYY-MM-DD-竞价清单.txt`，运行结束必须清理——报告里保留完整样本明细，清理后照样可复核。
- 交接：本 SKILL 只输出观察结论；要买什么、买多少由 $stock-analysis → $position-management 决定，本 SKILL 不调用它们。

## 输入：从 limit-find 报告取四组数据

第一步先定位报告：在 `report/涨停板复盘/` 下取**日期早于今天且最近**的一份 `YYYY-MM-DD.md`。若目录不存在或没有早于今天的报告，直接说明"没有可用的昨日涨停板复盘报告，请先运行 $limit-find"，结束，不猜数据。

从报告中取出四组数据（缺失的项按"未获取"处理，不脑补）：

| 需要的数据 | 报告中的位置 | 用途 |
|---|---|---|
| 昨日涨停全名单（代码 / 名称 / 板数 / 行业 / 昨日全天成交额） | 「涨停全名单（供次日竞价评估）」表 | 集体竞价表与板块竞价表的样本、竞价量占比的分母 |
| 昨日最高板（代码） | 「连板高度与最高板」 | 硬规则检查对象 |
| 涨停家数、炸板率、晋级率 | 「数据概览」「昨日涨停今日表现」 | 接力意愿判定 |
| 昨日报告给出的阵型（高度打开 / 轮动期 / 分歧期 / 崩塌·退潮期）与紧随其后的「结构说明」 | 「阵型判定（最近五次报告汇总）」 | 背景参考：阵型不同，同样的竞价分布含义不同；引用时必须连结构说明一起引，否则只看到“崩塌·退潮期”会误判成全市场都在崩。本 SKILL 不重新判定阵型，旧报告无此节时标“未获取” |
| 昨日主线板块 | 「当日主线板块（板块行合并表）」 | 板块竞价表的板块对照 |

报告缺少「涨停全名单」时（旧版报告）：经 $market-data 用 `fetch_limit_up.py --date <报告日期> --json` 的 `zt_rows` 重建清单，并在报告中注明"由接口重建，建议后续 limit-find 报告携带全名单"。

## 流程

### 第一步：生成竞价清单（临时文件）

把昨日涨停全名单写成 `report/涨停板评估/YYYY-MM-DD-竞价清单.txt`，每行 `代码 昨日全天成交额(亿) 行业`：

```
# 昨日涨停股竞价清单（来源：report/涨停板复盘/<昨日日期>.md）
sz000993 8.46 电力
sz002912 0.44 计算机设
```

- 昨日全天成交额一律取自报告（真实成交额），不要用估算值；
- 昨日最高板若不在名单中（异常情况），补进清单一行，保证硬规则能被检查；
- 清单文件只为给 fetch_auction.py 传样本，属于本次运行的临时文件，不留在报告目录里（第四步清理）。

### 第二步：拉取竞价数据（经 $market-data）

运行 $market-data 的竞价数据报告：

```
python market-data/scripts/fetch_auction.py --file report/涨停板评估/YYYY-MM-DD-竞价清单.txt \
    --top-board <昨日最高板代码> [--json]
```

只向 $market-data 说明需要的数据列（高开幅度、竞价成交额、昨日全天成交额、竞价量占比、集体分布、板块分组、最高板判定），具体参数由 $market-data 按其 SKILL 执行；拉取失败明确报错，不脑补。

口径判定：脚本按行情时间自动标注，报告中必须原样写明本次属于哪一种——

- **竞价口径**：9:25 撮合后、9:30 连续竞价前运行，当日成交额即竞价成交额，竞价量占比有效；
- **盘中/收盘后口径**：超过 9:30 再运行，成交额已混入连续竞价成交额，**竞价量占比失真**，此时只能作为事后复盘，报告要写明"本次非竞价口径，竞价量占比不可用"，不得当作次日盘前依据。

### 第三步：填集体竞价表与板块竞价表

**昨日涨停股集体竞价表（核心表）**

| 项目 | 记什么 |
|---|---|
| 样本家数 | 昨日涨停股中今天取到行情的只数（缺行情的另列） |
| 高开家数 / 平开家数 / 低开家数 | 例如：55 只中 27 高开、5 平开、23 低开 |
| 平均高开幅度（附中位数） | 例如：平均 +2.14%，中位数 0.00% |
| 竞价量占比：平均 + 分档分布 | `<1% / 1%–3% / 3%–8% / 8%–15% / >15%` 各多少只 |
| 昨日最高板今天怎么开 | 高开/平开/低开幅度、是否竞价涨停开、是否天地板或跌停 |
| 一句话结论 | 接力意愿：强 / 一般 / 弱（判定口径见 references/auction-read.md） |

**板块竞价表**

| 项目 | 记什么 |
|---|---|
| 集体高开的板块 | 昨日涨停股在本板块集体高开（板块、家数、平均高开幅度、平均竞价量占比），通常 1–2 个板块有明显一致性 |
| 内部低开分化的板块 | 板块内部分化（部分高开、部分低开）往往是退潮的第一信号 |
| 与报告主线对照 | 昨日主线板块今天是"延续"还是"退潮候选"，依据为板块行数字 |

### 第四步：写报告、清理竞价清单

1. 先读 references/report-template.md，按骨架逐节填充，再写入 `report/涨停板评估/YYYY-MM-DD.md`，然后在回复中给摘要与文件位置；
2. 报告落盘后删除本次的 `report/涨停板评估/YYYY-MM-DD-竞价清单.txt`，并在报告与回复中注明"竞价清单为临时文件，已清理"；
3. 运行中途失败（拉取报错、样本为空、硬规则中断等）时同样要清理清单文件，再说明失败原因；失败时不要留下任何残留文件；
4. 清理后 `report/涨停板评估/` 下每个交易日只保留 `YYYY-MM-DD.md` 报告。

## 两条硬规则（不可违背，写在报告结论里）

1. **竞价量占比一律按「竞价成交额 ÷ 昨日全天成交额」计算**（占比单位 %；经验区间 3%–8% 属活跃，>15% 要警惕竞价出货，<1% 说明市场根本没人关心这只票）。非竞价口径运行时该指标不可用，必须标注，不得用全天成交额冒充竞价成交额。
2. **看到"昨日最高板今天天地板或跌停"，当天不做任何打板动作，只观察。** 命中即写进报告首行与结论区，本 SKILL 的结论只能是"只观察"；不因其他指标好看而豁免。

## 报告格式（固定）

以 references/report-template.md 为骨架，节名、表头、列顺序照抄，不新增或调序；模板里的使用说明与填充示例不写进报告。不可省略的要求：

- 落盘 report/涨停板评估/YYYY-MM-DD.md，结尾必须带“不构成投资建议”；「规则检查」必须置顶（竞价量占比口径是否成立 + 昨日最高板今日是否天地板/跌停 → 当日结论）。
- 竞价明细必须是**全样本**：竞价清单清理后它就是唯一复核来源，逐行列出、不省略，末尾附高开幅度 Top 5 与 Bottom 5。
- 接力意愿给强/一般/弱并附数字；阵型只引用 $limit-find 报告的判定，**引用时阵型标签连那一行结构说明一起引**（崩在哪 + 抬在哪），不重复判定。
- 运行动作记录里注明竞价清单已清理（时间 HH:MM），report/涨停板评估/ 下只保留本报告。

各节的内容规格、表头与填写示例见 references/report-template.md（第四步落盘前读）。

## 硬性规则

- 数据必须真实：$market-data 拉不到就明确报错或标"未获取"，不编造高开幅度、竞价成交额、竞价量占比或板块数据；所有数字标数据日期与行情时间。
- 依赖明确：必须有 $limit-find 的上一份落盘报告作为样本来源；没有报告就说明原因结束，不用接口临时拼凑当日样本。
- 口径优先：9:30 后运行必须在报告与回复中标注"非竞价口径，竞价量占比不可用"。
- 只观察不决策：本 SKILL 不给买卖动作、不给仓位、不预测次日；结论只能是"只观察"或"可列入观察名单"。
- 硬规则不可绕过：最高板天地板/跌停 → 当天只观察；竞价量占比必须用规定的分子分母。
- 阈值可覆盖：接力意愿、炸板率、竞价量占比区间均为默认经验值，用户在请求中说明的个人阈值优先并在报告中注明。
- 报告必落盘：先写 report/涨停板评估/YYYY-MM-DD.md，再回复摘要；回复不替代落盘。
- 不留残留文件：竞价清单（YYYY-MM-DD-竞价清单.txt）是临时输入，运行结束——包括报错结束——必须清理，report/涨停板评估/ 下只保留 YYYY-MM-DD.md 报告；清理前必须已把全样本明细写进报告。
- 格式统一：报告按 references/report-template.md 的固定骨架输出，节名与表头不改写、不调序、不新增小节；模板里的使用说明与填充示例不写进报告。
- 输出可视化：数字一律进表格；竞价量占比分档与高开分布可加等宽条（如 ▉▉▉ 3 只），结论用固定标记（只观察 / 可列入观察名单）；不写散文式数字段，不用表情符号。
- 免责声明：报告结尾必须带"不构成投资建议"。
