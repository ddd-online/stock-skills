# 观察池审视

观察池是冲动与下单之间的缓冲区：标的、触发条件、预案三要素齐全，信号出现才动手。

## 触发与前置条件

- 触发：用户请求审视观察池。
- 前置：工作区已初始化，存在 WATCHLIST.md；观察池为空时输出“观察池为空”，不执行分析。
- 依赖文件：WATCHLIST.md（池内标的与状态）、ACCOUNT.md（账户状态）、POSITION.md（是否已持仓）、NOTES.md 与 MUST.md（个人准则，结论不得冲突）。
- 交接：状态“信号触发”的标的提示用 $position-management 确认仓位；本 SKILL 只审视，不产生买卖动作。

## 流程

1. 读取工作区上下文：WATCHLIST.md、ACCOUNT.md、NOTES.md、POSITION.md、MUST.md。
2. 列出池内全部标的（状态非“移除”的行），逐个自动调用 $stock-analysis 分析（无需用户逐个请求）。
3. 按分析结论更新每只标的状态：
   - 建仓信号：状态改“信号触发，按预案执行”，保留预案，提示 $position-management 做资金调度确认。
   - 观察：保持“等待”，如触发条件/预案有变化则更新；按最新收盘价复核该股条件单参数（触发价/委托限价/撤销条件，规则见 $stock-analysis references/conditional-order.md）；没有触发条件不建仓。
   - 空仓信号：从观察池移除该行，在审视报告中记录原因。
4. 回写 WATCHLIST.md：更新状态、增删行；移除的标的在报告中记录，不在池中保留。
5. 输出审视报告：
   - 每只标的：代码/名称、分析结论摘要、状态变化（等待/触发/移除）、建议动作
   - 池内已触发的标的数量与名单
   - 条件单状态：每只标的条件单（触发/未触发/撤销/已执行）；已触发时按复核清单（量能/换手/资金/形态/低开纪律）给出“可执行/放弃”结论
   - 结尾：“基于截至<日期>的真实数据，不构成投资建议，最终决定由用户作出。”

## 硬性规则

- 逐只分析，不跳过：池内每只标的都必须调用 $stock-analysis。
- 触发条件可以等，不可以编：“感觉要涨”不是信号。
- 只检查不改仓：审视不产生买卖动作；触发后转 $position-management。
- 空仓也是仓位；错过不是损失。
- 遵守 MUST.md 与 NOTES.md 中的个人规则。
