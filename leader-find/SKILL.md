# 龙头股查找（leader-find）

核心前提：

- 「龙头」在 A 股装着两种东西——**行业龙头**靠基本面当选（时间维度以年计），**人气龙头**靠资金当选（几天到几周）；两者风险等级完全不同。
- **最强的那只，常常不是你现在该买的那只**：本 SKILL 只解决「这条线有没有龙头、谁是」与「哪些值得进一步评估」，买不买、在哪买由后面的五关与用户纪律决定。
- **先认阶段，再认龙头**：龙头不是涨得最多的那只，也不是股价最高、名气最大的那只，而是最先动、能带动板块、板块回调时最抗跌的那只。点火期的板块一般没有龙头（全是首板时无法判断谁会成为核心），龙头候选只在扩散期出现，龙头要等加速期才确认。这条口径与 $limit-lifecycle 的「板块龙头认定」完全一致（见 references/leader-find-identification.md 第 2 节）。
- **一次只分析一个板块**：本 SKILL 不做全市场扫描；要找当天活跃板块/主线，先跑 $limit-find（涨停板复盘）或 $limit-lifecycle（题材生命周期）。

## 触发与前置

- 触发：「分析 XX 板块/题材里的龙头」「这个板块的龙头是谁」「某板块把最强和值得买分开」等。
- **板块参数必传（硬要求）**：请求里必须给出一个板块——板块名（如「铜缆高速连接」「液冷」「半导体」）或 BK 代码（如 BK1156）。**没给板块时不运行、不猜板块**，回复一句话请用户给出板块名或 BK 代码；同时命中的板块有多个时列出来让用户选，不自行合并题材。
- 板块定位：板块名先经 $market-data 的 fetch_sector_boards.py --search <关键词> 定位 BK 代码与类型（行业/概念）；定位不到就明确报错，不臆造代码；用户直接给 BK 代码时用它对齐板块行。
- 前置：$market-data 可用（板块行情榜 / 成分股榜 / 板块财务排名 / 涨停池明细 / 个股日K·MA / 新闻公告 / 资金流向）。本 SKILL **不依赖工作区文件**——不读取 ACCOUNT.md / POSITION.md / MUST.md / stocks/，可在任意目录直接运行。
- 落盘：报告写入 report/龙头扫描/YYYY-MM-DD-{{板块名}}.md（同一天分析多个板块就各写一份；report/ 与 report/龙头扫描/ 不存在则创建；同日同板块再次运行覆盖更新并注明运行时间）。
- 默认口径（用户请求说明的个人阈值优先，未说明则用本 SKILL 默认值并写进报告）：人气候选池剔除 ST/风险警示与 N/C 开头新股，当日涨幅 ≥3%，换手 5%–10%（>15% 标“情绪票”），流通市值 50–200 亿；行业龙头取板块内营收/净利第一梯队（前 3）；深查短名单每板块 ≤5 只。
- 交接：报告只给名单与观察预案，不下单；要继续判断「值不值得买」→ 每只转 $stock-analysis（出建仓/空仓信号与买点/止损/止盈），资金仓位走 $position-management。「观察」只是 $stock-analysis 报告里的等待中间态，触发条件与预案写在报告里、不落盘，由用户自行盯。

## 两种龙头速查

| | 行业龙头（真龙头） | 人气龙头（板块最强） |
|---|---|---|
| 当选依据 | 营收、净利润、市占率行业第一梯队 | 板块启动后最先动、最能带动板块、回调最抗跌 |
| 时间维度 | 以年计 | 几天到几周 |
| 主要风险 | 便宜时没人理、可能长期不涨 | 高位巨量就是派发，接棒亏损巨大 |
| 识别框架 | 定义行业 → 规模排名 → 质地 → 估值 → 主营验证 | 阶段 → 有无龙头（五字段纵向排序）→ 四查两两对比 → 上车点 |
| 本 SKILL 的处理 | 只识别与列名单；“值得买”需再过五关 | 只给“板块相对最强”候选与淘汰理由；“值得买”需再过五关 |

## 流程

### 第一步：确认板块参数与口径

1. **校验板块参数**：请求里没有板块名/BK 代码 → 停止并索取，不进入后续步骤；有板块名 → 记下关键词；有 BK 代码 → 记下代码。
2. 板块名经 $market-data 的 fetch_sector_boards.py --search <关键词> 定位 BK 代码与类型；命中多个要把候选（板块名 + BK 代码 + 类型 + 今日涨幅）列出来让用户选一个。
3. 不读取工作区文件：个人口径只取用户请求中的说明（市值/换手/涨幅门槛等），未说明则用默认口径并写进报告。
4. 确认数据时间（收盘后或盘中均可），报告注明口径与数据日期。

### 第二步：取板块数据（全部经 $market-data）

本 SKILL 需要以下数据列，具体脚本与参数由 $market-data 按其 SKILL 执行；拉取失败明确报错或标“未获取”，不脑补：

- 板块行：fetch_sector_boards.py（--search 定位板块，或用 --type 行业/概念榜找到该板块）→ BK 代码、板块名、类型、今日/5日/10日涨幅、上涨/下跌家数、领涨股、成交额、换手、主力净流入。
- 成分股榜：fetch_sector_leaders.py --board BKxxxx --top 300 → 板块成分股全量（脚本按 100 只一页分页拉齐，默认 30 只不够用，会漏计板块内涨停家数与连板股），字段含现价、今日/5日/10日涨幅、换手、量比、成交额、振幅、PE、流通/总市值、主力净流入、行业；东财行情中心接口不可用时该脚本自动切备用源（成分股名单取东财 F10「所属板块」，按 BK 代码匹配，名单可能少于行情中心全量），报告要写明数据源与口径。
- 板块财务排名：fetch_sector_fundamentals.py --board BKxxxx --top 12 → 板块内按营收榜/净利榜的第一梯队与最新报告期财务数字（行业龙头候选）；东财板块接口不可用时该脚本自动切备用源（名单取东财 F10「所属板块」、行情取腾讯），报告要写数据源与口径（F10 名单可能少于行情中心全量，题材内排名结论须注明）。
- 涨停池明细：fetch_limit_up.py --json → zt_rows（板数、首封/末封时间、换手、封板资金、炸板次数、成交额）、zb_all_rows（收盘未封住）、dt_rows（跌停）；用于阶段判定与龙头认定的五字段。
- 短名单个股：fetch_quote（日K与 MA）、fetch_capital_flow（主力净流入）、fetch_news（新闻/公告）。

**板块归属只按代码求交，不按名称匹配**：涨停池的行业名是接口给的 4 字截断名（如「汽车零部」「互联网电」），与板块名不能直接比对；做法是用该板块 BK 代码取成分股代码集合，再与 zt_rows / zb_all_rows / dt_rows 按**代码**求交。

### 第三步：判这条线的阶段（与 $limit-lifecycle 同口径，当日版）

判阶段只看三个维度：**涨停结构 / 龙头状态 / 资金与量能**，判定顺序**固定**：收缩 → 加速 → 扩散 → 点火，标签只有四个。

| 阶段 | 涨停结构 | 龙头状态 | 资金与量能 |
|---|---|---|---|
| 点火 | 1–3 家涨停、多是首板；更多家数但全是首板也按点火记 | 没有 2 板及以上（没有连板核心） | 小幅净流入，量能温和放大 |
| 扩散 | 涨停家数较昨日明显增加（默认 +≥2 家或 ≥50%） | **出现 2–3 板晋级股（决定性）** | 净流入为正，板块内涨停股换手 5%–15% |
| 加速 | 板块内多股连板、涨停家数占全场比重高（默认 ≥15%） | 龙头 ≥4 板，或 ≥2 只三板及以上 | 净流入最大，板块内涨停股平均换手 ≥20% |
| 收缩 | 涨停家数快速减少或归零、开始出现跌停 | 龙头断板、炸板或跌停 | 资金转为净流出 |

- 完整判定顺序、冲突处理与三检查点见 references/leader-find-identification.md 第 2 节与 $limit-lifecycle 速查表。
- **本 SKILL 是当日单日口径**：不读历史报告，所以不给「本轮第 N 天」，也不做资金「今日 vs 基准日」的方向对比；需要本轮第几天、主线健康度三检查点与推荐板块，转 $limit-lifecycle。

### 第四步：板块龙头认定（五字段纵向排序）

1. **先按阶段看有没有龙头**（不许跳过阶段直接点名字）：
   - 点火（全是首板）：**一般没有龙头**——8 家首板也照样写「无龙头（全是首板）」，最多标「先动股：{{名称}}（首封 {{时间}}）」，不写「龙头候选」；
   - 扩散（出现 2–3 板晋级股）：这些晋级股就是**龙头候选**，全部点名（名称 + 板数），排序第一名写「龙头候选（首选）」；
   - 加速（龙头 ≥4 板，或板块内 ≥2 只三板及以上）：写「**龙头（已确认）：{{名称}} {{N}} 板**」并给带动性数字（首封时间 + 板块跟涨：板块涨幅为正、涨停家数占全场 ≥15%、平均换手 ≥20%）；
   - 收缩（龙头断板/炸板/跌停）：按第 4 条的四种走法判定并写动作。
2. **五字段纵向排序**（同板块内，顺序固定）：① 首封时间（09:25 集合竞价封板、开盘秒板最强；11:00 后转弱，14:00 后＝尾盘偷袭板）② 连板高度（板块内最高板且与跟风股拉开档次）③ 换手与量能（5%–15% 健康，连板 ≥25% 属高位高换手板）④ 资金（板块主力净流入为正 + 个股有大单进场；板块净流出而它独涨＝独涨板）⑤ 炸板后的回封速度（首封/末封时间、炸板次数，收盘未封住在 zb_all_rows）。五个字段是**排序**用的，不是打分表；字段 1 与 2 冲突（先动的不是最高板）时两只都留在候选里，冲突写进理由。
3. **四种伪龙头降级**（识别到就写「伪龙头（{{类型}}）」，不占龙头/龙头候选位）：跟风板（首封排在龙头之后）、尾盘偷袭板（14:00 后首封）、高位高换手板（连板换手 ≥25%）、独涨板（板块上涨家数 < 下跌家数或资金净流出）。伪龙头不等于会跌，而是没有带动性，不能用板块主线的逻辑操作。
4. **龙头断板后的四种走法**（昨日最高板今日不在涨停池时必写）：换龙头（板块内冒出新的连板核心、家数没继续塌、资金仍流入 → 按新票重做阶段评估）；龙头独活（龙头还封着但板块家数腰斩、资金转负 → 按退潮处理，看板块家数与资金，不看龙头的脸色）；板块退潮（龙头断板 + 跟风股集体下跌 + 资金净流出 → 移出跟踪）；反包（断板次日重新涨停收复 → 只观察、不参与）。
5. 认定结果写进报告的「板块龙头认定」一节（有无龙头 + 五字段排序表 + 伪龙头降级 + 断板走法），并作为第五步四查与结论的输入。

### 第五步：人气龙头四查打分（两两对比，候选 ≤5 只）

候选 = 第四步的龙头/龙头候选，加上板块内当日涨幅居前的成分股；先过默认口径快筛，不足 5 只时放宽到当日涨幅前 5 只并逐只标注为何破例；超过则按涨幅排序取前 5。

对每只候选按 references/leader-find-identification.md 的四查表打分，每项给“过/不过/待核 + 数字”：

| # | 检查项 | 合格标准（数据依据） |
|---|---|---|
| 1 | 相对强度 | 板块启动期先涨、涨得多：5日/10日涨幅高于板块自身与同板块多数候选；回调期跌得少、先收复（用日K确认） |
| 2 | 硬逻辑占主营 | 题材收入写在最新财报主营构成里；公告/新闻澄清“无收入/不相关”→ **一票否决** |
| 3 | 量能健康 | 上涨有量、回调缩量；换手 5%–10% 人气足但未过热；高位巨量、换手 >30% = 派发嫌疑（一票否决） |
| 4 | 给上车点 | 有回踩企稳收阳/放量突破回踩不破的候选点；连板/涨停不给点 = “等回踩”，不算给点 |

两两对比只在本板块内进行，结论写“谁相对最强、为什么、淘汰理由是什么”——**淘汰理由比选中理由更重要**，每只被淘汰的都写一行。

### 第六步：行业龙头（基本面第一梯队）核验

1. 规模排名：按 fetch_sector_fundamentals 的营收榜/净利榜取第一梯队（前 3）；概念/题材板块的财务榜只能说明“板块内财务第一梯队”，要标「题材内财务排名，行业地位待验证」，不能直接叫行业龙头。
2. 质地：毛利率高于同行、ROE 高且多年稳定、负债率合理、经营现金流为正（fetch_sector_fundamentals / fetch_fundamentals 多报告期核对，缺失标“待核”）。
3. 估值：PE/PB 与同行、与自身历史比（fetch_quote），溢价离谱标“好公司坏价格”。
4. 主营验证：最新财报主营构成/公告/新闻里题材收入占比要真实；占比为 0 或被澄清 → 伪龙头，一票否决，不进名单。

第 2–4 步只对营收/净利前 3–5 只执行，控制深查数量。

### 第七步：短名单深查（每板块 ≤5 只）

对第四、五步的相对最强候选（≤2 只）与行业龙头前 3 只，经 $market-data 拉：日K 15–30 根（含 MA，确认回调缩量/收复与均线位置）、新闻公告（近 3–5 条，做逻辑证伪与主营验证）、资金流向（主力净流入是否与涨势同向）。数据缺项标注“未获取”，不脑补；本步只补证据，不替代 $stock-analysis 的建仓/空仓判断。

### 第八步：汇总结论并落盘

1. 读 references/report-template.md，按骨架逐节填充：节名、表头、列顺序照抄，`{{...}}` 全部替换为真实数字或“未获取”；当天没有内容的小节保留标题并写“无”或“不适用”；模板自带的使用说明与填充示例不写进报告。
2. 正文先写入 report/龙头扫描/YYYY-MM-DD-{{板块名}}.md，再在回复中给结论与文件位置。

结论区把两类分开：

- “最强”名单：行业龙头第一梯队 + 人气龙头（本板块相对最强）——只说明它们强在哪个数字上；
- “值得买”候选：需要**再过五关**（体检 → 买点 → 仓位 → 止损 → 复盘）才谈得上买；本 SKILL 只输出“值得进一步评估”的名单与下一步（转 $stock-analysis），不给买卖动作。五关映射见 references/leader-find-identification.md 第 6 节。

## 报告格式（固定）

以 references/report-template.md 为骨架，节名、表头、列顺序照抄，不新增或调序；模板里的使用说明与填充示例不写进报告。不可省略的要求：

- 落盘 report/龙头扫描/YYYY-MM-DD-{{板块名}}.md（文件名含板块名，同日同板块重跑覆盖更新并注明运行时间），结尾必须带“不构成投资建议”。
- 报告开头「板块定位与口径」必须写明板块名、BK 代码、类型、定位方式（--search 检索或用户给定）与数据时间；**没有板块参数就不生成报告**。
- 「板块行情与阶段」节写板块行数字（今日/5日/10日涨幅、上涨:下跌、成交额、主力净流入）+ 三维理由 + 阶段标签，并注明本轮第 N 天与三检查点体检转 $limit-lifecycle。
- 「板块龙头认定」节不可省：有无龙头判定 + 五字段排序表 + 伪龙头降级 + 断板后走法（无断板写“无”）。
- 结论区**把「最强」与「值得买」分开列**：最强只说明强在哪个数字上；值得买只给“值得进一步评估”的候选与下一步（转 $stock-analysis），不给买卖动作、买点止损与仓位。
- 淘汰理由与被淘汰的候选都要留痕（每只一行），不写“看起来弱”这类无数值判断。

各节的内容规格、表头与填写示例见 references/report-template.md（第八步落盘前读）。

## 硬性规则

- **板块参数必传**：没有板块名/BK 代码时不运行、不猜板块、不做全市场扫描，直接请用户给出板块；板块名定位不到 BK 代码时报错并列出相近候选，不臆造代码。
- 数据必须真实：$market-data 拉不到就明确报错或标“未获取”，禁止编造涨幅、家数、板数、首封时间、换手、营收、净利、新闻或资金数据；每条引用标数据日期。
- 龙头认定跟着阶段走：点火档（全是首板）写「无龙头」，不硬点一只当龙头，最多标「先动股」；龙头候选只在扩散档出现（2–3 板晋级股，逐个点名）；龙头要等加速档才写「已确认」并给带动性数字；收缩档必写断板后四种走法之一。不预测次日谁会成为龙头。
- 板块内纵向比较用五字段固定顺序：① 首封时间 → ② 连板高度 → ③ 换手与量能 → ④ 资金 → ⑤ 炸板后的回封速度（数字取 zt_rows / zb_all_rows 与板块行）；跟风板、尾盘偷袭板（14:00 后首封）、高位高换手板（连板换手 ≥25%）、独涨板只能写「伪龙头（类型）」，不占龙头位。
- 只判当日单日口径：本 SKILL 不读历史报告，不给「本轮第 N 天」、不做资金两时点方向对比；需要这些转 $limit-lifecycle。
- 行业定义用东财行业分类，不凭题材自拼“行业”；概念板块的财务榜不得直接写成“行业龙头”。
- 一票否决不妥协：ST/退市风险、澄清“无收入/不相关”、高位巨量换手 >30% 派发嫌疑等，任何一条命中即不进名单，淘汰理由写入报告。
- 最强 ≠ 值得买：报告始终把“强”与“买”分开；本 SKILL 不出买卖信号、不写买点止损、不给仓位建议；深查与买卖判断一律转 $stock-analysis → $position-management。
- 只识别不追高：当日涨停的领涨股列“涨停候选/等回踩”，默认不视作有上车点。
- 报告必落盘：先写 report/龙头扫描/YYYY-MM-DD-{{板块名}}.md，再回复摘要；回复不替代落盘。
- 口径优先：本 SKILL 不读取工作区文件；用户请求中明确说明的个人阈值优先于默认值并在报告中注明。
- 格式统一：报告按 references/report-template.md 的固定骨架输出，节名与表头不改写、不调序、不新增小节；模板里的使用说明与填充示例不写进报告。
- 输出可视化：数字一律进表格；五字段排序与四查打分用「过/不过/待核 + 数字」短标记而不是整段描述，归属用箭头链（如「半导体 → 中晶科技（龙头候选·首选）」）；状态用固定标记（龙头（已确认）/ 龙头候选（首选）/ 龙头候选 / 先动股 / 无龙头 / 伪龙头（类型）、主线候选/涨停候选·等回踩、值得进一步评估）；不写散文式数字段，不用表情符号。
- 免责声明：报告结尾必须带“不构成投资建议”。
