# 涨停板查找（find-limit）

涨停数据是市场情绪与短线主线的“体温计”。本 SKILL 负责把当日涨停板数据查找齐全，并按四个问题组织报告：今天涨停/跌停多少家？最高板几板、是谁、是否一字？昨日涨停今天还有多少在涨、有没有炸板潮？当日主线板块是什么？最后把当日与之前四次报告并排看，定出情绪处在阵型四态中的哪一态。所有数字必须来自真实行情，判定阈值一律可复核、可被用户请求中说明的个人阈值覆盖。

## 触发与前置

- 触发：用户请求查找涨停板数据——涨停/跌停家数、连板高度、最高板、晋级率、炸板潮、当日主线板块、当前情绪处在哪一态（含“涨停复盘”式提法）；收盘后运行得到当日定稿口径，盘中运行得到实时口径（报告中注明）。
- 前置：$market-data 可用（fetch_limit_up.py 提供涨停/跌停/炸板池与晋级数据，fetch_sector_boards.py 提供板块行情榜）。本 SKILL **不依赖工作区文件**——不读取 MUST.md / NOTES.md / ACCOUNT.md 等，可在任意目录直接运行；报告写入运行目录下的 report/涨停板复盘/YYYY-MM-DD.md。
- 数据日期：fetch_limit_up.py 缺省自动取最近有数据的交易日；用户指定日期但该日无独立数据时，回退到接口最新数据日并在报告中注明，不把回退日期冒充请求日期。
- 落盘：报告写入 report/涨停板复盘/YYYY-MM-DD.md（YYYY-MM-DD 为数据日期；report/ 与 report/涨停板复盘/ 不存在则创建；同日再次运行覆盖更新并注明运行时间），格式照 references/report-template.md 的固定骨架；阵型判定是同一份报告的最后（「阵型判定」）一节，样本取自本目录下最近的五份报告。
- 交接：本 SKILL 只查找数据并做情绪与主线的判定，不产生买卖动作；如需对主线板块内的个股做买卖判断，转 $stock-analysis / $position-management。

## 流程

### 第一步：确认日期与口径

1. 确认“今天”的数据日期：先直接运行 $market-data 的涨停板数据报告（不指定 --date，自动解析），从输出头部读数据日期；需要指定历史日期时用 --date YYYYMMDD。
2. 不读取工作区文件：个人阈值（涨停热度区间、炸板潮判定、主线确认口径）只取用户请求中的说明，未说明则用本 SKILL 默认值并写进报告。
3. 读取 report/涨停板复盘/ 下**日期早于本次数据日期**的最近四份 `YYYY-MM-DD.md`：其「主线板块」「情绪判定」用于环比，其四个数字（最高板、晋级率、炸板率、跌停家数）用于第四步的阵型汇总。不足四份或目录不存在时不阻塞本次运行，按实际份数进入第四步并注明样本天数。

### 第二步：拉取数据（全部经 $market-data）

- 涨停板全景：fetch_limit_up.py（默认最新数据日；输出今日/昨日涨停、跌停、炸板家数与封板率，连板梯队与最高板（含一字核对），昨日涨停今日晋级与涨跌分布，涨停股行业分布、跌停股行业分布）。**另用 `--json` 取 `zt_rows`（当日涨停池全量明细，含首板）**，用于报告中的「涨停全名单」——次日 $judge-limit 的竞价评估直接以它为样本；**跌停结构**（`--json` 的 `dt_rows` 全量跌停明细 + `dt_industry_dist` 跌停行业分布）用于阵型的「结构说明」——崩在哪由它给数字。
- 板块行情榜：fetch_sector_boards.py --type industry --sort change --top 10 与 --type concept --sort change --top 10；另拉 --sort gain5 --top 10 复核持续性（近5日）。
- 只向 $market-data 说明需要以上数据列，具体参数由 $market-data 按其 SKILL 执行；拉取失败明确报错，不脑补。

### 第三步：按四问解读

**① 今日涨停/跌停家数**

- 数字直接来自报告概览：今日涨停 X（昨 Y）、跌停 A（昨 B）、炸板 C（昨 D）、封板率 P%（昨 Q%）。
- 情绪温度标注（默认经验阈值，用户说明优先）：涨停 ≥80 家 → 偏热；40–79 → 常态；<40 → 偏冷。涨停减少且封板率下降 → 标注“热度回落”，不预测次日。
- 口径备注：东财涨停池不含 ST 与科创板，比较家数时只用同口径。

**② 连板高度与最高板**

- 最高板数（昨日最高几板，高度是升是降）、最高板名单、逐一标注是否一字（以行情开=高=低=收核对，报告“一字：是/否”）。
- 列高标梯队（≥3 板）表：板数/代码/名称/涨停统计/首封-末封/换手/封板资金/行业/一字。
- 高度回落、晋级率下降、炸板率上升三者同时出现时，标“情绪退潮迹象（数据判定）”，仅陈述三项数字，不下单建议。

**③ 昨日涨停今日表现与炸板潮**

- 晋级：昨日涨停 X 只，今日继续涨停 Y 只，晋级率 Y/X%；上涨（含涨停）U 只、下跌 D 只、平均涨幅 A%。
- 炸板潮判定（默认经验阈值，用户说明优先）：
  - 炸板率（炸板/(涨停+炸板)）≥35%，或
  - 炸板家数 ≥15 且较昨日明显增多（如 +50% 以上）
  → 标“有炸板潮/退潮迹象”；否则标“无明显炸板潮”。
- 结论只写数字与判定，不写“明天会怎样”。

**④ 当日主线板块（与板块行合并写）**

- 输入两个口径：涨停股行业分布 Top 10（来自涨停板报告）+ 板块行情榜（行业/概念：今日/5日/10日涨幅、领涨股、涨跌家数、主力净流入）。
- 合并成“板块行”表格（见报告格式第 5 节）：每个候选板块一行，同时给出“涨停集中度 × 板块涨幅 × 资金流入”三个口径的数字。
- 主线确认规则：涨停家数集中的行业/概念（≥3 家或占比前 3）∩ 板块当日与近5日涨幅为正 ∩ 主力净流入为正（或至少不明显流出），取交集按涨停家数排序取 ≤3 个为当日主线；交集不足时只写“板块榜靠前但涨停未集中”，不硬凑主线。
- 与昨日报告的主线对照：昨日主线今日仍在榜单 → 写“延续”；今日跌出榜单或炸板集中 → 写“退潮候选”，依据为当日榜行数据。

### 第四步：阵型汇总（当日 + 之前四次报告，共五次）

单日数字说明不了情绪走到哪一步，把最近五次报告并排看才知道。判定口径见 references/find-limit-cheatsheet.md。

1. 取样本：本次数据日期为第一份，加上 report/涨停板复盘/ 下日期早于本次数据日期的最近四份 `YYYY-MM-DD.md`，共五份；不足四份时按实际份数（含当日）。
2. 逐份取四个数字——最高板数、晋级率、炸板率、跌停家数（来自各报告的「数据概览」「连板高度与最高板」「昨日涨停今日表现」）；旧报告缺项写“未获取”，不脑补。
3. 填五次报告汇总表，末列给每份报告一个单日态标签，便于看走势是连贯还是反复横跳：

   | 数据日期 | 涨停家数 | 跌停家数 | 炸板率 | 最高板 | 晋级率 | 单日态 |

4. 定当日阵型，顺序固定三步：**先看最高板有没有抬升 → 再看晋级率有没有回到 30% 以上 → 最后看炸板率**；第一步没做到，后两步好看也只算轮动期。炸板率 ≥35% 或跌停家数两位数偏“分歧期”；“崩塌·退潮期”要**同时**满足两个条件——跌停家数 ≥ 20 家，**且** 跌停家数 ≥ 涨停家数的三分之一（只有比例达标、跌停家数不到 20 家的日子按“分歧期”走：涨停家数少的时候比例容易被小样本顶上去，6 家跌停撑不起“崩塌”）；最高板天地板或连续跌停同样落“崩塌·退潮期”。
5. 阵型标签后面**必须紧跟一行「结构说明」**，写清崩在哪、抬在哪：
   - 崩在哪：跌停集中在哪些行业/题材（取跌停股行业分布的家数，点出代表性个股）；
   - 抬在哪：今天仍在创新高的方向（高标梯队与最高板所在行业、连板数）；
   - 收一句定型（如“老题材崩塌 + 局部高度抬升”）。

   只写“崩塌·退潮期”会让读的人（包括明天的自己）以为全市场都在崩，而当天可能还有票在创连板新高——两个信息缺一个，判断都会走偏。
6. 结论写进报告的「阵型判定」一节：阵型 + 结构说明 + 三步判断依据（每步跟一个数字）+ 该阵型已持续几个交易日（按汇总表数连续天数）。
7. 只判定当前位置，不推演下一日阵型；样本不足五份时写明“样本 N 份，不足五次”；跌停明细只返回 Top N 时按接口实际条数写并注明口径。

### 第五步：生成报告并落盘

1. 读 references/report-template.md，按模板骨架逐节填充：节名、表头、列顺序照抄，`{{...}}` 全部替换为真实数字或“未获取”；当天没有内容的行删掉，涨停全名单（含首板）不省略；模板自带的使用说明与填充示例不写进报告。
2. 正文先写入 report/涨停板复盘/YYYY-MM-DD.md（目录不存在则创建；同日再次运行覆盖更新并注明运行时间），再在回复中给摘要与文件位置。

## 报告格式（固定）

生成时以 references/report-template.md 为骨架（节名、表头、列顺序照抄，不新增或调序小节），下方为规格说明：

1. 标题：涨停板复盘 · YYYY-MM-DD（数据日期；运行时间 HH:MM；盘中/收盘口径）
2. 数据概览表：今日/昨日——涨停家数、跌停家数、炸板家数、封板率（口径：东财涨停池不含 ST 与科创板）
3. 连板高度与最高板：最高 N 板（昨日最高 M 板）+ 名单 + 一字标记；高标梯队表（≥3 板）
4. 昨日涨停今日表现：晋级家数/晋级率、上涨/下跌/平均涨幅；炸板潮判定（数字 + 有/无明显炸板潮）
5. 当日主线板块（板块行合并表）：

   | 板块（代码） | 类型 | 今日% | 5日% | 10日% | 领涨股 | 主力净流入(亿) | 涨停家数 | 判定 |

   末列判定：主线候选（涨停集中∩涨幅∩资金）/ 仅榜前（涨停不集中）/ 退潮候选（跌出榜或炸板集中）
6. 涨停全名单（供次日竞价评估）：当日**全部**涨停股逐行列出——代码、名称、板数、行业、成交额(亿)、首封时间、备注（一字/涨停统计）；数据取 fetch_limit_up.py --json 的 zt_rows，含首板、不省略（这份名单是次日 $judge-limit 竞价评估的样本与「竞价成交额 ÷ 昨日全天成交额」的分母来源）
7. 情绪判定小结：热度（偏热/常态/偏冷）、高度（升/降）、晋级（升/降）、炸板潮（有/无），每条后跟一个数字
8. 与昨日对比（有昨日报告或接口给出昨日数时）：涨停家数、最高板、晋级率、炸板率四项环比
9. 阵型判定（最近五次报告汇总）：五次报告汇总表（数据日期 / 涨停家数 / 跌停家数 / 炸板率 / 最高板 / 晋级率 / 单日态）+ 阵型结论（高度打开 / 轮动期 / 分歧期 / 崩塌·退潮期）+ **结构说明（崩在哪：跌停集中的行业与家数、代表个股；抬在哪：创连板新高的方向与最高板）** + 三步判断依据（最高板是否抬升、晋级率是否回到 30% 以上、炸板率）+ 该阵型已持续几个交易日；样本不足五次时注明实际份数
10. 结尾：“以上基于截至<数据日期>的真实数据，不构成投资建议，最终决定由用户作出。”

## 硬性规则

- 数据必须真实：$market-data 拉不到就明确报错或标“未获取”，不编造涨停/跌停/炸板家数、板数、一字、晋级率或板块数据；数字一律标数据日期。
- 同口径比较：东财涨停池不含 ST 与科创板；家数环比只用同一天同一口径。
- 默认阈值可覆盖：热度区间、炸板潮判定、主线确认均为默认经验阈值；本 SKILL 不读取工作区文件，用户请求中说明的个人阈值优先并在报告中注明。
- 只判定不预测：情绪退潮、主线延续等判定只基于当日与昨日的真实数字，不写“明天会涨停/会退潮”式预测。
- 一字判定要核验：不用“9:25 封板”代替行情核对；以开=高=低=收给出“一字：是/否”，无行情时标“-”。
- 主线不硬凑：数据交集不足就写“无明确主线”，不允许为了凑三条而把榜前但涨停不集中的板块写成主线。
- 阵型靠历史报告：阵型四态只能由 report/涨停板复盘/ 下已落盘的报告汇总得出（当日 + 之前四次，共五次）；报告不足五份时按实际份数写并注明样本天数，不用接口数据临时补造历史数字，也不推演下一日的阵型。
- 阵型必带结构说明：阵型标签后面必须跟一行结构说明（崩在哪 + 抬在哪），只给标签不给结构视为不合格；跌停明细只有 Top N 时按接口返回条数写并注明口径。
- 报告必落盘：先写 report/涨停板复盘/YYYY-MM-DD.md，再回复摘要；回复不替代落盘。
- 格式统一：报告按 references/report-template.md 的固定骨架输出，节名与表头不改写、不调序、不新增小节——次日 $judge-limit 按固定节名取数；模板里的使用说明与填充示例不写进报告。
- 免责声明：报告结尾必须带“不构成投资建议”。
