# 连板天梯（limit-ladder）

一张图回答三件事：

1. 今天的高度在哪里：按连板数从高到低排列；
2. 每只票是几连板、几天几板：层级看连板数，`N天M板`只做标注；
3. 昨天的高度有没有断：昨日涨停、今日未封的股票，在昨日高度用虚线卡片标“断板”，并写今日收盘价。

最终产物是一页自包含 HTML，使用 `assets/ladder-template.html` 的固定样式；以后每天只换数据，不另写一套视觉风格。

## 触发与前置

- 触发：用户请求“连板天梯”“涨停梯队”“最高几板”“断板记录”，或需要把某日涨停股做成 HTML。
- 最佳运行时间：收盘后（15:00 之后）生成定稿天梯。盘中运行可以生成临时天梯，但断板只是当前状态，HTML 必须标“盘中临时，未定稿”。
- 数据依赖：$market-data 的 `fetch_limit_up.py --json` 与 `fetch_quote.py`；上一份 `$limit-find` 的 `report/涨停板复盘/<prev_date>.md`（读取「涨停全名单（供次日竞价评估）」表）。
- 不依赖 ACCOUNT.md / POSITION.md / MUST.md / stocks/，可在任意目录运行。
- 输出：`report/连板天梯/YYYY-MM-DD.html`，日期为数据日期；同日重跑覆盖更新并注明生成时间。

## 数据口径

### 今日涨停

`fetch_limit_up.py --json` 取：

- `base_date`、`prev_date`：今天与上一交易日；
- `zt_rows`：今日全部涨停股，含首板；
- `board_count`：连板数，天梯层级用它；
- `zt_stat`：几天几板，例如 `3天2板`，只作为标注；
- `first_seal`：今日首次封板时间；
- `industry`、`price`：行业与涨停价；
- `zb_all_rows`：今日炸板池，用来给断板加“炸板断板”标签。

今日每只股票再用 `fetch_quote.py <代码> --days 5 --json` 取：

- `quote.open`：今日开盘价；
- `quote.price`：收盘后是收盘价，盘中是现价；
- `quote.datetime`：行情时间；
- `quote.limit_up`：涨停价，用于核对是否仍封板。

### 昨日文章与断板

在 `report/涨停板复盘/` 下找日期早于 `base_date` 的最近一份报告；优先取 `<prev_date>.md`，没有则取日期最近的一份。

从报告「涨停全名单（供次日竞价评估）」表读取：代码、名称、板数、行业、首封时间、备注。报告缺失时，才允许用 `fetch_limit_up.py --date <prev_date> --json` 重建昨日名单，并在 HTML 标注“由接口重建，未读取昨日文章”。

断板定义：

- 昨日涨停代码集合减去今日 `zt_rows` 代码集合；
- 今日不在涨停池、但在 `zb_all_rows` → 标“炸板断板”；
- 今日不在涨停池、也不在炸板池 → 标“未封断板”；
- 按**昨日连板数**放回对应天梯层级，卡片用虚线样式；
- 断板卡片写昨日封板时间、今日开盘价、今日收盘价（盘中写现价并标临时）。

如果某只昨日涨停股今日没有行情，保留卡片，开盘/收盘写“未获取”，不猜价格。

## 流程

### 第一步：取今日涨停池与昨日日期

1. 运行 `python market-data/scripts/fetch_limit_up.py --json`。
2. 核对 `data_available`；没有数据时明确报错，不生成空天梯。
3. 记下 `base_date`（数据日期）与 `prev_date`（上一交易日）。
4. 如果当前时间在 15:00 前，标记本次为“盘中临时，未定稿”；断板卡片一律写“临时断板”。

### 第二步：读取昨日文章

1. 定位 `report/涨停板复盘/<prev_date>.md`；没有时取日期早于 `base_date` 的最近一份。
2. 解析「涨停全名单（供次日竞价评估）」Markdown 表；表头固定为：
   `代码 | 名称 | 板数 | 行业 | 成交额(亿) | 首封时间 | 备注`
3. 保存昨日每只股票的代码、名称、板数、行业、首封时间、备注（备注里的 `N天M板` 用于断板标注）。
4. 报告不存在或表格缺失时，按上方规则用接口重建并标注来源。

### 第三步：补齐开盘价与断板收盘价

需要行情的代码 = 今日 `zt_rows` 代码 ∪ 昨日涨停但今日未涨停的代码。

逐只运行：

```
python market-data/scripts/fetch_quote.py <代码> --days 5 --json
```

同一代码只取一次，结果按代码缓存。取不到的字段写“未获取”，不填 0、不用昨日价格冒充。

### 第四步：分组与判定

1. 今日涨停股按 `board_count` 分组；`1` 板也保留。层级从最高板到 1 板排列。
2. 今日每张卡片显示：
   - 名称、代码、行业；
   - `N连板`（层级）；
   - `N天M板`（`zt_stat`，没有则 `-`）；
   - 今日首封时间；
   - 今日开盘价；
   - 若 `board_count` 与 `zt_stat` 不一致，例如 2连板但“4天3板”，两个标签都保留，说明“层级按连板数，几天几板仅标注”。
3. 断板股按昨日 `board_count` 放回对应层级，卡片显示：
   - “断板”印章；
   - 昨日 `N连板` + 昨日 `N天M板`；
   - 昨日首封时间；
   - 今日开盘价；
   - 今日收盘价（盘中为现价，标“临时”）；
   - 炸板/未封标签。
4. 同一层级没有今日涨停但有断板时，仍保留该层级；没有今日也没有断板的层级不显示。
5. 头部汇总：今日涨停家数、最高板、连板家数（`board_count>=2`）、断板家数、数据时间、是否定稿。

### 第五步：套用固定 HTML 模板

1. 复制 `assets/ladder-template.html`，只替换占位符，不改 CSS、卡片结构、颜色变量与字体层级。
2. 填入：
   - `{{TITLE}}`：`连板天梯 · YYYY-MM-DD`
   - `{{DATA_DATE}}`：数据日期
   - `{{GENERATED_AT}}`：生成时间
   - `{{DATA_WINDOW}}`：收盘定稿 / 盘中临时
   - `{{SUMMARY_HTML}}`：汇总卡片
   - `{{LADDER_HTML}}`：层级与股票卡片
   - `{{SOURCE_NOTE}}`：数据源、昨日文章路径、重跑覆盖说明
   - `{{DISCLAIMER}}`：不构成投资建议
3. 卡片必须使用模板中的 `.stock-card`、`.is-broken`、`.tag`、`.meta` 结构；不要临时加内联颜色或另一套卡片样式。
4. 写 `report/连板天梯/YYYY-MM-DD.html`；先落盘，再回复摘要与文件位置。

## HTML 输出要求

- 单文件、内嵌 CSS，不依赖 CDN、字体文件或外部图片；离线可打开。
- 今日封板卡片用红色左侧强调；断板卡片用灰色虚线边框，标题带“断板”印章。
- 天梯从最高板向下排列；每层左侧固定显示 `N板`，右侧横向排列卡片。
- 数字进小卡片或标签，不写大段散文；不使用表情符号。
- 顶部必须显示“收盘定稿”或“盘中临时，未定稿”；数据时间与数据日期分开写。
- 底部写数据来源、昨日报告路径、生成时间与“不构成投资建议”。

## 硬性规则

- **层级以连板数为准**：`board_count` 决定天梯层级；`zt_stat` 的 `N天M板`只做标注，不能拿 `M` 当层级。
- **断板按昨日高度记录**：昨日涨停、今日不在 `zt_rows` 的股票，放回昨日 `board_count` 层级，不能从今日层级里消失。
- **每只股票都要有封板时间与开盘价**：今日涨停用今日首封时间；断板用昨日首封时间；开盘价取今日 `quote.open`。取不到写“未获取”。
- **断板必须写收盘价**：收盘后取 `quote.price` 作为收盘价；盘中只能写“现价（临时）”，不得冒充收盘价。
- **昨日文章优先**：能从 `report/涨停板复盘/` 读到名单就读；只有缺失时才用接口重建，并在 HTML 明示。
- **数据真实**：不编价格、封板时间、板数、几天几板、断板或收盘价；接口失败标“未获取”。
- **模板固定**：必须使用 `assets/ladder-template.html`；后续所有天梯保持同一套颜色、卡片、层级和字体风格。
- **输出可视化**：层级、状态、数字用卡片/标签/表格呈现；不写散文式数字段，不用表情符号。
- **不预测、不给买卖信号**：天梯只记录当日涨停结构与断板事实，不写明日推荐、不给仓位。
- **报告必落盘**：先写 `report/连板天梯/YYYY-MM-DD.html`，再回复摘要；同日重跑覆盖更新。
- **免责声明**：HTML 底部必须带“不构成投资建议”。
