# 个股分析与持仓检查

原则：**基于真实数据、基于近期数据、证据先行、结论最后**。输出不构成投资建议。

## 两种模式

买前的分析与买后的每日检查是同一套证据与规则的两端，合并在本 SKILL 内；建仓/加仓/减仓/清仓的资金调度与执行始终由 $position-management 负责。

| 模式 | 触发 | 输出 | 落盘 |
|---|---|---|---|
| 分析模式 | 用户请求分析某标的（是否值得买、支撑压力、加仓/减仓/离场判断），或 $leader-find / $simmer-find 候选深查 | 分析报告：证据分节 → 四动作信号 → 支撑压力 → 条件单参数；建仓/加仓信号附六格清单分析 | 不落盘、不维护任何状态文件（观察池不落盘） |
| 持仓检查模式 | 用户请求检查持仓（我买的股票现在怎么样、该不该卖、收盘复盘持仓部分），或 $stock-report 午间/收盘复盘逐只调用 | 持仓检查报告：固定三段（个股 / 量价 / 明日预案）+ 触发判断 | 只追加：既有 STOCK-REVIEW.md 的「每日检查」表一行，并回写 POSITION.md 现价与浮动盈亏（不创建文件、不改写交易计划） |

## 触发与前置条件

- 触发（分析模式）：用户请求分析某标的（建仓/加仓/减仓/空仓信号、支撑压力、全面分析），或对已持仓股票请求加仓/减仓/离场判断。
- 触发（持仓检查模式）：用户请求检查某只持仓（含“我买的股票现在怎么样”“该不该卖”“收盘复盘持仓部分”），或 $stock-report 午间/收盘复盘逐只调用。
- 前置：工作区已初始化（存在 ACCOUNT.md / NOTES.md / POSITION.md / stocks/）；未初始化时明确标注后继续。持仓检查模式还要求该股在 POSITION.md 持仓中，不在持仓时不执行每日检查，明确标注并提示改用分析模式。
- 必需输入：标的代码（sh/sz 前缀）与名称；缺失时不输出结论。
- 依赖文件：分析模式读 ACCOUNT.md、NOTES.md、POSITION.md、MUST.md 与该股 stocks/ 文件；持仓检查模式读 POSITION.md（总览表 + 该股持仓明细小节）、MUST.md（个人交易风格与必守规则）与 stocks/<股票名称-股票代码>/STOCK-REVIEW.md（交易计划与历史检查记录）。
- 交接：
  - 分析模式：建仓/加仓信号 → 本 SKILL 完成六格清单分析（见下方「六格清单分析」）→ $position-management 做资金调度确认，建仓执行时由 $position-management 创建 stocks/<股票名称-股票代码>/STOCK-REVIEW.md 并写入交易计划（本 SKILL 不创建该文件、不写交易计划）；减仓/空仓信号 → 直接调用 $position-management 执行资金调度（减仓/清仓）。
  - 持仓检查模式：检查后回写 POSITION.md 该股持仓明细的现价与浮动盈亏（标注数据日期），并在 STOCK-REVIEW.md「每日检查」表追加当日行（决定 + 明日预案一句话）；触发止损/止盈/时间止损时只给出平仓结论，实际卖出由用户在可交易时间执行；用户卖出后调用 $position-management 告知卖出价，由它完成平仓复盘与总结。

## 分析模式流程

1. 读取工作区上下文（每次必做，从当前工作区根目录）：
   - ACCOUNT.md：本金、现金、总盈亏、累计支取、实际可用资产（=本金+总盈亏−累计支取）→ 账户状态参考（仓位计算与确认由 $position-management 负责）
   - NOTES.md：知识、教训、准则 → 结论不得与之冲突，输出时引用相关准则
   - POSITION.md：当前持仓 → 已持有该股时，判断加仓/减仓/空仓信号（对照加仓条件与减仓条件），不重复建仓
   - MUST.md：个人交易风格与必须遵守的规则 → 分析过程与结论必须遵守，输出时引用相关规则
   - 文件缺失或未填写：明确标注“未提供”，不臆测账户与持仓数据
2. 确认标的：代码（sh/sz前缀，如 sh600410、sz002491）与名称。
3. 查看该股工作区文件（stocks/<股票名称-股票代码>/，存在则读）：
   - STOCK-REVIEW.md：交易计划 + 每日检查记录（买入理由、止损止盈、持仓期间检查结论）→ 结论必须对照既有计划，不给出冲突建议
   - TRADE-SUMMARY.md：该股交易记录与盈亏总结（由 $position-management 维护）
   - history/YYYY-MM-DD/：历史归档的复盘/规则/总结 → 避免重复犯错
   - 从未交易过该股（无该股文件夹）时标注“该股无历史记录”
4. 拉取真实数据：调用 $market-data 获取该股行情、财报、新闻公告与资金流向数据。
5. 证据收集，逐项填写（所有数字必须来自上一步数据，标注数据日期；先按「个股体检五步」体检，再逐项填写）：
   - 基本面：PE 正负与数值、PB（行情接口）；营收、净利润、毛利率、负债率（注意同比要和去年同期比）；与同行/历史比较。
   - 技术面：近期趋势（高低点方向、MA5/10/20/60 排列、价格相对 MA60 的位置）、量价（放量/缩量、高位放量滞涨/大阴线）。
   - 支撑压力：用三种方法找锚点——前期高低点（近2-4周明显低点/高点，多次触及更可信）、成交密集区（量大价位附近）、均线/整数关口（MA20/MA60、整数价位）；重叠区域优先。支撑区与压力区都是**区域不是精确线**，标依据（哪个低点/哪条均线/几次测试）。
   - 事件面（新闻/公告）：近期公告类型与标题（业绩预告、增减持、诉讼、重大合同、异常波动等）与相关新闻；逐条对照买入理由做“逻辑证伪”——有没有事件直接否定买入逻辑（如业绩变脸、减持、ST/退市风险）。
   - 资金面（资金流向）：最新交易日主力/超大单/大单/中单/小单净流入方向，近5日主力净流入趋势；配合量价判断——放量+主力净流入=资金流入，放量+主力净流出=出货嫌疑。
   - 风险：ST/退市、题材炒作特征、换手率与振幅是否剧烈；避雷清单逐条过。
6. 证据汇总（一节一节列出数字）→ 最后写“结论”。
7. 结论（四动作信号，按持仓状态选择）：
   - 未持仓：
     - 建仓信号：证据全部通过 + 触发条件出现，给交易计划要素（买点=支撑区、止损、止盈=压力区、时间止损、盈亏比）；金额与仓位由 $position-management 资金调度确认。
     - 空仓信号：硬伤或条件不足（如“PE为负+PB近10倍”“ST退市风险”“触发条件未出现”），一句话说明；继续空仓等待。
   - 已持仓（POSITION.md 有该股）：
     - 加仓信号：证据全部通过，且符合加仓条件（持仓盈利、趋势延续未破位、判断被确认而非摊低成本），给加仓建议（参考加仓价=支撑区、止损/止盈=压力区、参考批次与盈亏比）；加多少由 $position-management 按资金调度确认。
     - 减仓信号：到第一压力位或跌破移动止损（破位），建议减仓（≥2手卖一半，破位不犹豫）；由 $position-management 执行资金调度并更新 POSITION.md。
     - 空仓信号：买入理由破坏 / 止损触发 / 时间止损到期，建议离场；由 $position-management 按清仓流程结算（用户卖出后告知卖出价）。
   - 观察（中间态，非动作）：体检及格但触发条件未出现。
     - 未持仓：输出「观察」= 等待——把触发条件（可检查的信号：回踩支撑企稳收阳/放量突破后回踩不破）与预案（买点=支撑区、止损、止盈、时间止损）写在报告里，由用户自行盯；本 SKILL 不落盘、不维护观察池。随后按第 9 步输出条件单参数。
     - 已持仓：不加不减，说明差什么条件，按既有规则继续持有/执行。
8. 支撑压力详细输出（用户问支撑压力，或结论为建仓/加仓/减仓/观察时给出）：
   - 支撑区（1-2个，标依据）
   - 压力区（分层：第一道最紧，第二道以上）
   - 当前价格位置：靠近支撑还是压力（距离%）
   - 有效性评估：停留时间、伴随量能、距离当前远近三因素
   - 角色互换提示：已跌破/突破则旧位变新角色（需放量与回踩确认，警惕假突破）
   - 盈亏比参考：支撑买→压力卖 vs 现价追入
9. 条件单参数输出（等待/建仓信号必出，空仓信号不出）：
   - 按 references/conditional-order.md 给出：类型（回踩买/突破买）、触发价、委托限价、止损、止盈、手数上限、撤销条件
   - 手数上限 = floor(单笔预算 ÷ ((委托限价−止损)×100))，预算实时取自 ACCOUNT.md 资金规则（实际可用资产×2%，连亏 2 笔降档为实际可用资产×1%，不写死；实际可用资产=本金+总盈亏−累计支取）
   - 一手风险超预算、情绪高潮期、MUST 不买情形 → 不设条件单，写明原因

## 个股体检五步（组织证据前先体检）

证据收集（流程第 5 步）前按下面五步把标的过一遍，每一步都落到可核验的数字（标注数据日期）；体检结论是证据的一部分，不是最终信号。

1. 买得起吗：一手金额=价格×100；对照 ACCOUNT.md 的实际可用资产（=本金+总盈亏−累计支取）与当前现金，判断能否参与及最多几手量级；注意板块权限（创业板/科创板有门槛）。这一步只做可行性体检，金额/手数/批次由 $position-management 资金调度确认。
2. K线在讲什么：阴阳线、实体、上下影线、十字星；先定周期（日K/周K/60分钟K）。
3. 趋势在哪个周期：高低点方向；MA5/20/60 排列；多头/空头排列。
4. 风险像不像你：近期涨幅、振幅、估值（PE/PB）；满仓±10%能否接受。
5. 写下体检结论：一句话说清“赚不赚钱、贵不贵、风险在哪”。

结论示例：PE为负、PB 9.5、换手15%+、价格在MA60下方 → 基本面不及格；按流程第 7 步属硬伤，输出“空仓信号”（MUST.md 明确允许技术面博弈时除外，仍需严格止损）。

报告结构（证据→结论）：证据分节（基本面/技术面/支撑压力/事件与资金面/风险）先给数字，结论放最后（建仓/加仓/减仓/空仓信号，观察为中间态）+ 硬伤或待观察条件；等待/建仓信号必出条件单参数（类型/触发价/委托限价/止损/止盈/手数上限/撤销条件，规则见「流程」第 9 步与 references/conditional-order.md）。

## 六格清单分析（建仓前完成，不落盘）

输出建仓/加仓信号后自动执行（用户也可直接请求），在本 SKILL 输出中完成六格清单分析，作为交接输入交 $position-management 汇总；工作区不再生成/维护 TRADE-RULES.md。

- 输入：标的（代码/名称）、买点=支撑区、止损、止盈=压力区、时间止损、盈亏比、买入理由、风险偏好（默认稳健）与交易周期（默认 1-2 周，默认值说明理由）；MUST.md 个人风格与 NOTES.md 实战教训必须纳入且不得违背。
- 清单内容：六格清单（选什么/何时买/买多少/错了怎么办/对了怎么办/交易后，价位与盈亏比必须具体到数字；「买多少」只给单笔亏损预算约束，金额/手数/批次由 $position-management 资金调度确定）+ 下单前六问，逐格逐问对照下方模板与实战教训。
- 交接：六格清单分析完成后调用 $position-management 确认仓位；建仓执行时由 $position-management 创建 stocks/<股票名称-股票代码>/STOCK-REVIEW.md，把六格要素与资金调度结果汇总为「交易计划」（含最大亏损金额与本金%、盈亏比）写入；本 SKILL 不落盘任何交易规则文件。
- 纪律：清单必须具体到数字；不替用户定金额/手数/批次；加仓清单需「加仓」信号与 POSITION.md 持仓，缺一不输出。

### 六格清单（数字按该股分析与用户确认值替换）

| 格子 | 规则 |
|---|---|
| 选什么 | ①基本面体检及格：PE不为负、看得懂 ②不在避雷清单 ③波动能承受（见「个股体检五步」第 4 步） |
| 何时买 | 只在支撑区附近企稳买，或放量突破后回踩不破；不追箱体中部和上沿 |
| 买多少 | 单笔亏损预算实时取自 ACCOUNT.md 资金规则（默认实际可用资产 2%，连亏 2 笔降档为 1%；实际可用资产=本金+总盈亏−累计支取），不写死；金额/手数/批次由 $position-management 资金调度确认 |
| 错了怎么办 | 止损=支撑区下方；收盘跌破执行；跳空破位/暴跌日不等收盘，接受滑点尽快走 |
| 对了怎么办 | 止盈=压力区附近，到点按既有交易计划执行（减仓/清仓规则见流程第 7 步）；默认 1-2 周不涨按时间止损走 |
| 交易后 | 每日收盘检查由本 SKILL 持仓检查模式执行（追加 STOCK-REVIEW.md 每日检查行）；平仓复盘按事实→执行→判断→改进，交接 $position-management 汇总 |

### 下单前六问（缺一条就不做）

1. 选什么：这只票体检及格了吗？
2. 何时买：现在的位置符合买点吗？
3. 买多少：这笔最多亏多少，预算内手数上限是多少？
4. 错了怎么办：止损和触发规则写下来了吗？
5. 对了怎么办：止盈和时间止损写下来了吗？
6. 交易后：每日收盘检查与平仓复盘流程准备好了吗？

## 分析模式输出格式（固定）

1. 标题 + 数据日期（如：通鼎互联（sz002491）分析 · 截至2026-08-19）
2. 工作区上下文（缺失项标注“未提供”）
3. 证据：基本面 / 技术面 / 支撑压力 / 事件与资金面 / 风险
4. 结论（放最后）：建仓 / 加仓 / 减仓 / 空仓信号（观察为中间态）+ 一句话理由 + 硬伤或待观察条件
5. 支撑压力 / 触发条件与预案 / 条件单参数：内容按流程第 7-9 步输出，不涉及则省略；观察为等待中间态，触发条件与预案写在报告里（不落盘）；建仓/加仓信号额外输出六格清单分析（交接给 $position-management 汇总进交易计划，不落盘）
6. 结尾：“以上基于截至<日期>的真实数据，不构成投资建议，最终决定由用户作出。”

## 持仓检查模式流程

用收盘价做判断，不盘中盯价；输出按「收盘复盘输出格式」固定三段（格式与细项见 references/position-check.md），输入仍按「每日检查五条」逐项核对。

1. 读取工作区上下文：先从 POSITION.md 读取该股总览表行与持仓明细小节（代码、买入价/成本、手数、止损、触发规则、止盈、时间止损、买入理由），从 MUST.md 读取个人交易风格与必守规则（检查与结论必须遵守）；明细缺失字段可从该股 STOCK-REVIEW.md 的交易计划取。POSITION.md 缺失或未填写时，向用户询问或明确标注“未提供”。
2. 拉取真实数据：调用 $market-data 获取该股行情数据（收盘价、今日高/低、成交量/换手、MA5/10/20；午间调用用盘中数据并注明时段）。
3. 输出“持仓检查报告”（固定三段，格式见 references/position-check.md）：
   - 数据表：现价、今日高/低、成交量/换手、MA5/10/20、距止损/止盈（金额与%）
   - 第三步 个股：日K形态、收盘价 vs 止损/止盈/时间止损、触发与否、买入理由、新信息与心态
   - 第四步 量价：放量/缩量 + 涨/跌 → 量价四句翻译
   - 第五步 明日预案：按预案行模板填一行（9:25 看什么 / 触发条件 / 动作 / 不许做什么）
   - 客观判断：是否触发规则（如“收盘价14.61 > 止损14.58 → 未触发，按计划持有”）
   - 禁止：建议挪止损、改止盈、加仓摊平
4. 落盘（只追加，不建档；$stock-report 午间版精简介入时只输出、不写文件）：
   - 把本次检查结果与明日预案写入该股 STOCK-REVIEW.md 的「每日检查」表：追加一行（“决定”列含客观判断与“明日预案：…”一句话），交易计划节不改写
   - 回写 POSITION.md：更新该股持仓明细小节中的现价与浮动盈亏（标注数据日期）；出现异动（接近/触发规则、建议平仓等）时在小节内追加一行“{{日期}} 备注：…”
5. 结论：未触发 → 按计划持有，不动作；触发（收盘跌破止损/跳空破位/止盈/时间止损）→ 结论为“建议平仓”，写明触发条件与建议动作，不代替用户下单（可能不在交易时段）；用户卖出后调用 $position-management 告知卖出价完成平仓总结。
6. 结尾：“基于截至<日期>的真实数据，不构成投资建议，最终决定由用户作出。”

## 每日检查五条（持仓检查模式的输入清单）

用收盘价做判断，不盘中盯价。

| # | 检查项 | 看什么 |
|---|---|---|
| 1 | 价格位置 | 收盘价多少？离止损、止盈多远（金额与%）？ |
| 2 | 量能 | 放量还是缩量？和前些天比异常吗？ |
| 3 | 新信息 | 公告、行业、大盘有没有变化？查不到标“未核实” |
| 4 | 买入理由 | 当初为什么买？今天还成立吗？ |
| 5 | 心态 | 有没有冲动想改计划？为什么？ |

对应关系：检查 1（价格位置）→ 第三步个股；检查 2（量能）→ 第四步量价；检查 3–5（新信息/买入理由/心态）→ 第三步个股的补充行。

## 触发规则（持仓检查模式）

- 收盘价跌破止损 → 触发，离场
- 跳空低开直接跌破止损 / 暴跌日 → 不等收盘，破位即走
- 盘中插针（最低破、收盘守住）→ 不触发

判断输出：未触发 → 按计划持有，不动作；触发 → 按规则离场，不商量、不挪止损。

## 硬性规则

通用：

- 证据先行：先给可核验的数字，再下结论；禁止先有结论再找证据。
- 工作区先行：工作区文件缺失或未填写就标注“未提供”，不臆测。
- 近期数据优先：只用最近3-6个月行情与最新估值；陈旧数据必须标注日期。
- 数据必须真实：$market-data 拉不到数据就明确报错，不编造。
- 不替用户做决定：结论用框架（建仓/加仓/减仓/空仓信号，观察为中间态），不承诺收益、不催单；不代替用户下单。

分析模式：

- 事件检查：分析时必查近期公告与新闻；存在否定买入理由的事件（业绩变脸、减持、诉讼、ST/退市风险、异常波动提示等）时，不得输出建仓/加仓信号。
- 区域优先：说“4.70–4.71一带”而不是“支撑在4.70”。
- 假突破提醒：突破/跌破需配合放量与回踩确认，警惕“差一点又回来”。
- 遵守既有计划：该股 STOCK-REVIEW.md 交易计划（或 history/ 归档的旧计划与 TRADE-SUMMARY.md 总结）、NOTES.md 已有准则时，结论必须与之对照；不给出与既有计划冲突的建议。
- 加仓纪律：禁止亏损摊平；加仓条件见流程第 7 步，缺一不加。
- 观察不落盘：观察只是等待中间态——标的/触发条件/预案三要素齐全地写在报告里，由用户自行盯；分析模式只分析并输出报告，不维护观察池、不写任何状态文件。体检不及格或已破位，直接给空仓信号。
- 条件单预算约束：条件单参数遵守 ACCOUNT.md 资金规则与流程第 9 步公式；一手风险超预算时不得设单，标注原因；条件单只验证价格，触发后仍需人工复核（量能/换手/资金/形态）。
- 信号纪律与职责边界：分析模式只输出信号、锚点与建议（观察为中间态，触发条件与预案写在报告里，见「观察不落盘」），不落盘任何分析文件、不计算金额/仓位/手数/批次/单笔亏损预算（资金调度由 $position-management 负责）；四动作都必须有触发条件，无触发条件不动作；输出信号后调用 $position-management，不自行下单。

持仓检查模式：

- 客观判断触发与否：只说“触发/未触发”，不预测涨跌；预案只写可检查的触发条件与动作。
- 收盘复盘三段输出：个股/量价/明日预案按 references/position-check.md 的固定结构输出，$stock-report 收盘版直接采用汇总。
- 持仓信息以 POSITION.md 为准：先读工作区 POSITION.md，缺失字段再向用户询问或标注“未提供”；明细缺失字段可从该股 STOCK-REVIEW.md 的交易计划取。
- 不改规则：持仓期间不调整用户既定止损/止盈，不建议挪止损、改止盈、加仓摊平。
- 只给平仓结论不下单：触发平仓条件时只输出“建议平仓”，实际卖出由用户在可交易时间执行。
- 只追加不建档：STOCK-REVIEW.md 在本 SKILL 执行前已存在（含交易计划），持仓检查模式只在「每日检查」表追加一行（当日行含客观判断与“明日预案：…”一句话），不创建文件、不改写交易计划；本模式唯一允许写的两处是 STOCK-REVIEW.md 每日检查行与 POSITION.md 现价/浮动盈亏。
- 只做每日检查：平仓复盘、盈亏计算与 TRADE-SUMMARY.md 由 $position-management 负责，本 SKILL 不越权。
