# 个股全面分析（建仓/加仓/减仓/空仓信号 + 支撑压力）

原则：**基于真实数据、基于近期数据、证据先行、结论最后**。输出不构成投资建议。

## 触发与前置条件

- 触发：用户请求分析某标的（建仓/加仓/减仓/空仓信号、支撑压力、全面分析），或对已持仓股票请求加仓/减仓/离场判断。
- 前置：工作区已初始化（存在 ACCOUNT.md / NOTES.md / POSITION.md / stocks/）；未初始化时先提示运行 $setup-stock-workspace，或明确标注后继续。
- 必需输入：标的代码（sh/sz 前缀）与名称；无标的或拉取不到行情数据时，不输出结论。
- 交接：建仓/加仓信号 → $trade-rules-generate 生成/追加规则 → $position-management 做资金调度确认；减仓/空仓信号 → 直接调用 $position-management 执行资金调度（减仓/清仓）。

## 流程

1. 读取工作区上下文（每次必做，从当前工作区根目录）：
   - ACCOUNT.md：本金、现金、总盈亏 → 账户状态参考（仓位计算与确认由 $position-management 负责）
   - NOTES.md：知识、教训、准则 → 结论不得与之冲突，输出时引用相关准则
   - POSITION.md：当前持仓 → 已持有该股时，判断加仓/减仓/空仓信号（对照加仓条件与减仓条件），不重复建仓
   - MUST.md：个人交易风格与必须遵守的规则 → 分析过程与结论必须遵守，输出时引用相关规则
   - WATCHLIST.md：观察池 → 检查该股是否已在池中，分析结论联动进出池状态（进池/等待/移除/信号触发）
   - 文件缺失或未填写：明确标注“未提供”，不臆测账户与持仓数据；可提示先运行 $setup-stock-workspace 初始化
2. 确认标的：代码（sh/sz前缀，如 sh600410、sz002491、sh510300）与名称；确认是A股还是ETF。
3. 查看该股工作区文件（stocks/<纯数字代码>/，存在则读）：
   - STOCK-REVIEW.md：历史复盘（买卖理由、执行情况、经验教训）
   - TRADE-RULES.md：该股专属规则（六格规则 + 下单前六问）→ 结论必须对照既有规则，不给出冲突建议
   - TRADE-SUMMARY.md：累计交易记录与盈亏
   - history/YYYY-MM-DD/：历史归档的复盘/规则/总结 → 避免重复犯错
   - 从未交易过该股（无代码文件夹）时标注“该股无历史记录”
4. 拉取真实数据：

   ```bash
   python scripts/fetch_quote.py <代码> --days 60
   python scripts/fetch_fundamentals.py <代码>
   python scripts/fetch_news.py <代码> --news 5 --ann 5
   python scripts/fetch_capital_flow.py <代码>
   ```

   任一接口拿不到数据就明确说“数据获取失败”，不编造价格、PE、PB、营收、利润、新闻、公告或资金流向。
5. 证据收集，逐项填写（所有数字必须来自上一步数据，标注数据日期）：
   - 基本面：PE 正负与数值、PB（行情接口）；营收、净利润、毛利率、负债率（fetch_fundamentals.py，注意同比要和去年同期比）；与同行/历史比较；ETF 标注“不适用，看指数估值”。
   - 技术面：近期趋势（高低点方向、MA5/10/20/60 排列、价格相对 MA60 的位置）、量价（放量/缩量、高位放量滞涨/大阴线）。
   - 支撑压力：用三种方法找锚点——前期高低点（近2-4周明显低点/高点，多次触及更可信）、成交密集区（量大价位附近）、均线/整数关口（MA20/MA60、整数价位）；重叠区域优先。支撑区与压力区都是**区域不是精确线**，标依据（哪个低点/哪条均线/几次测试）。
   - 事件面（fetch_news.py）：近期公告类型与标题（业绩预告、增减持、诉讼、重大合同、异常波动等）与相关新闻；逐条对照买入理由做“逻辑证伪”——有没有事件直接否定买入逻辑（如业绩变脸、减持、ST/退市风险）。
   - 资金面（fetch_capital_flow.py）：最新交易日主力/超大单/大单/中单/小单净流入方向，近5日主力净流入趋势；配合量价判断——放量+主力净流入=资金流入，放量+主力净流出=出货嫌疑。
   - 风险：ST/退市、题材炒作特征、换手率与振幅是否剧烈；避雷清单逐条过。
6. 证据汇总（一节一节列出数字）→ 最后写“结论”。
7. 结论（四动作信号，按持仓状态选择）：
   - 未持仓：
     - 建仓信号：证据全部通过 + 触发条件出现，给交易计划要素（买点=支撑区、止损、止盈=压力区、时间止损、盈亏比）；金额与仓位由 $position-management 资金调度确认。
       - 若该股已在观察池：把状态改为“信号触发，按预案执行”。
     - 空仓信号：硬伤或条件不足（如“PE为负+PB近10倍”“ST退市风险”“触发条件未出现”），一句话说明；继续空仓等待。
       - 不进池；若该股已在观察池：移除并标注原因。
   - 已持仓（POSITION.md 有该股）：
     - 加仓信号：证据全部通过，且符合加仓条件（持仓盈利、趋势延续未破位、判断被确认而非摊低成本），给加仓建议（参考加仓价=支撑区、止损/止盈=压力区、参考批次与盈亏比）；加多少由 $position-management 按资金调度确认。
     - 减仓信号：到第一压力位或跌破移动止损（破位），建议减仓（≥2手卖一半，破位不犹豫）；由 $position-management 执行资金调度并更新 POSITION.md。
     - 空仓信号：买入理由破坏 / 止损触发 / 时间止损到期，建议离场；由 $position-management 按清仓流程结算（用户卖出后告知卖出价）。
   - 观察（中间态，非动作）：体检及格但触发条件未出现。
     - 未持仓：进观察池，写入触发条件（可检查的信号：回踩支撑企稳收阳/放量突破后回踩不破）与预案（买点=支撑区、止损、止盈、时间止损），状态“等待”。
     - 已持仓：不加不减，说明差什么条件，按既有规则继续持有/执行。
   - 建仓/加仓信号 → 自动调用 $trade-rules-generate 生成（或更新）六格交易规则，再由 $position-management 做资金调度确认；减仓/空仓信号 → 直接调用 $position-management 执行资金调度。
8. 支撑压力详细输出（用户问支撑压力，或结论为建仓/加仓/减仓/观察时给出）：
   - 支撑区（1-2个，标依据）
   - 压力区（分层：第一道最紧，第二道以上）
   - 当前价格位置：靠近支撑还是压力（距离%）
   - 有效性评估：停留时间、伴随量能、距离当前远近三因素
   - 角色互换提示：已跌破/突破则旧位变新角色（需放量与回踩确认，警惕假突破）
   - 盈亏比参考：支撑买→压力卖 vs 现价追入

## 输出格式（固定）

1. 标题 + 数据日期（如：通鼎互联（sz002491）分析 · 截至2026-08-19）
2. 工作区上下文：账户资金 / 相关准则 / 是否已持仓 / 该股历史（引用来源文件名；缺失项标注“未提供”）
3. 证据：基本面 / 技术面 / 支撑压力 / 事件与资金面 / 风险
4. 结论（放最后）：建仓 / 加仓 / 减仓 / 空仓信号（观察为中间态）+ 一句话理由 + 硬伤或待观察条件
5. 观察池状态：进池（触发条件+预案）/ 等待 / 移除（原因）/ 信号触发
6. 支撑压力部分：支撑区 / 压力区 / 当前价格位置 / 盈亏比参考
7. 结尾：“以上基于截至<日期>的真实数据，不构成投资建议，最终决定由用户作出。”

## 硬性规则

- 证据先行：先给可核验的数字，再下结论；禁止先有结论再找证据。
- 工作区先行：每次分析前必读 ACCOUNT.md / NOTES.md / POSITION.md / MUST.md / WATCHLIST.md 与该股 stocks/<代码>/ 文件及 history 归档；缺失或未填写就标注，不臆测。
- 近期数据优先：只用最近3-6个月行情与最新估值；陈旧数据必须标注日期。
- 数据必须真实：脚本拉不到就报错，不猜测。
- 事件检查：分析时必查近期公告与新闻；存在否定买入理由的事件（业绩变脸、减持、诉讼、ST/退市风险、异常波动提示等）时，不得输出建仓/加仓信号。
- 区域优先：说“4.70–4.71一带”而不是“支撑在4.70”。
- 假突破提醒：突破/跌破需配合放量与回踩确认，警惕“差一点又回来”。
- 遵守既有规则：该股 TRADE-RULES.md 已有规则、NOTES.md 已有准则时，结论必须与之对照；不给出与既有规则冲突的建议。
- 加仓纪律：加仓只在该股已持仓且符合加仓条件时给出（持仓盈利、趋势延续未破位、判断被确认而非摊低成本）；禁止亏损摊平。
- 观察池纪律：进池必须三要素齐全（标的、触发条件、预案）；没有触发条件不建仓；体检不及格不进池；已在池中且体检不及格/破位不企稳 → 移除。
- 职责边界：本 SKILL 不计算金额、仓位、手数、批次与单笔亏损预算（资金调度由 $position-management 负责）；分析只输出信号、锚点与建议。
- 信号纪律：四个动作（建仓/加仓/减仓/空仓）都必须有触发条件与金额规则（金额由 $position-management 资金调度计算）；无触发条件不动作；输出信号后调用 $position-management，不自行下单。
- 不替用户做决定：结论用框架（建仓/加仓/减仓/空仓信号，观察为中间态），不承诺收益、不催单。
