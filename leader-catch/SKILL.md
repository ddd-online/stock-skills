# 龙头股专题扫描（leader-catch）

核心前提（经验性框架）：“龙头”在 A 股装着两种东西——**行业龙头**靠基本面当选（真龙头，时间维度以年计），**人气龙头**靠资金当选（板块内相对最强，生命周期几天到几周）。两者风险等级完全不同；而且**最强的那只，常常不是你现在该买的那只**。本 SKILL 只解决“识别最强、列出值得买的候选”，买不买、在哪买由后面的六关与用户纪律决定。

## 触发与前置

- 触发：用户请求“扫描/分析当前市场活跃板块里的龙头”“分析 XX 板块（行业/题材）的行业龙头与人气龙头”“把最强和值得买分开”“今天哪些题材在走主升、龙头是谁”等；也可定时跟踪（连续交易日对比板块榜持续性）。
- 前置：$market-data 可用（板块行情榜/成分股榜/板块财务排名脚本为必备数据能力，已并入 market-data）；工作区文件（ACCOUNT.md / POSITION.md / MUST.md / WATCHLIST.md）**可选**——存在则读取并遵守个人口径，不存在则明确标注“未读取账户/持仓上下文”，本报告仍按通用默认口径执行。
- 模式：
  - 全市场扫描：从行业板块与概念板块榜找当前活跃板块/题材，聚焦 ≤3 个（重叠题材合并），逐个下钻人气龙头，并对聚焦行业板块下钻行业龙头；
  - 指定板块：用户给板块/题材名（如“铜缆、液冷、算力连接”）或 BK 代码，直接在对应板块下钻两类龙头；板块名先用 fetch_sector_boards 的 --search 关键词定位 BK 代码，定位不到时报错，不臆造代码。
- 默认口径（未读取到 MUST.md 时使用；MUST.md / 用户说明优先）：
  - 人气候选池：剔除 ST/风险警示、名称 N/C 开头新股；当日涨幅 ≥3%；换手 5%–10%（人气健康区，>15% 标“情绪票”）；流通市值 50–200 亿；当日封死涨停的另列“涨停候选”，不默认给上车点。
  - 行业龙头候选：板块内按营收/净利排名第一梯队（前 3 名）+ 质地四数字 + 估值 + 主营验证。
  - 覆盖规则：聚焦主题 ≤3 个；财务排名每板块 ≤12 只；深查（日K/新闻/资金）只对每板块 ≤5 只短名单执行。
- 交接：扫描报告只给名单与观察预案，不下单；用户要继续“值不值得买”→ 每只转 $stock-analysis（出建仓/空仓信号与买点/止损/止盈）；资金仓位走 $position-management；纳入/退出观察池由 $watchlist-review 处理。
- 落盘：报告写入 report/龙头扫描-YYYY-MM-DD.md（report/ 不存在则创建；同日再次运行覆盖更新并注明运行时间）。

## 两种龙头速查

| | 行业龙头（真龙头） | 人气龙头（板块最强） |
|---|---|---|
| 当选依据 | 营收、净利润、市占率行业第一梯队 | 板块启动后涨得最猛、资金最认可 |
| 时间维度 | 以年计 | 几天到几周 |
| 主要风险 | 便宜时没人理、可能长期不涨 | 高位巨量就是派发，接棒亏损巨大 |
| 识别框架 | 定义行业 → 规模排名 → 质地 → 估值 → 主营验证 | 相对强度 → 硬逻辑 → 量能健康 → 给上车点（四查两两对比） |
| 本 SKILL 的处理 | 只识别与列名单；“值得买”需再过六关 | 只给“板块相对最强”候选与淘汰理由；“值得买”需再过六关 |

## 流程

### 第一步：确认目标与上下文

1. 用户指定板块 → 记下板块名/代码；未指定 → 全市场扫描模式。
2. 当前目录有 ACCOUNT.md / POSITION.md / MUST.md / WATCHLIST.md 则读取：个人市值/换手/仓位过滤、持仓与观察池标的（避免重复、标注“已持仓/观察中”）、NOTES.md 教训；缺文件标注“未提供”，不臆测。
3. 确认数据时间（A股交易日收盘后或盘中均可；报告注明“实时/延迟”与数据日期）。

### 第二步：活跃板块/题材扫描（全市场模式；指定板块模式可跳过，直接定位 BK）

通过 $market-data 拉取（按需组合，具体脚本与参数由 $market-data 决定，本 SKILL 需要以下数据列）：

- 行业板块榜：按当日涨跌幅、主力净流入、近5日涨跌幅分别看，得行业方向；
- 概念板块榜：同上，得题材方向；
- 每行数据含：BK 代码、板块名、今日/近5日/近10日涨幅、领涨股（名/码/涨幅）、上涨/下跌家数、成交额、换手、主力净流入。

聚焦规则（全部用真实数字，逐条给依据，不凭印象）：

1. 候选 = 当日涨幅榜前 10–15 与主力净流入榜前 10–15 的并集；
2. 持续性复核：5日涨幅 > 0 且 10日涨幅 > 0 的优先（有资金持续性）；5日涨幅 ≤ 0 但今日放量首涨的标“疑似启动第一天”，需次日复核；
3. 宽度复核：上涨家数/下跌家数 ≥ 2:1，或上涨家数 ≥ 10（小板块单独标注，避免用 3 只股票拼“活跃板块”）；
4. 去重叠：领涨股或成分高度重叠的概念（如算力/液冷/铜缆）合并为同一题材簇，聚焦 ≤3 个；
5. 成交额过小（无法容纳资金的题材）标注“容量不足”，不纳入聚焦。

输出“活跃板块表”，并给每个聚焦板块一句话位置描述（仅陈述数据：今日/5日/10日涨幅高低、是否高位放量），不预测次日涨跌。

### 第三步：板块内下钻，取两类龙头数据

对每个聚焦板块（或用户指定板块）经 $market-data 拉：

- 成分股榜（按当日涨幅，Top 30；表头含板块今日/5日/10日涨幅、领涨股、涨跌家数）→ 人气龙头候选数据；
- 财务排名（总市值前 12 的最新报告期营收/净利/毛利率/ROE/负债率）→ 行业龙头候选数据；
- 若板块是**概念/题材板块**：财务榜只能说明“板块内财务第一梯队”，不能直接叫“行业龙头”；须同时定位该题材对应的**东财行业板块**再拉财务榜，或明确标注“此为题材内财务排名，行业地位待验证”。

### 第四步：人气龙头四查打分（两两对比，候选 ≤5 只）

候选先过默认口径快筛（见“触发与前置”），不足 5 只时放宽到当日涨幅前 5 只并逐只标注为何破例；超过则按涨幅排序取前 5。

对每只候选按 references/leader-identification.md 的四查表打分，每项给“过/不过/待核 + 数字”：

| # | 检查项 | 合格标准（数据依据） |
|---|---|---|
| 1 | 相对强度 | 板块启动期先涨、涨得多：5日/10日涨幅高于板块自身与同板块多数候选；回调期跌得少、先收复（用日K确认，见第 5 步） |
| 2 | 硬逻辑占主营 | 题材收入写在最新财报主营构成里；公告/新闻澄清“无收入/不相关”→ **一票否决** |
| 3 | 量能健康 | 上涨有量、回调缩量；换手 5%–10% 人气足但未过热；高位巨量、换手 >30% = 派发嫌疑（一票否决） |
| 4 | 给上车点 | 有回踩企稳收阳/放量突破回踩不破的候选点；连板/涨停不给点 = “等回踩”，不算给点 |

两两对比只对同一板块/题材内进行，结论写“谁相对最强、为什么、淘汰理由是什么”——**淘汰理由比选中理由更重要**，每只被淘汰的都写一行。

### 第五步：行业龙头（基本面第一梯队）核验

对聚焦的行业板块（或用户指定行业）：

1. 规模排名：按 fetch_sector_fundamentals 的营收榜/净利榜取第一梯队（前 3）；
2. 质地：毛利率高于同行、ROE 高且多年稳定、负债率合理、经营现金流为正（fetch_sector_fundamentals / fetch_fundamentals 多报告期核对，缺失标“待核”）；
3. 估值：PE/PB 与同行、与自身历史比（fetch_quote），溢价离谱标“好公司坏价格”；
4. 主营验证：最新财报主营构成/公告/新闻里题材收入占比要真实；占比为 0 或被澄清 → 伪龙头，一票否决，不进名单。

第 2–4 步只对营收/净利前 3–5 只执行，控制深查数量；行业龙头选的是“板块第一梯队 + 质地 + 主营真实”，不是最大市值。

### 第六步：短名单深查（每板块 ≤5 只，只查“最强候选”）

对每板块人气相对最强候选（≤2 只）与行业龙头前 3 只，经 $market-data 拉：

- 行情日K 15–30 根（含 MA）：确认相对强度里的回调缩量/收复、是否在均线上方（上升趋势）；
- 新闻公告（近 3–5 条）：逻辑证伪与主营验证；
- 资金流向：主力净流入是否与涨势同向。

数据缺项标注“未获取”，不脑补。本步只补证据，不替代 $stock-analysis 的建仓/空仓判断。

### 第七步：汇总结论并落盘

报告固定格式（见下）；正文先写入 report/龙头扫描-YYYY-MM-DD.md，再在回复中给结论与文件位置。结论区把两类分开：

- “最强”名单：行业龙头第一梯队 + 人气龙头（板块相对最强）——只说明它们强在哪个数字上；
- “值得买”候选：需要**再过六关**（体检 → 观察池 → 买点 → 仓位 → 止损 → 复盘）才谈得上买；本 SKILL 只输出“值得进一步评估”的名单与下一步（转 $stock-analysis），不给买卖动作。六关映射见 references/leader-identification.md。

## 报告格式（固定）

1. 标题：龙头扫描报告 · YYYY-MM-DD（运行时间 HH:MM；数据时间来自 $market-data 报告）
2. 模式与范围：全市场活跃板块 / 指定板块（名称 + BK 代码）；MUST/账户/持仓是否读取
3. 活跃板块表（全市场模式）：板块代码/名称/今日/5日/10日涨幅/领涨股/上涨:下跌/成交额/主力净流入/位置描述
4. 聚焦板块摘要：每个板块一行（今日与5日10日、领涨股、宽度），并注明合并/淘汰了哪些重叠题材
5. 人气龙头四查表：每板块一张，候选 5 行内，四查逐项过/不过/待核 + 数字 + 淘汰理由
6. 行业龙头表：营收/净利第一梯队（报告期、营收、净利、同比、毛利率、ROE、负债率）+ 质地/估值/主营核验状态（过/待核/一票否决）
7. 结论：最强名单 vs 值得买候选（分开列）；观察池建议（触发条件与预案一句话；进池动作交 $watchlist-review）；下一步动作（$stock-analysis / $position-management）或“无进一步动作”
8. 结尾：“以上基于截至<日期>的真实数据，不构成投资建议，最终决定由用户作出。”

## 硬性规则

- 数据必须真实：$market-data 拉不到就明确报错或标“未获取”，禁止编造涨幅、家数、营收、净利、新闻或资金数据；每条引用标数据日期。
- 行业定义用东财行业分类，不凭题材自拼“行业”；概念板块的财务榜不得直接写成“行业龙头”。
- 一票否决不妥协：ST/退市风险、澄清“无收入/不相关”、高位巨量换手 >30% 派发嫌疑等，任何一条命中即不进名单，淘汰理由写入报告。
- 最强 ≠ 值得买：报告始终把“强”与“买”分开；本 SKILL 不出买卖信号、不写买点止损、不给仓位建议；深查与买卖判断一律转 $stock-analysis → $position-management。
- 只识别不追高：当日涨停的领涨股列“涨停候选/等回踩”，默认不视作有上车点。
- 报告必落盘：先写 report/龙头扫描-YYYY-MM-DD.md，再回复摘要；回复不替代落盘。
- 工作区规则优先：MUST.md / NOTES.md 与默认口径冲突时按用户规则执行并在报告中注明。
- 免责声明：报告结尾必须带“不构成投资建议”。
