# 涨停板查找（limit-find）

涨停数据是市场情绪与短线主线的“体温计”。本 SKILL 负责把当日涨停板数据查找齐全，并按六个问题组织报告：今天涨停/跌停多少家？最高板几板、是谁、是否一字？昨日涨停今天还有多少在涨、有没有炸板潮？昨日涨停股今天怎么开的、尾盘什么状态、所在板块强不强、板块内有没有分化？今天涨停的板数怎么分布、各板块的晋级率与炸板率如何、板块活跃度够不够？当日主线板块是什么？最后把当日与之前四次报告并排看，定出情绪处在阵型四态中的哪一态。所有数字必须来自真实行情，判定阈值一律可复核、可被用户请求中说明的个人阈值覆盖。

## 触发与前置

- 触发：用户请求查找涨停板数据——涨停/跌停家数、连板高度、最高板、晋级率、炸板潮、昨日涨停股今日开盘与尾盘分类、板块强弱与分化、分板块晋级率与炸板率、板块活跃度、当日主线板块、当前情绪处在哪一态、昨日阵型今天确认了没有（含“涨停复盘”式提法）；收盘后运行得到当日定稿口径，盘中运行得到实时口径（报告中注明）。
- 前置：$market-data 可用（fetch_limit_up.py 提供涨停/跌停/炸板池与晋级数据，fetch_sector_boards.py 提供板块行情榜）。本 SKILL **不依赖工作区文件**——不读取 MUST.md / NOTES.md / ACCOUNT.md 等，可在任意目录直接运行；报告写入运行目录下的 report/涨停板复盘/YYYY-MM-DD.md。
- 数据日期：fetch_limit_up.py 缺省自动取最近有数据的交易日；用户指定日期但该日无独立数据时，回退到接口最新数据日并在报告中注明，不把回退日期冒充请求日期。
- 落盘：报告写入 report/涨停板复盘/YYYY-MM-DD.md（YYYY-MM-DD 为数据日期；report/ 与 report/涨停板复盘/ 不存在则创建；同日再次运行覆盖更新并注明运行时间），格式照 references/report-template.md 的固定骨架；阵型判定是同一份报告的最后（「阵型判定」）一节，样本取自本目录下最近的五份报告。
- 交接：本 SKILL 只查找数据并做情绪与主线的判定，不产生买卖动作；如需对主线板块内的个股做买卖判断，转 $stock-analysis / $position-management。

## 流程

### 第一步：确认日期与口径

1. 确认“今天”的数据日期：先直接运行 $market-data 的涨停板数据报告（不指定 --date，自动解析），从输出头部读数据日期；需要指定历史日期时用 --date YYYYMMDD。
2. 不读取工作区文件：个人阈值（涨停热度区间、炸板潮判定、板块强弱与分化口径、板块活跃度口径、主线确认口径）只取用户请求中的说明，未说明则用本 SKILL 默认值并写进报告。
3. 读取 report/涨停板复盘/ 下**日期早于本次数据日期**的最近四份 `YYYY-MM-DD.md`：其「主线板块」「情绪判定」用于环比，其四个数字（最高板、晋级率、炸板率、跌停家数）用于第四步的阵型汇总。不足四份或目录不存在时不阻塞本次运行，按实际份数进入第四步并注明样本天数。
4. 另取**上一份报告**的四项内容用于「昨日阵型确认」：阵型标签（一个字都不改地抄过来，并决定用哪张检验卡）、最高板（空间板代码）、晋级率、当日炸板率与跌停家数。没有上一份报告时该子块写“无前一日态，不判确认”（首次运行）。

### 第二步：拉取数据（全部经 $market-data）

- 涨停板全景：fetch_limit_up.py（默认最新数据日；输出今日/昨日涨停、跌停、炸板家数与封板率，连板梯队与最高板（含一字核对），昨日涨停今日晋级与涨跌分布，涨停股行业分布，**昨日涨停股今日开盘与尾盘分类（高开/平开/低开 × 尾盘涨停/上涨/平/下跌/跌停，含分行业汇总）与分板块晋级与炸板统计（含板数结构）**，跌停股行业分布）。**另用 `--json` 取 `zt_rows`（当日涨停池全量明细，含首板）**，用于报告中的「涨停全名单」——次日 $limit-judge 的竞价评估直接以它为样本；`yesterday_open_close`（开盘与尾盘分类汇总，含分行业）与 `yesterday_performance.rows`（昨日涨停股逐只明细，含当日开盘分类与尾盘状态）用于「昨日涨停股今日开盘与尾盘分类」一节；`industry_promotion`（分板块晋级率/炸板率与板数结构）用于「分板块晋级与炸板统计」一节；**跌停结构**（`--json` 的 `dt_rows` 全量跌停明细 + `dt_industry_dist` 跌停行业分布）用于阵型的「结构说明」——崩在哪由它给数字。
- 板块行情榜：fetch_sector_boards.py --type industry --sort change --top 10 与 --type concept --sort change --top 10；另拉 --sort gain5 --top 10 复核持续性（近5日）；东财板块接口不可用时该脚本自动切腾讯备用源并在输出里标注数据源与口径（主力净流入＝腾讯 zljlr），板块行的主力净流入按实际数据源标注，跨源数值不可比。
- 只向 $market-data 说明需要以上数据列，具体参数由 $market-data 按其 SKILL 执行；拉取失败明确报错，不脑补。

### 第三步：按六问解读

阈值、判定表与示例见 references/limit-find-cheatsheet.md（解读前读）；用户请求中说明的个人阈值优先并写进报告。六问各给数字 + 判定，不写行情预测：

1. **今日涨停/跌停家数**：今日涨停 X（昨 Y）、跌停 A（昨 B）、炸板 C（昨 D）、封板率 P%（昨 Q%）；按情绪温度区间标偏热/常态/偏冷，涨停减少且封板率下降标“热度回落”。家数比较只用同口径（东财涨停池不含 ST 与科创板）。
2. **连板高度与最高板**：最高 N 板（昨 M 板）+ 名单 + 逐只一字核对（以行情开=高=低=收核对，写“一字：是/否”，无行情标“-”）；高标梯队（≥3 板）按数据报告表头照抄。高度回落 + 晋级率下降 + 炸板率上升三者同时出现 → 标“情绪退潮迹象（数据判定）”。
3. **昨日涨停今日表现与炸板潮**：晋级 X→Y 只与晋级率、上涨/下跌/平均涨幅；按炸板潮口径给“有/无明显炸板潮”。
4. **昨日涨停股今日开盘与尾盘分类**：逐只分高开/平开/低开（今开 vs 昨收）与尾盘状态（涨停/上涨/平/下跌/跌停；尾盘取运行时刻最新价，收盘后即收盘价），给总体分布 + 分行业表，并按口径判板块强弱与板块内分化。只写分布与判定，不给买卖动作。
5. **分板块晋级与炸板统计**：按行业给板数分档（一板/二板/三板/四板及以上）、该行业最高板、板块晋级率与炸板率（分母写清，为 0 记「-」），按活跃度口径标活跃/中性/转弱/样本不足；一板多而无二板以上＝只有扩散没有高度。
6. **当日主线板块**：把涨停股行业分布 Top 10 与板块行情榜合并成“板块行”表（每行同时给涨停集中度 × 板块涨幅 × 资金流入三个口径），按主线确认口径取 ≤3 个；交集不足写“无明确主线”，不硬凑；与昨日报告的主线对照给“延续/退潮候选”。
- 主线确认规则：涨停家数集中的行业/概念（≥3 家或占比前 3）∩ 板块当日与近5日涨幅为正 ∩ 主力净流入为正（或至少不明显流出），取交集按涨停家数排序取 ≤3 个为当日主线；交集不足时只写“板块榜靠前但涨停未集中”，不硬凑主线。
- 与昨日报告的主线对照：昨日主线今日仍在榜单 → 写“延续”；今日跌出榜单或炸板集中 → 写“退潮候选”，依据为当日榜行数据。

### 第四步：阵型汇总（当日 + 之前四次报告，共五次）

单日数字说明不了情绪走到哪一步，把最近五次报告并排看才知道。判定口径见 references/limit-find-cheatsheet.md。

1. 取样本：本次数据日期为第一份，加上 report/涨停板复盘/ 下日期早于本次数据日期的最近四份 `YYYY-MM-DD.md`，共五份；不足四份时按实际份数（含当日）。
2. 逐份取四个数字——最高板数、晋级率、炸板率、跌停家数（来自各报告的「数据概览」「连板高度与最高板」「昨日涨停今日表现」）；旧报告缺项写“未获取”，不脑补。
3. 填五次报告汇总表，末列给每份报告一个单日态标签，便于看走势是连贯还是反复横跳：

   | 数据日期 | 涨停家数 | 跌停家数 | 炸板率 | 最高板 | 晋级率 | 单日态 |

4. 定当日阵型，顺序固定三步：**先看最高板有没有抬升 → 再看晋级率有没有回到 30% 以上 → 最后看炸板率**；第一步没做到，后两步好看也只算轮动期。炸板率 ≥35% 或跌停家数两位数偏“分歧期”；“崩塌·退潮期”要**同时**满足两个条件——跌停家数 ≥ 20 家，**且** 跌停家数 ≥ 涨停家数的三分之一（只有比例达标、跌停家数不到 20 家的日子按“分歧期”走：涨停家数少的时候比例容易被小样本顶上去，6 家跌停撑不起“崩塌”）；最高板天地板或连续跌停同样落“崩塌·退潮期”。
5. 阵型标签后面**必须紧跟一行「结构说明」**，写清崩在哪、抬在哪：
   - 崩在哪：跌停集中在哪些行业/题材（取跌停股行业分布的家数，点出代表性个股）；
   - 抬在哪：今天仍在创新高的方向（高标梯队与最高板所在行业、连板数）；
   - 收一句定型（如“老题材崩塌 + 局部高度抬升”）。

   只写“崩塌·退潮期”会让读的人（包括明天的自己）以为全市场都在崩，而当天可能还有票在创连板新高——两个信息缺一个，判断都会走偏。
6. 结论写进报告的「阵型判定」一节：阵型 + 结构说明 + 三步判断依据（每步跟一个数字；这三步是**定当日标签**用的，确认昨日标签另走第 7 条的检验卡）+ 该阵型已持续几个交易日（按汇总表数连续天数）。
7. **昨日阵型确认**（对上一份报告的标签判分，写进同一节的「昨日阵型确认」子块）：把昨日标签原样抄过来（不许回头改），再**按昨日标签取对应的检验卡**——一套判据不能套所有标签，四张卡与逐档判分见 references/formation-followup-cards.md：
   - 昨日「高度打开」：① 空间板有没有续板（或高开且不破前收）→ ② 晋级率有没有守住 30% → ③ 炸板率与跌停（容错）。空间板崩（跌停 / 跌停附近开盘 / 收阴 ≥5%）或晋级率 <15% 判**失效**；空间板未续但未崩、晋级率 15%–30% 判**切换**。
   - 昨日「轮动期」：① 有没有出现新高的高标（最高板抬升）→ ② 有没有崩塌（跌停 ≥20 家，或跌停 ≥ 涨停家数的三分之一）。两项都没发生 = **延续**（今天仍是轮动期，写「延续 N 天」，**不写「未确认」**）；最高板抬升且晋级率 ≥30%，或跌停回到两位数 = **切换**（写明切到哪一态）。
   - 昨日「分歧期」：① 空间板有没有收复 → ② 炸板率与跌停有没有同时收敛；同时收敛 = 延续（转回轮动），跌停扩大成片 = 失效，其余 = 维持分歧。
   - 昨日「崩塌·退潮期」：① 跌停家数有没有收敛 → ② 空间板有没有止跌；收敛且止跌 = 延续，跌停再创新高 = 失效，其余 = 震荡维持。
   结论只能是**延续 / 切换 / 失效**（旧口径的确认、未确认、证伪已停用；切换要写明切到哪一态）。
8. **记账**：在「昨日阵型确认」子块记一行四格——昨日标签 / 今日标签 / 变化类型（延续・切换・失效）/ 是否计入对错。**只有有方向的标签记对错**：高度打开、崩塌·退潮期的次日仍为同一标签 = 对，换标签 = 错；轮动期与分歧期是中性标签，**不记对错**，只记「延续 N 天 / 今天切换」。统计口径用**强标签延续率**（强标签次日仍同标签次数 ÷ 强标签总次数），不用「对 ÷ 总行数」的阵型确认率；只统计已有次日检验记录的标签，不事后补判；累计 20 个交易日后才看这个比率。
9. 只判定当前位置，不推演下一日阵型；样本不足五份时写明“样本 N 份，不足五次”；跌停明细只返回 Top N 时按接口实际条数写并注明口径。

### 第五步：生成报告并落盘

1. 读 references/report-template.md，按模板骨架逐节填充：节名、表头、列顺序照抄，`{{...}}` 全部替换为真实数字或“未获取”；当天没有内容的行删掉，涨停全名单（含首板）不省略；模板自带的使用说明与填充示例不写进报告。
2. 正文先写入 report/涨停板复盘/YYYY-MM-DD.md（目录不存在则创建；同日再次运行覆盖更新并注明运行时间），再在回复中给摘要与文件位置。

## 报告格式（固定）

以 references/report-template.md 为骨架，节名、表头、列顺序照抄，不新增或调序；模板里的使用说明与填充示例不写进报告。不可省略的要求：

- 落盘 report/涨停板复盘/YYYY-MM-DD.md（文件名日期＝数据日期；同日重跑覆盖更新并注明运行时间），结尾必须带“不构成投资建议”。
- **涨停全名单含首板全量、不省略**（取 --json 的 zt_rows）：它是次日 $limit-judge 的样本与「竞价成交额 ÷ 昨日全天成交额」的分母。
- **阵型判定是最后一节**：五次报告汇总表 + 阵型结论 + 紧邻的结构说明（崩在哪＝跌停集中行业与家数、代表个股；抬在哪＝创新高的方向与最高板）+ 三步判断依据（最高板是否抬升、晋级率是否回到 30%、炸板率；定当日标签用）+ 已持续几个交易日；样本不足五次注明实际份数。
- 同节的「昨日阵型确认」子块不可省：昨日标签照抄（不许回头改）+ 按昨日标签取的检验项（高度打开＝空间板/晋级率/炸板率与跌停，轮动期＝有无新高标/有无崩塌，分歧期＝空间板收复/炸板与跌停收敛，崩塌·退潮期＝跌停收敛/空间板止跌）+ 结论（延续/切换/失效）+ 动作提示 + 每日四格记账行（昨日标签/今日标签/变化类型/是否计入对错）+ 强标签延续率；口径见 references/formation-followup-cards.md。
- 第五节取 --json 的 yesterday_open_close 与 yesterday_performance.rows；第六节取 industry_promotion；标题注明盘中/收盘口径。

各节的内容规格、表头与填写示例见 references/report-template.md（第五步落盘前读）。

## 硬性规则

- 数据必须真实：$market-data 拉不到就明确报错或标“未获取”，不编造涨停/跌停/炸板家数、板数、一字、晋级率或板块数据；数字一律标数据日期。
- 板块资金标源：板块行「主力净流入」必须带数据源标记（东财 / 腾讯备用源）；当日板块资金先按 auto 重试并切源，两源都失败才写「未获取」——这一列是次日 $limit-lifecycle「主线健康度三检查表」第三格的基准日来源，跨源两个日期不能直接算比例。
- 同口径比较：东财涨停池不含 ST 与科创板；家数环比只用同一天同一口径。
- 默认阈值可覆盖：热度区间、炸板潮判定、板块强弱与板块内分化口径、板块活跃度口径、主线确认均为默认经验阈值；本 SKILL 不读取工作区文件，用户请求中说明的个人阈值优先并在报告中注明。
- 分类口径固定：开盘分类用「今开 vs 昨收」（高开/平开/低开），尾盘状态用「当日涨停池 / 当日跌停池 / 涨跌幅正负」（涨停/上涨/平/下跌/跌停）；板块晋级率与炸板率的分母按 references/report-template.md「分板块晋级与炸板统计」节的表头口径写，分母为 0 记“-”，样本不足的板块写明“样本不足”并保留数字，不放大单只个股的结论。
- 只给筛选不给动作：开盘与尾盘分类、板块强弱与分化、板块活跃度都只是数据判定，不写买入/加仓动作、不预测次日；要落到个股买卖走 $stock-analysis → $position-management。
- 只判定不预测：情绪退潮、主线延续等判定只基于当日与昨日的真实数字，不写“明天会涨停/会退潮”式预测。
- 一字判定要核验：不用“9:25 封板”代替行情核对；以开=高=低=收给出“一字：是/否”，无行情时标“-”。
- 主线不硬凑：数据交集不足就写“无明确主线”，不允许为了凑三条而把榜前但涨停不集中的板块写成主线。
- 阵型靠历史报告：阵型四态只能由 report/涨停板复盘/ 下已落盘的报告汇总得出（当日 + 之前四次，共五次）；报告不足五份时按实际份数写并注明样本天数，不用接口数据临时补造历史数字，也不推演下一日的阵型。
- 阵型必带结构说明：阵型标签后面必须跟一行结构说明（崩在哪 + 抬在哪），只给标签不给结构视为不合格；跌停明细只有 Top N 时按接口返回条数写并注明口径。
- 昨日阵型必须确认，且判据跟着昨日标签走：每个交易日对上一份报告的阵型标签判分，**先抄昨日标签，再取该标签对应的检验卡**（高度打开＝空间板 → 晋级率 → 炸板率与跌停；轮动期＝有无新高标 → 有无崩塌；分歧期＝空间板收复 → 炸板与跌停收敛；崩塌·退潮期＝跌停收敛 → 空间板止跌），结论只能是延续/切换/失效；把「高度打开」的三项套到轮动期上、让正确的延续落成「未确认」视为不合格。**昨日标签照抄、不许回头改**——改了等于没有赌注，学不到东西。
- 只有有方向的标签记对错：高度打开、崩塌·退潮期按对错记账（次日仍同标签 = 对，换标签 = 错）；轮动期与分歧期是中性标签，只记「延续 N 天 / 今天切换」，不进对错分母；统计给单列的**强标签延续率**（强标签次日仍同标签次数 ÷ 强标签总次数），不写「阵型确认率」。
- 报告必落盘：先写 report/涨停板复盘/YYYY-MM-DD.md，再回复摘要；回复不替代落盘。
- 格式统一：报告按 references/report-template.md 的固定骨架输出，节名与表头不改写、不调序、不新增小节——次日 $limit-judge 按固定节名取数；模板里的使用说明与填充示例不写进报告。
- 输出可视化：数字一律进表格；趋势与变化用箭头（如「最高板 6→5→4」「晋级率 18%→10%」），状态用固定标记（偏热/常态/偏冷、有/无明显炸板潮、主线候选/仅榜前/退潮候选）；竞价或家数分档可加等宽条（如 ▉▉▉ 3 家）；不写散文式数字段，不用表情符号。
- 免责声明：报告结尾必须带“不构成投资建议”。
